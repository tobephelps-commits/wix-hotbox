# Milestone v1.1: Storefront Polish & Operations Dashboard

**Status:** SHIPPED 2026-02-04
**Phases:** 31-36
**Total Plans:** 12

## Overview

Enhanced customer-facing storefront with stock visibility and variant image switching, plus built operational tooling for easier store management including daemon controls, pipeline wizard, and product migration.

## Phases

### Phase 31: Stock Visibility

**Goal**: Show "Out of Stock" for unavailable color/size combinations instead of hiding them
**Depends on**: v1.0 complete
**Plans**: 3 plans

Plans:
- [x] 31-01: WIX Inventory API service + stock sync refactor
- [x] 31-02: Product creation inventory integration
- [x] 31-03: Verification + documentation

**Details:**
Integrated WIX Inventory V2 API to enable native inventory tracking on products. Out-of-stock variants now display "Out of Stock" message instead of being hidden from customers. Stock sync updated to use inventory quantities instead of variant visibility toggling. Created enable-inventory.ts utility for retroactive fixes to legacy products.

### Phase 32: Variant Image Switching

**Goal**: Display color-specific product images when customer selects a color variant
**Depends on**: Phase 31
**Plans**: 1 plan

Plans:
- [x] 32-01: Verify API linking + WIX Editor configuration guide

**Details:**
Verified that buildMediaPayload() already correctly assigns front/back images to color choices. Created comprehensive documentation for one-time WIX Editor configuration (enable "Link gallery images to product options" in Product Gallery widget). No code changes required - API layer was already correct.

### Phase 33: Side-View Image Investigation & Fix

**Goal**: Debug root cause of incorrect side angle images from vendor API, fix for sleeve logo placement
**Depends on**: Phase 32
**Plans**: 1 plan

Plans:
- [x] 33-01: Fix incorrect sideImage assignment in mapper.ts

**Details:**
Research revealed SanMar CLASS_TYPE_HIGH (2001) images are high-resolution front/lifestyle shots, not true side-view images. Fixed mapper.ts to explicitly set sideImage to null for SanMar products, preventing incorrect logo placements on sleeve areas. Removed side image choice assignment from buildMediaPayload() to prevent duplicate front-looking images in variant switching.

### Phase 34: Operations Dashboard Foundation

**Goal**: Build daemon control panel and store health overview dashboard
**Depends on**: Phase 33
**Plans**: 2 plans

Plans:
- [x] 34-01: Daemon lifecycle control API + operations health endpoint
- [x] 34-02: Operations Dashboard UI

**Details:**
Added programmatic daemon control via AbortSignal for graceful shutdown. Created /api/daemon/start, /api/daemon/stop, and /api/operations/health endpoints. Built dark-themed Operations Dashboard section with daemon Start/Stop buttons, status indicator, and four health metric cards (Orders, Inventory, Sync Daemon, Errors) with auto-refresh.

### Phase 35: Product Pipeline Wizard

**Goal**: Step-by-step guided product creation with previews at each stage
**Depends on**: Phase 34
**Plans**: 3 plans

Plans:
- [x] 35-01: Wizard foundation with step navigation UI and state management
- [x] 35-02: Step content panels (product, variants, pricing, logo, review)
- [x] 35-03: API integration and verification

**Details:**
Created 5-step wizard flow: (1) Product search/fetch, (2) Color/size variant selection with visual swatches, (3) Pricing configuration with live margin preview, (4) Optional logo overlay, (5) Review and create. Wizard validates each step before advancing, integrates with existing /api/create endpoint, and displays success screen with WIX product link.

### Phase 36: Product Migration Tooling

**Goal**: Browse existing WIX products and migrate untracked ones through the Pipeline Wizard
**Depends on**: Phase 35
**Plans**: 2 plans

Plans:
- [x] 36-01: WIX products API endpoint with tracking status
- [x] 36-02: Migration UI section with product browser and wizard integration

**Details:**
Added GET /api/wix/products endpoint that returns all WIX products with tracking status (tracked/untracked/unknown vendor). Built Migration section in preview dashboard with product grid, filter dropdown (All/Untracked/Tracked), search by style or name, and Migrate button that opens wizard pre-filled with detected vendor and style number.

## Milestone Summary

**Key Decisions:**

| Phase | Decision | Rationale |
|-------|----------|-----------|
| 31 | Use WIX Inventory V2 API for stock visibility | Native inventory tracking shows "Out of Stock" instead of hiding variants |
| 31 | Keep all variants visible (visible: true) | Customers can see all color/size options, improving UX |
| 32 | Verification-only for API layer (no code changes) | buildMediaPayload() already correctly assigns images to color choices |
| 33 | Set sideImage to null explicitly for SanMar | CLASS_TYPE_HIGH (2001) is a high-res front/lifestyle shot, not a side view |
| 34 | AbortSignal for daemon control (not process.exit) | Graceful shutdown allows current tick to complete before exiting |
| 35 | Steps 3-4 default valid (pricing/logo optional) | User can proceed with defaults; reduces friction |
| 36 | Vendor detection via text + SKU heuristics | Standard naming conventions allow reliable vendor identification |

**Issues Resolved:**

- Incorrect side-view images causing wrong sleeve logo placement (fixed by setting sideImage to null for SanMar)
- Legacy products missing inventory tracking (created enable-inventory.ts utility)
- No way to browse existing WIX products (added migration browser)

**Issues Deferred:**

- 30 WIX Editor manual fixes still pending for store owner
- Variant image switching requires one-time WIX Editor configuration

**Technical Debt Incurred:**

- preview.html continues to grow (~5000+ lines) - may need splitting in future milestone
