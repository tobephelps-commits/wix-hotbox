3. If match found, call `linkToCustomer(db, wixContactId, customer.id)`
4. Return count of newly linked contacts
5. Log: `[WixContacts] Auto-linked {n} contacts to existing customers`

This auto-link runs after each sync to opportunistically connect WIX contacts to B2B customer accounts.

  <action>
Create `src/wix-contacts/daemon.ts` — polling daemon mirroring `src/sync/sync-poller.ts` exactly.

Module-level state:
- `_syncHealth: CustomerSyncHealth | null`
- `_abortController: AbortController | null`
- `_running: boolean`

Constants:
- `TICK_INTERVAL_MS = 5 * 60 * 1000` (5 minutes — contacts change less frequently than inventory)
- `ERROR_ESCALATION_THRESHOLD = 5`

Public API (mirror sync-poller.ts):
1. `isDaemonRunning()` — returns _running
2. `getSyncHealth()` — returns copy of _syncHealth or null
3. `syncOnce(db, wixConfig)` — single sync cycle: call syncContacts(), then autoLinkContacts(). Returns CustomerSyncResult.
4. `startDaemon(db, wixConfig)` — start polling loop. Returns true if started, false if already running. Initialize CustomerSyncHealth. Run first tick immediately, then setInterval(TICK_INTERVAL_MS). Handle AbortSignal for graceful shutdown.
5. `stopDaemon()` — abort controller signal. Returns true if stopped, false if not running.

Internal `executeTick(db, wixConfig)`:
- Increment totalCycles, set lastTickAt
- Try: syncContacts() + autoLinkContacts(), update contactsSynced, set lastSuccessAt, reset consecutiveErrors
- Catch: increment consecutiveErrors and totalErrors, log warning/error based on escalation threshold
- Finally: update tick duration metrics (lastTickDurationMs, avgTickDurationMs, maxTickDurationMs) using cumulative moving average — same math as sync-poller.ts

`cleanupOnShutdown()`:
- Log session summary (totalCycles, contactsSynced, totalErrors, uptime)
- Reset all module state to null/false

Update `src/wix-contacts/index.ts` to also export from sync-engine.ts and daemon.ts.
  </action>

<task type="auto">
  <name>Task 3: Create routes and register in app</name>
  <files>src/routes/wix-contacts.ts, src/routes/index.ts</files>
  <action>
Create `src/routes/wix-contacts.ts` — Fastify plugin with REST endpoints for WIX contact sync management. Follow pattern from `src/routes/sync.ts`.

Endpoints:

1. `GET /` — List synced WIX contacts. Query params: `search` (string), `linked` ('true'|'false'). Calls listWixContacts(db, options). Returns `{ contacts: WixContact[], total: number }`.

2. `GET /stats` — Contact sync statistics. Calls getWixContactStats(db). Returns stats object.

3. `GET /:wixContactId` — Get single WIX contact by ID. Returns contact or 404.

4. `POST /sync/once` — Trigger one-shot sync. Validates wixApiKey and wixSiteId are configured (return 400 if not). Calls syncOnce(db, wixConfig). Returns CustomerSyncResult.

5. `POST /sync/start` — Start daemon. Validates WIX credentials configured. Calls startDaemon(db, wixConfig). Returns `{ started: true }` or `{ started: false, reason: 'already running' }`.

6. `POST /sync/stop` — Stop daemon. Calls stopDaemon(). Returns `{ stopped: true }` or `{ stopped: false, reason: 'not running' }`.

7. `GET /sync/health` — Daemon health. Calls getSyncHealth(). Returns health object or `{ running: false }`.

8. `POST /:wixContactId/link` — Link WIX contact to B2B customer. Body: `{ customerId: string }`. Validates customer exists. Calls linkToCustomer(). Returns updated contact or 404.

9. `DELETE /:wixContactId/link` — Unlink WIX contact from customer. Calls unlinkFromCustomer(). Returns updated contact or 404.

Build wixConfig from fastify.config: `{ apiKey: fastify.config.wixApiKey!, siteId: fastify.config.wixSiteId! }`.

Register in `src/routes/index.ts`:
- Import wixContactRoutes from './wix-contacts.js'
- Add: `await fastify.register(wixContactRoutes, { prefix: '/wix-contacts' });`
- Place after the existing customer routes registration
