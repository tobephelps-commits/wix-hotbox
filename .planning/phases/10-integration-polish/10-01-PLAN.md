<task type="auto">
  <name>Task 1: Add graceful degradation to fetchProductData and harden mapper</name>
  <files>scripts/pipeline/fetch-product.ts, scripts/pipeline/mapper.ts</files>
  <action>
**fetchProductData (fetch-product.ts):**
The current `Promise.all` fails fast -- if any of the 4 SanMar API calls fails, the entire fetch fails. This is too aggressive for production use. Refactor to use `Promise.allSettled` so that:

1. Product info is REQUIRED -- if this fails, throw with clear error (style doesn't exist or creds are bad)
2. Pricing, inventory, and media are OPTIONAL -- if any fail, log a warning and continue with sensible defaults:
   - Pricing failure: use `null` for pricing, mapper builds preview with "pricing unavailable" indicator
   - Inventory failure: use empty array `[]`, all variants treated as "unknown stock" (visible by default)
   - Media failure: use empty array `[]`, product created with no images (can be added later)
3. After allSettled, check each result. For rejected promises, classify using SanMarError. If retryable error, log warning with suggestion. If user error, throw immediately.
4. Update the ProductData interface to make pricing optional: `pricing: PricingInfo | null`

**buildProductPreview (mapper.ts):**
Handle null pricing gracefully:
- If pricing is null, set wholesalePrice to 0, suggestedRetail to 0, saleActive to false
- Log a warning: "Pricing data unavailable for {style} -- wholesale cost will need manual entry"

Handle empty images array (already works since it returns empty arrays from find operations).

Handle empty inventory array -- all colors show as "Stock Unknown" instead of "Out of Stock". Change the `inStock` field logic: if inventory array is empty, set a new `stockUnknown: true` field on ColorPreview. If inventory exists but qty is 0, keep `inStock: false`. This distinction matters for curation UI.

**Add stockUnknown to ColorPreview type (types.ts):**
Add `stockUnknown?: boolean` to the ColorPreview interface.

Do NOT change the existing happy-path behavior. All changes are additive defensive handling.
  </action>
  <verify>
Run `npx tsc --noEmit` to verify no type errors. Manually review that the happy path (all 4 APIs succeed) still works identically.
  </verify>
  <done>
fetchProductData handles partial API failures gracefully. Product info failure = hard error. Pricing/inventory/media failures = warnings with safe defaults. buildProductPreview handles null pricing and empty inventory without crashing.
  </done>

<task type="auto">
  <name>Task 2: Add partial failure recovery to createWixProduct and harden sync</name>
  <files>scripts/pipeline/create-product.ts, scripts/sync/stock-sync.ts, scripts/sync/sync-poller.ts, scripts/monitor/poller.ts</files>
  <action>
**createWixProduct (create-product.ts):**
The current flow is: create product -> add media -> update variants -> verify. If step 2 (media) fails, the product exists but has no images and no variant pricing. This is a partially-created product with no recovery path. Fix:

1. Wrap each step (media, variants, verify) in try/catch AFTER the initial product creation
2. If media upload fails: log warning "Media upload failed for {productId}: {error}. Product created but images need manual upload." Continue to variant updates.
3. If variant update fails: log error "Variant update failed for {productId}: {error}. Product exists as draft but variants need manual configuration." Return a partial CreationResult with a new `warnings: string[]` field.
4. If verify fails: log warning but return the result (product was created, we just couldn't confirm)
5. Add `warnings: string[]` to CreationResult interface. Empty array on full success, populated on partial failures.
6. CLI runner: after createWixProduct, if result.warnings.length > 0, print all warnings at the end

**syncProductStock (stock-sync.ts):**
Current error handling is solid (per-product try/catch with errors array). Add one improvement:
- When WIX API returns a 404 for a mapped product (product was deleted from WIX), add a specific error message: "WIX product {id} not found -- it may have been deleted. Run `npm run sync:scan` to refresh mappings."
- Detect 404 by checking if error message contains "not found" or "404" (WIX V1 error format)

**syncOnce (sync-poller.ts):**
Add a pre-flight check at the start of syncOnce:
- Check that WIX_API_KEY env var exists. If missing, throw with message: "WIX_API_KEY not set. Add it to .env file. Get your API key from WIX Dashboard > Developer Tools > API Keys."
- Check that SANMAR_CUSTOMER_NUMBER env var exists. If missing, throw with message: "SanMar credentials not configured. Set SANMAR_CUSTOMER_NUMBER, SANMAR_USERNAME, SANMAR_PASSWORD in .env file."
- These checks prevent cryptic auth errors deep in the SOAP/REST call chains

**pollOnce (monitor/poller.ts):**
Add the same SanMar credentials pre-flight check before the polling loop starts. Only check once on first call (use a module-level boolean flag).

Do NOT add pre-flight checks to the library functions themselves (fetchProductData, createProduct, etc.) -- those should remain reusable. Only add checks to the CLI-facing entry points and poller loops.
  </action>

Run `npx tsc --noEmit` to verify no type errors. Review that sync and monitor CLIs give clear messages when env vars are missing.
  </verify>
  <done>
createWixProduct recovers from partial failures (media/variant steps) and reports warnings. syncProductStock detects deleted WIX products. syncOnce and pollOnce validate environment before running. No cryptic errors from missing credentials.
  </done>
