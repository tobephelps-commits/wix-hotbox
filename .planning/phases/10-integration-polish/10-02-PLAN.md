  <files>scripts/pipeline/validate-pipeline.ts, package.json</files>
  <action>
Create `scripts/pipeline/validate-pipeline.ts` -- a read-only validation tool that tests the entire pipeline without modifying any WIX data. The script accepts an optional style number argument for SanMar data validation.

**Structure the script as a series of checks, each printing PASS/FAIL/SKIP:**

```
Pipeline Validation Report
==========================

1. Environment
   [PASS] SanMar credentials configured (SANMAR_CUSTOMER_NUMBER, SANMAR_USERNAME, SANMAR_PASSWORD)
   [PASS] WIX API key configured (WIX_API_KEY)
   [PASS] SMTP notifications configured (SMTP_HOST, NOTIFY_TO)
   -- OR --
   [SKIP] SMTP not configured (optional -- set NOTIFY_ENABLED=true to enable)

2. SanMar API Connectivity
   [PASS] Product info endpoint reachable
   [PASS] Pricing endpoint reachable
   [PASS] Inventory endpoint reachable
   [PASS] Media endpoint reachable
   -- OR --
   [FAIL] Product info endpoint: Connection refused (port 8080 blocked?)

3. SanMar Data Fetch (style: PC61)
   [PASS] Product data: 60 variants, 30 colors, 8 sizes
   [PASS] Pricing data: wholesale $3.66, retail $8.98
   [PASS] Inventory data: 1,847 SKUs with stock
   [PASS] Media data: 45 images across 30 colors
   -- OR --
   [SKIP] No style number provided (pass a style as argument to test)

4. WIX API Connectivity
   [PASS] WIX product query works (found 105 products)
   -- OR --
   [FAIL] WIX API: 401 Unauthorized (check WIX_API_KEY)

5. Monitor State
   [PASS] 3 products tracked
   [PASS] Last poll: 2026-01-31 14:30:00 (2 hours ago)
   [PASS] Alert log: 12 entries
   -- OR --
   [SKIP] No products tracked (run `npm run monitor:add <STYLE>` to start)

6. Sync State
   [PASS] 3 product mappings configured
   [PASS] All mapped WIX products exist and are accessible
   -- OR --
   [WARN] Product mapping PC61 -> wxp-abc123: WIX product not found (may have been deleted)
   -- OR --
   [SKIP] No product mappings (run `npm run sync:scan` to auto-discover)

Summary: 14 passed, 0 failed, 2 skipped
```

**Implementation details:**

1. **Environment checks:** Check each env var exists (don't print values -- they're secrets). SMTP is SKIP not FAIL if unconfigured (it's optional).

2. **SanMar API connectivity:** Call `validateCredentials()` from sanmar module to test auth. If that passes, the endpoints are reachable. If it fails, classify the error using SanMarError and report the specific issue.

3. **SanMar data fetch (optional):** If a style number is provided as CLI argument, run `fetchProductData(style)` and report what was returned. Validate the data makes sense: >0 products, >0 sizes, pricing > $0, etc. If any of the 4 API responses had issues, report which ones. This exercises the real data path without creating anything in WIX.

4. **WIX API connectivity:** Call `listAllProducts()` and report count. This is read-only. If it fails, report the specific error (usually auth issue).

5. **Monitor state:** Load monitor config and tracked products. Report count, last poll time (from latest snapshot file timestamp), alert log stats. SKIP if no products tracked.

6. **Sync state:** Load product mappings. For each mapping, verify the WIX product still exists by calling `getProduct(id)`. Report any orphaned mappings (WIX product deleted but mapping still exists). SKIP if no mappings.

**CLI interface:**
```
Usage: npx tsx scripts/pipeline/validate-pipeline.ts [STYLE]
       npm run validate [-- STYLE]

Options:
  STYLE   Optional SanMar style number to test data fetch (e.g., PC61)

Examples:
  npm run validate              # Check environment and connectivity only
  npm run validate -- PC61      # Also test SanMar data fetch for PC61
```

**Add npm script to package.json:**
```json
"validate": "npx tsx scripts/pipeline/validate-pipeline.ts"
```

Use `import 'dotenv/config'` at the top to load .env. Use try/catch around every check so one failure doesn't prevent the rest from running. Track pass/fail/skip/warn counts and print summary at the end.

Exit code: 0 if all checks pass or skip, 1 if any check fails.

<task type="auto">

  <action>
Extend the SanMar data fetch section (step 3) with data quality checks that surface real-world edge cases:

1. **Missing front images:** Count colors that have no front image (classTypeId 1007). Warn if >20% of colors have no front image: "WARN: {N}/{total} colors have no front image -- these will appear without product photos in WIX"

2. **Zero inventory colors:** Count colors where ALL sizes have zero stock. Report: "INFO: {N} colors are completely out of stock: {list}"

3. **Weight missing:** Check if any product variants have pieceWeight of 0 or undefined. Warn: "WARN: {N} variants have no weight data -- shipping calculations may be affected"

4. **Price sanity check:** If wholesale price is $0 or negative, flag: "WARN: Wholesale price is $0 -- pricing calculations will produce $0 retail"
If wholesale > $100, flag: "WARN: Wholesale price is ${X} -- verify this is correct (unusually high for SanMar blanks)"

5. **Description check:** If product description is empty or very short (<20 chars), flag: "WARN: Product description is very short ({N} chars) -- consider adding a description in WIX after creation"

6. **Size gaps:** Check if standard sizes are present (S, M, L, XL). If common sizes are missing, warn: "WARN: Missing common sizes: {list} -- this style may only come in limited sizes"

These are all WARN/INFO level -- they don't cause FAIL status. They help the operator spot potential issues before creating WIX products.

Print these after the basic data fetch results in step 3.
