  <files>scripts/pipeline/preview.html</files>
  <action>
  Add a status overview section at the top of the orders section (above the existing filter pills and order table). This provides at-a-glance confidence.

  **Status Summary Cards:**
  - Fetch `GET /api/orders/summary` on orders section load and on each refresh
  - Display a row of compact status cards, one per active status: New, On Hold, Ordered, Received, In Production, Packed, Shipped, Delivered
  - Each card shows: status name + count number (e.g., "New: 5")
  - Cards with count 0 should be dimmed/muted (gray text, no background)
  - Cards with count > 0 should have a subtle colored left border:
    - New: blue (#4a90d9)
    - On Hold: amber (#f5a623)
    - Ordered/Received/In Production: purple (#6c63ff)
    - Packed/Shipped: green (#2ecc71)
    - Delivered: gray (#999)
  - If `errorCount > 0` from the summary, show an additional red card: "⚠ Errors: N" with red left border (#e74c3c). Clicking this card should filter to show only errored orders.
  - Clicking any status card filters the order list to that status (reuse existing filter pill logic by programmatically activating the corresponding filter)
  - Add "on-hold" to the existing status filter pills

  **CSS for status cards:**
  - `.order-summary-row` — flex container, gap: 8px, flex-wrap: wrap, margin-bottom: 12px
  - `.order-summary-card` — padding: 8px 14px, border-radius: 6px, background: #f9f9f9, border-left: 3px solid [color], cursor: pointer, font-size: 13px, min-width: 80px, transition: background 0.15s
  - `.order-summary-card:hover` — background: #f0f0ff
  - `.order-summary-card.dimmed` — opacity: 0.4, border-left-color: #ddd
  - `.order-summary-card .card-count` — font-size: 18px, font-weight: 700, display: block
  - `.order-summary-card .card-label` — font-size: 11px, text-transform: uppercase, color: #888, letter-spacing: 0.3px

  **Sync Health Indicator:**
  - Below the status summary cards, show a small sync health line:
    - "Last synced: [relative time] ago" (e.g., "5 minutes ago", "2 hours ago", "Never")
    - If `lastSync` is empty or missing: show "Never synced" in amber
    - If `lastSync` is older than 1 hour: show in amber with "(stale)" suffix
    - If `lastSync` is within 1 hour: show in green
  - Use the `lastSync` value from the `/api/orders/summary` response
  - Style: `.sync-health` — font-size: 12px, color: #999, margin-bottom: 8px, display: flex, align-items: center, gap: 6px
  - Add a small colored dot (6px circle) before the text: green for fresh, amber for stale, gray for never

  **Implementation approach:**
  - Create a `loadOrderSummary()` async function that fetches the summary endpoint
  - Call it when the orders section is activated and after every sync/refresh
  - Update the DOM by building the card row from the response data
  - Store the summary data so the error card click can trigger the error filter
  </action>

<task type="auto">
  <name>Task 2: Error alert banner, resolve controls, and enhanced status timeline</name>
  <files>scripts/pipeline/preview.html</files>
  <action>
  **Error Alert Banner:**
  - When `errorCount > 0` from the summary, show a dismissible alert banner below the sync health indicator:
    - Yellow/amber background (#fff3cd), border: 1px solid #ffc107, border-radius: 6px, padding: 10px 14px
    - Text: "N order(s) have unresolved errors" with a "View errors" link
    - Clicking "View errors" fetches `GET /api/orders/errors` and shows only those orders in the list
    - Add a small "×" dismiss button (hides the banner for this session only, does NOT resolve the errors)
  - CSS: `.error-alert-banner` — standard alert styling with flex layout for text + dismiss button

  **Error Display in Order Detail:**
  - In the order detail view, if the order has unresolved errors in its `errors` array:
    - Show an error section below the status section with red left border
    - Each error shows: operation type (as a badge), message, timestamp (relative), retry count
    - Add a "Mark Resolved" button next to each error that calls `POST /api/orders/:id/resolve-error` with the operation type
    - On success, remove the error from the display and show a toast "Error resolved"
    - If all errors resolved, hide the error section
  - CSS: `.order-errors-section` — padding: 12px, background: #fff5f5, border-left: 3px solid #e74c3c, border-radius: 4px, margin-bottom: 12px
  - CSS: `.error-entry` — flex row with badge, message, time, and resolve button
  - CSS: `.error-badge` — small colored pill showing operation type (sync=blue, print=orange, cart-fill=purple)

  **Enhanced Status Timeline:**
  - The existing `.order-status-timeline` already shows status history entries with a vertical timeline. Enhance it:
    - Add relative timestamps next to absolute timestamps (e.g., "Jan 15, 2:30 PM (3 days ago)")
    - Color-code the timeline dots by status category:
      - New/On Hold: blue
      - Ordered/Received/In Production: purple (#6c63ff)
      - Packed/Shipped: green (#2ecc71)
      - Delivered: dark green (#27ae60)
      - Cancelled: red (#e74c3c)
    - Show the duration between each status transition (e.g., "→ 2h 15m" between entries). Calculate from timestamp difference between consecutive entries.
    - For the current (most recent) status entry, use a slightly larger dot (12px instead of 10px) and add a subtle pulse animation to indicate it's the current state

  **Implementation:**
  - Modify the existing `renderOrderDetail()` / order detail rendering function to:
    1. Check `order.errors` array and render error section if unresolved errors exist
    2. Enhance the timeline rendering with colored dots, relative times, and duration between steps
  - Add `formatRelativeTime(isoString)` helper if not already present (reuse pattern from sync health)
  - Add `formatDuration(ms)` helper for time between transitions (show as "Xh Ym" or "Xm" or "< 1m")
  - The "Mark Resolved" button handler: POST to resolve-error endpoint, on success refresh the order detail
  </action>

Timeline shows colored dots, relative times, and durations between transitions. Error alert banner appears at top of orders section when errors exist.</verify>
