<task type="auto">
  <name>Task 2: Implement touch interaction CSS patterns and responsive behavior</name>
  <files>ui/src/index.css, ui/src/components/Sidebar.css, ui/src/App.css</files>
  <action>
  1. Update `ui/src/index.css` with touch interaction foundation:
     - All interactive elements: minimum 44px touch target (CSS rule for button, a, [role="button"], .touchable)
     - `-webkit-tap-highlight-color: transparent` on all elements (remove blue flash on tap)
     - `touch-action: manipulation` already on body (Plan 01) — verify present
     - Add `.touch-scroll` utility class: overflow-y auto, -webkit-overflow-scrolling touch, overscroll-behavior-y contain (prevents pull-to-refresh)
     - Add `.no-select` utility class: user-select none, -webkit-user-select none
     - Add active state feedback: `.touchable:active { opacity: 0.7; transition: opacity 50ms; }` — instant visual feedback on tap

  2. Update `ui/src/components/Sidebar.css` with touch-specific styles:
     - Tab items: apply touch target minimum (already 56px from Task 1, but ensure)
     - Add active pseudo-class: background darkens slightly on press (immediate tactile feedback)
     - Prevent text selection on all tab elements
     - Add `will-change: background-color` for smooth transitions on Pi hardware
     - Ensure no hover-dependent styles that would fail on touch (hover should enhance, not be required)

  3. Add responsive sidebar behavior for smaller screens (LAN access from phones — Phase 55 prep):
     - Below 768px: sidebar collapses to icon-only (48px wide), labels hidden
     - Below 480px: sidebar becomes bottom navigation bar (fixed bottom, horizontal, icons only)
     - Use CSS media queries only (no JS) — this is a CSS-first responsive approach
     - Content area adjusts grid accordingly

  4. Add smooth content area scrolling in `ui/src/App.css`:
     - Content area: apply .touch-scroll class behavior
     - Scroll behavior: smooth for programmatic scrolls
     - Overscroll containment: prevent rubber-banding on content boundaries

  IMPORTANT: Touch patterns must work on Chromium kiosk (15.6" touch display) — this is the primary target.
  IMPORTANT: Responsive breakpoints are for LAN access (Phase 55) — the kiosk display is always 1920x1080 or similar, so full sidebar always shows on the kiosk.
  IMPORTANT: Do NOT install any touch/gesture library — CSS touch-action and native events are sufficient for sidebar navigation. Gesture libraries are for later phases if needed.
  </action>
