Create `scripts/ss-activewear/adapter.ts` implementing VendorAdapter.

**Key difference from SanMar adapter:** S&S `/v2/products/?style=X` returns FLAT objects where each SSProduct contains product info, pricing, images, AND inventory inline. The adapter must decompose one API response into four unified type arrays.

**Mapping functions (private):**

1. `mapSSProduct(ss: SSProduct): UnifiedProduct`:
   - vendor: 'ss'
   - brandName: ss.brandName
   - style: ss.styleName (this is the S&S part number / style identifier)
   - productTitle: `${ss.brandName} ${ss.styleName}` (S&S doesn't have a separate title on the products endpoint; enrich from styles endpoint if available)
   - description: '' (products endpoint doesn't include description; fetched separately from styles if needed)
   - color: ss.colorName
   - colorCode: ss.colorCode
   - size: ss.sizeName
   - sizeOrder: ss.sizeOrder
   - category: '' (enriched from styles endpoint if needed)
   - pieceWeight: ss.unitWeight
   - status: 'Active' (S&S doesn't have explicit status on products; items returned by API are available)
   - caseQty: ss.caseQty

2. `mapSSPricing(ss: SSProduct): UnifiedPricing`:
   - vendor: 'ss'
   - piecePrice: ss.piecePrice
   - casePrice: ss.casePrice
   - salePrice: ss.salePrice > 0 ? ss.salePrice : null
   - saleExpiration: convert ss.saleExpiration from MM/DD/YYYY to ISO format (YYYY-MM-DD). Return null if empty/falsy.
   - customerPrice: ss.customerPrice (pass through — may be negotiated rate)
   - mapPrice: ss.mapPrice

3. `mapSSInventory(ss: SSProduct): UnifiedInventory`:
   - vendor: 'ss'
   - style: ss.styleName
   - color: ss.colorName
   - size: ss.sizeName
   - totalQty: ss.qty (already aggregated by API)
   - warehouses: ss.warehouses.map(w => ({
       id: w.warehouseAbbr,
       name: SS_WAREHOUSES[w.warehouseAbbr]?.name ?? w.warehouseAbbr,
       qty: w.qty
     }))

4. `mapSSMedia(ss: SSProduct): UnifiedMedia`:
   - vendor: 'ss'
   - color: ss.colorName
   - frontImage: resolveSSImageUrl(ss.colorFrontImage)
   - backImage: resolveSSImageUrl(ss.colorBackImage)
   - sideImage: resolveSSImageUrl(ss.colorSideImage)
   - swatchImage: resolveSSImageUrl(ss.colorSwatchImage, 'fm') (swatches use medium)
   - onModelFront: resolveSSImageUrl(ss.colorOnModelFrontImage)
   - onModelBack: resolveSSImageUrl(ss.colorOnModelBackImage)
   - onModelSide: resolveSSImageUrl(ss.colorOnModelSideImage)

5. `deduplicateMediaByColor(media: UnifiedMedia[]): UnifiedMedia[]` — S&S returns one SSProduct per SKU (color+size), so the same color images repeat for each size. Deduplicate to one UnifiedMedia per unique color.

**SSAdapter class implementing VendorAdapter:**

- `vendorId: 'ss'`
- `vendorName: 'S&S Activewear'`

- `getProductsByStyle(style)`:
  1. Call getSSProductsByStyle(style) → SSProduct[]
  2. Map each to UnifiedProduct
  3. Return array

- `getStylePricing(style)`:
  1. Call getSSProductsByStyle(style) → SSProduct[]
  2. Map each to UnifiedPricing
  3. Deduplicate by color+size (in case of duplicates)
  4. Return array

- `getStyleInventory(style)`:
  1. Call getSSStyleInventory(style) → SSInventoryItem[] (lighter endpoint)
  2. Map to UnifiedInventory (note: SSInventoryItem doesn't have color/size names — only sku/gtin. Need to either:
     a. Use the full products endpoint to get color/size names, OR
     b. Parse from sku if possible)
  3. **Decision:** For inventory monitoring, use the full products endpoint with `?fields=sku,styleName,colorName,sizeName,qty,warehouses` to get color/size with inventory while minimizing payload. If the fields parameter works, this is one call for all data.
  4. Return array

- `getProductImages(style)`:
  1. Call getSSProductsByStyle(style) → SSProduct[]
  2. Map each to UnifiedMedia
  3. Deduplicate by color (one entry per color)
  4. Return array

- `fetchAllProductData(style)`:
  1. S&S is fundamentally different from SanMar: ONE call gets everything
  2. Call getSSProductsByStyle(style) → SSProduct[]
  3. Optionally call getSSStyleInfo(style) to get title and description
  4. Decompose flat data into products, pricing, inventory, media arrays
  5. Return UnifiedProductData
  6. This is MORE efficient than SanMar (1-2 API calls vs 4)

- `validateCredentials()` — calls validateSSCredentials()
