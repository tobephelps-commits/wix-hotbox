<task type="auto">
  <name>Task 1: Create unified vendor types</name>
  <files>scripts/vendor/types.ts</files>
  <action>
Create `scripts/vendor/types.ts` with vendor-agnostic types that abstract over SanMar and S&S differences.

Define:

1. `VendorId` — literal union type `'sanmar' | 'ss'`

2. `UnifiedProduct` — normalized product data:
   - `vendor: VendorId`
   - `brandName: string`
   - `style: string` (vendor-scoped: SanMar style number OR S&S styleName/partNumber)
   - `productTitle: string`
   - `description: string`
   - `color: string` (display color name)
   - `colorCode: string` (vendor-internal color code: SanMar catalogColor or S&S colorCode)
   - `size: string`
   - `sizeOrder: string` (for sorting: SanMar sizeIndex or S&S sizeOrder)
   - `category: string`
   - `pieceWeight: number`
   - `status: string`
   - `caseQty?: number`

3. `UnifiedPricing` — normalized pricing:
   - `vendor: VendorId`
   - `piecePrice: number` (wholesale cost)
   - `casePrice: number`
   - `salePrice: number | null`
   - `saleExpiration: string | null` (ISO format — S&S adapter must convert MM/DD/YYYY)
   - `priceCode?: string` (SanMar-specific)
   - `customerPrice?: number` (S&S-specific negotiated price)
   - `mapPrice?: number` (S&S MAP price)

4. `UnifiedWarehouse` — normalized warehouse:
   - `id: string` (string to accommodate both SanMar numeric IDs and S&S state abbreviations)
   - `name: string` (display name)
   - `qty: number`

5. `UnifiedInventory` — normalized per-SKU inventory:
   - `vendor: VendorId`
   - `style: string`
   - `color: string`
   - `size: string`
   - `totalQty: number`
   - `warehouses: UnifiedWarehouse[]`

6. `UnifiedMedia` — normalized image URLs (always absolute, full-size):
   - `vendor: VendorId`
   - `color: string`
   - `frontImage: string | null`
   - `backImage: string | null`
   - `sideImage: string | null`
   - `swatchImage: string | null`
   - `onModelFront: string | null`
   - `onModelBack: string | null`
   - `onModelSide: string | null`

7. `UnifiedProductData` — aggregated data from a vendor for a single style (mirrors existing ProductData):
   - `vendor: VendorId`
   - `style: string`
   - `products: UnifiedProduct[]`
   - `pricing: UnifiedPricing[]`
   - `inventory: UnifiedInventory[]`
   - `media: UnifiedMedia[]`

All types must be exported. Use JSDoc comments explaining the field semantics and vendor-specific notes (e.g., "S&S saleExpiration is converted from MM/DD/YYYY to ISO by adapter").

Do NOT import from `scripts/sanmar/` — these types are vendor-agnostic.
  </action>
  <verify>npx tsc --noEmit scripts/vendor/types.ts</verify>
  <done>All unified types exported, no TypeScript errors, no imports from vendor-specific modules</done>
</task>

<task type="auto">
  <name>Task 2: Create VendorAdapter interface and vendor registry</name>
  <files>scripts/vendor/registry.ts, scripts/vendor/index.ts</files>
  <action>
Create `scripts/vendor/registry.ts`:

1. `VendorAdapter` interface with async methods:
   - `readonly vendorId: VendorId`
   - `readonly vendorName: string` (display name: "SanMar", "S&S Activewear")
   - `getProductsByStyle(style: string): Promise<UnifiedProduct[]>`
   - `getStylePricing(style: string): Promise<UnifiedPricing[]>`
   - `getStyleInventory(style: string): Promise<UnifiedInventory[]>`
   - `getProductImages(style: string): Promise<UnifiedMedia[]>`
   - `fetchAllProductData(style: string): Promise<UnifiedProductData>` (convenience: fetches all 4 in parallel, mirrors existing fetchProductData pattern)
   - `validateCredentials(): Promise<boolean>`

2. Vendor registry (module-level Map):
   - `registerVendor(adapter: VendorAdapter): void` — registers by vendorId
   - `getVendor(id: VendorId): VendorAdapter` — throws if unknown
   - `getDefaultVendor(): VendorAdapter` — returns 'sanmar' (backward compatibility)
   - `listVendors(): VendorId[]` — returns all registered vendor IDs
   - `isVendorRegistered(id: VendorId): boolean` — check without throwing
   - `parseVendorFlag(flag: string | undefined): VendorId` — parses CLI --vendor flag value, defaults to 'sanmar'. Accepts: 'sanmar', 'ss', 'ss-activewear', 's&s'. Throws on unrecognized values.

Export VendorAdapter interface and all registry functions.

Create `scripts/vendor/index.ts` barrel export:
- Re-export everything from `./types.js`
- Re-export everything from `./registry.js`
  </action>
  <verify>npx tsc --noEmit scripts/vendor/index.ts</verify>
  <done>VendorAdapter interface exported, registry functions work, barrel export compiles cleanly</done>
</task>
