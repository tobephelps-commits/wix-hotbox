  <name>Task 1: Add vendor field to pipeline types and refactor fetchProductData</name>
  <files>scripts/pipeline/fetch-product.ts, scripts/pipeline/types.ts</files>
  <action>
**scripts/pipeline/types.ts** — Add vendor tracking:
- Add `vendor?: VendorId` to `CuratedProduct` interface (optional for backward compatibility)
- Add `vendor?: VendorId` to `ProductPreview` interface
- Import VendorId from `../vendor/types.js`

**scripts/pipeline/fetch-product.ts** — Refactor to use VendorAdapter:

1. Change the `fetchProductData` function signature:
   ```typescript
   export async function fetchProductData(style: string, vendorId?: VendorId): Promise<ProductData>
   ```

2. At the top of the function:
   - Import both adapters to ensure registration: `import '../sanmar/adapter.js'` and `import '../ss-activewear/adapter.js'`
   - Call `getVendor(vendorId ?? 'sanmar')` to get the adapter
   - Call `adapter.fetchAllProductData(style)` to get UnifiedProductData

3. Map UnifiedProductData back to the existing ProductData interface for backward compatibility. This is the key bridge: the pipeline still uses ProductData internally (for mapper.ts compatibility), but it's now populated from unified types.
   - Create a mapping function `unifiedToProductData(unified: UnifiedProductData): ProductData` that converts:
     - unified.products → ProductInfo[] (reconstruct SanMar-shaped objects)
     - unified.pricing → PricingInfo | null
     - unified.inventory → SkuInventory[]
     - unified.media → MediaContent[]

   **IMPORTANT:** This reverse mapping is a transitional bridge. For SanMar, the mapping is lossless. For S&S, the mapping constructs SanMar-shaped objects from unified data. This approach avoids rewriting mapper.ts and create-product.ts in this plan — those will continue to consume ProductData as before.

4. Set `preview.vendor = vendorId ?? 'sanmar'` on the returned ProductPreview

5. Update CLI runner to accept `--vendor` flag:
   ```
   Usage: npx tsx scripts/pipeline/fetch-product.ts [--vendor sanmar|ss] <STYLE>
   ```
   Parse `--vendor` from process.argv before the style argument. Use `parseVendorFlag()` from vendor registry.

**Key design decision:** This plan bridges unified types back to existing ProductData shape rather than rewriting all pipeline consumers. This is deliberate — it minimizes risk and keeps the change contained. Future phases can migrate pipeline internals to unified types directly if desired.
  </action>

  <done>fetchProductData accepts optional vendorId parameter, defaults to 'sanmar', CLI accepts --vendor flag, pipeline still outputs ProductData shape for backward compatibility</done>
