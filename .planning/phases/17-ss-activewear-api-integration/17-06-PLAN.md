4. Add `vendor?: VendorId` to `StockAlert` interface

**scripts/monitor/poller.ts:**
Read the existing poller to understand its structure. Then:

1. Import VendorAdapter registry: `import { getVendor } from '../vendor/registry.js'`
2. Import both adapters for registration: `import '../sanmar/adapter.js'` and `import '../ss-activewear/adapter.js'`
3. In the polling function (where it currently calls SanMar inventory functions directly):
   - Determine vendor from `trackedProduct.vendor ?? 'sanmar'`
   - Get adapter: `const adapter = getVendor(vendor)`
   - Call `adapter.getStyleInventory(style)` instead of direct SanMar call
   - Map UnifiedInventory[] to SkuSnapshot[] (the existing internal format)
   - The rest of the change detection / alert generation logic stays the same

4. Create a mapping helper: `unifiedInventoryToSnapshots(inventory: UnifiedInventory[]): SkuSnapshot[]`:
   - Maps UnifiedWarehouse[] to WarehouseQuantity[] (converting id back to number for SanMar, keeping string for S&S)
   - Note: WarehouseQuantity.warehouseId is currently `number`. For S&S (string abbreviations like "IL"), use a hash or lookup to create a numeric ID, OR change warehouseId to `number | string`. **Decision: Change WarehouseQuantity.warehouseId to `string` type** — this is cleaner and SanMar numeric IDs work fine as strings. Update all consumers of warehouseId to handle string.

**scripts/monitor/store.ts:**
If the store reads/writes TrackedProduct from JSON files:
- Ensure vendor field is preserved in serialization
- Ensure backward compatibility: existing tracked-products.json files without vendor field default to 'sanmar'

**Key constraint:** Existing tracked SanMar products must continue working without any manual migration. The vendor field defaults to 'sanmar' when absent.
