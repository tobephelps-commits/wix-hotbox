<objective>
Add recent-choice memory to the product creation form so settings persist across sessions.

Purpose: Eliminate repetitive re-configuration. The form remembers the user's last selections (vendor, pricing preset, markup%, rounding, size upcharges, logo overlay settings, decoration cost) and pre-fills them on next visit. Only product-specific data (style number, colors, sizes) resets — everything else carries forward.

Output: localStorage-backed form state persistence with save-on-change and restore-on-load behavior.
</objective>

<task type="auto">
  <name>Task 1: Implement localStorage save/restore for form preferences</name>
  <files>scripts/pipeline/preview.html</files>
  <action>
Add a form-preferences persistence layer using localStorage in preview.html.

**What to persist** (key: `hotbox_pipeline_prefs`):
- `vendor` — last selected vendor ('sanmar' or 'ss')
- `pricingPreset` — last selected preset key (e.g., 'standard-tee', 'hoodie-fleece')
- `markupPercent` — last used markup percentage (number)
- `rounding` — last used rounding mode ('nearest-99', 'nearest-dollar', 'none')
- `sizeUpcharges` — last used upcharge map (e.g., { '2XL': 2, '3XL': 3, ... })
- `angleOverlayState` — last logo overlay configuration per angle (the full angleOverlayState object)
- `decorationCost` — last used decoration cost (number, 0 if unset)
- `decorationType` — last used decoration type (string, 'none' if unset)

**What NOT to persist** (product-specific, changes every time):
- Style number
- Selected colors
- Selected sizes
- Product data (fetched from vendor)

**Implementation approach:**

1. Add a `savePrefs()` function that serializes the above fields to `localStorage.setItem('hotbox_pipeline_prefs', JSON.stringify({...}))`. Call it after any form field changes that affect the persisted values: preset change, markup change, rounding change, upcharge edits, vendor change, logo overlay toggle/select/scale/position changes.

2. Add a `loadPrefs()` function that reads from localStorage on page load, parses JSON, and applies values to the form state variables AND DOM elements:
   - Set `currentVendor` and update `vendorSelect.value`
   - Set `pricingConfig.markupPercent` and update `markupInput.value`
   - Set `pricingConfig.rounding` and update `roundingSelect.value`
   - Set `pricingConfig.sizeUpcharges` and update the upcharge table inputs
   - Set `currentPreset` and update `presetSelect.value`
   - Set `angleOverlayState` values (but don't trigger overlay previews until a product is loaded)
   - Handle missing/corrupt localStorage gracefully — if parse fails, use defaults silently

3. Call `loadPrefs()` at the end of the initialization section (after DOM refs are set up but before any product is loaded). This ensures the form shows remembered settings even before a style number is entered.

4. Wire `savePrefs()` calls into existing event listeners:
   - `vendorSelect 'change'` handler (line ~3564)
   - `presetSelect 'change'` handler (line ~3725)
   - `markupInput 'input'` handler (wherever markup updates)
   - `roundingSelect 'change'` handler
   - Upcharge input change handlers
   - Angle overlay toggle/logo-select/scale/position change handlers

**Important:** Don't modify the create flow. The `createDraft()` function already reads from the state variables — if those variables are pre-filled from localStorage, the create flow automatically uses them. No changes needed to the server or API.

**UX detail:** Add a small "Settings remembered" indicator near the pricing section header that appears briefly (2s fade) when prefs are loaded from storage, so users know their settings were restored. Use a subtle text like "✓ Settings restored from last session" in muted color, positioned after the "Pricing" section title.

<task type="auto">
  <name>Task 2: Add server-side last-used preferences endpoint for backup persistence</name>
  <files>scripts/pipeline/preview-server.ts</files>
  <action>
Add a simple server-side preferences endpoint as a fallback for when localStorage is cleared (e.g., browser reset). This stores the same preferences to a JSON file on disk.

**Endpoint:** `GET /api/preferences` and `PUT /api/preferences`

**Storage:** `data/pipeline-preferences.json`

**GET /api/preferences:**
- Read `data/pipeline-preferences.json`, return `{ ok: true, data: {...} }` or `{ ok: true, data: null }` if file doesn't exist.

**PUT /api/preferences:**
- Accept JSON body with the same shape as the localStorage prefs object.
- Write to `data/pipeline-preferences.json` with `JSON.stringify(body, null, 2)`.
- Return `{ ok: true }`.

**Route registration in parseRoute():**
- Add route matching for `/api/preferences` → `{ route: 'preferences' }`
- In the request handler switch, handle both GET and PUT for this route.

**Integration with preview.html:**
- In `savePrefs()`, also fire a background `fetch('/api/preferences', { method: 'PUT', headers: {'Content-Type': 'application/json'}, body: JSON.stringify(prefs) })` — fire-and-forget, no await needed, wrapped in try/catch that silently fails.
- In `loadPrefs()`, if localStorage has no saved prefs, attempt `fetch('/api/preferences')` as fallback. If server has prefs, use them AND save to localStorage for next time.

**File I/O pattern:** Follow existing data/*.json patterns (e.g., data/templates.json, data/customers.json):
```typescript
import { readFileSync, writeFileSync, existsSync, mkdirSync } from 'node:fs';
const PREFS_PATH = path.join(DATA_DIR, 'pipeline-preferences.json');
```

Use DATA_DIR constant that should already exist for other data files. If not, derive from `path.resolve(import.meta.dirname, '../../data')` following the existing pattern.

    3. curl http://localhost:3456/api/preferences → returns { ok: true, data: { vendor: "ss", markupPercent: 120 } }
    4. Verify data/pipeline-preferences.json file exists on disk with correct content
  </verify>
  <done>Server-side preferences endpoint works for GET and PUT. Preview.html saves preferences to both localStorage and server. On load, falls back to server if localStorage is empty.</done>
