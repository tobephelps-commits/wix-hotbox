<task type="auto">
  <name>Task 1: Build SOAP client factory with caching</name>
  <files>scripts/sanmar/client.ts</files>
  <action>
Create the SOAP client factory that all service modules use to get connected SOAP clients.

**scripts/sanmar/client.ts:**

1. Import `soap` (use `import * as soap from 'soap'`)
2. Import `WSDL_URLS`, `TEST_WSDL_URLS` from `./constants.js`

3. Create a `Map<string, soap.Client>` for client caching (module-level singleton)

4. `getClient(wsdlUrl: string): Promise<soap.Client>` function:
   - Check cache first — if client exists for this WSDL URL, return cached
   - Otherwise call `soap.createClientAsync(wsdlUrl)` to create new client
   - Cache the client and return it
   - IMPORTANT: WSDL parsing is expensive (network fetch + XML parse). Creating per-request is the #1 anti-pattern. Always cache.

5. `getProductInfoClient(useTest?: boolean): Promise<soap.Client>` convenience function:
   - Returns getClient(useTest ? TEST_WSDL_URLS.productInfo : WSDL_URLS.productInfo)

6. `getInventoryClient(useTest?: boolean): Promise<soap.Client>` convenience function:
   - Returns getClient for inventory WSDL

7. `getPricingClient(useTest?: boolean): Promise<soap.Client>` convenience function:
   - Returns getClient for pricing WSDL

8. `getPSProductClient(useTest?: boolean): Promise<soap.Client>` — PromoStandards Product Data
9. `getPSInventoryClient(useTest?: boolean): Promise<soap.Client>` — PromoStandards Inventory
10. `getPSMediaClient(useTest?: boolean): Promise<soap.Client>` — PromoStandards Media Content
11. `getPSPricingClient(useTest?: boolean): Promise<soap.Client>` — PromoStandards Pricing

12. `describeClient(client: soap.Client): object` function:
    - Returns `client.describe()` — useful for discovering available methods and argument structure
    - This is critical for validating WSDL parsing since exact arg mapping needs runtime validation

13. `clearClientCache(): void` function:
    - Clears the client cache Map — useful for testing and recovery from connection errors

14. `getLastRequest(client: soap.Client): string | undefined` — returns `client.lastRequest`
15. `getLastResponse(client: soap.Client): string | undefined` — returns `client.lastResponse`

Export all functions. Export the `soap` namespace as well for type usage in service modules.

NOTE on port 8080: SanMar WSDLs run on port 8080. The URLs in constants.ts already include the port. If connection fails, the error handler (Task 2) should detect ECONNREFUSED/ETIMEDOUT and suggest checking port 8080 firewall rules.

<task type="auto">
  <name>Task 2: Build error handling and retry utilities</name>
  <files>scripts/sanmar/utils/error-handler.ts, scripts/sanmar/utils/retry.ts</files>
  <action>
Create error handling utilities for SOAP calls. SanMar's API has specific error patterns documented in RESEARCH.md.

**scripts/sanmar/utils/error-handler.ts:**

1. Define `SanMarErrorType` enum:
   - `INVALID_CREDENTIALS` — bad username/password/customer number
   - `INVALID_STYLE` — style number not found
   - `INVALID_COLOR` — color not found (likely catalogColor vs color confusion)
   - `INVALID_SIZE` — size not found
   - `TIMEOUT` — response too large or server timeout
   - `CONNECTION_ERROR` — ECONNREFUSED, ETIMEDOUT (port 8080 blocked)
   - `SOAP_FAULT` — generic SOAP fault
   - `UNKNOWN` — unclassified error

2. Define `SanMarError` class extending Error:
   - `type: SanMarErrorType`
   - `originalError?: unknown`
   - `soapFault?: string` (raw SOAP fault XML if available)
   - `suggestion?: string` (actionable fix suggestion)

3. `classifyError(error: unknown): SanMarError` function:
   - Parse error to determine type:
     - Check for `errorOccured === true` in SanMar responses → read `message` field
     - Message contains "Invalid Style" or "Invalid Color" or "Invalid Size" → INVALID_STYLE/COLOR/SIZE
     - Message contains "Authentication" or "Invalid credentials" → INVALID_CREDENTIALS
     - Error code ECONNREFUSED or ETIMEDOUT → CONNECTION_ERROR with suggestion about port 8080
     - SOAP fault detected → SOAP_FAULT
     - Response is null/empty after long wait → TIMEOUT with suggestion about large dataset
     - Otherwise → UNKNOWN
   - For INVALID_COLOR: Add suggestion "Use catalogColor (mainframe color) instead of display color name. Example: 'Ath. Maroon' not 'Athletic Maroon'"
   - For CONNECTION_ERROR: Add suggestion "Ensure port 8080 is open for outbound traffic to 63.251.12.134"
   - For TIMEOUT: Add suggestion "Avoid querying by brand or category. Use style-level queries instead."

4. `isRetryable(error: SanMarError): boolean` function:
   - TIMEOUT → true (worth retrying)
   - CONNECTION_ERROR → true (transient network issue)
   - SOAP_FAULT → true (server hiccup)
   - INVALID_CREDENTIALS, INVALID_STYLE, INVALID_COLOR, INVALID_SIZE → false (user error, won't change)
   - UNKNOWN → false (don't retry blindly)

5. `formatError(error: SanMarError): string` function:
   - Returns human-readable error string with type, message, and suggestion

Export all: SanMarErrorType, SanMarError, classifyError, isRetryable, formatError.

**scripts/sanmar/utils/retry.ts:**

1. Define `RetryOptions` interface:
   - maxRetries: number (default 3)
   - baseDelay: number in ms (default 1000)
   - maxDelay: number in ms (default 10000)
   - onRetry?: (attempt: number, error: SanMarError) => void (optional callback)

2. `withRetry<T>(fn: () => Promise<T>, options?: Partial<RetryOptions>): Promise<T>` function:
   - Execute fn()
   - On error: classify with classifyError(), check isRetryable()
   - If retryable and attempts remaining: wait with exponential backoff (baseDelay * 2^attempt, capped at maxDelay), call onRetry callback if provided, retry
   - If not retryable or max retries exceeded: throw the SanMarError
   - Use actual `setTimeout` with Promise wrapper for delays (not busy-wait)

3. `DEFAULT_RETRY_OPTIONS: RetryOptions` const with defaults

Export all.

IMPORTANT: Do NOT use any external retry library. This is simple enough to implement correctly, and SanMar-specific error classification needs custom logic.
