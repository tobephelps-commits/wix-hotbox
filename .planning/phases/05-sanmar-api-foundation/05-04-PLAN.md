<objective>
Build the pricing and inventory service modules. Pricing service wraps SanMar Standard `getPricing` for querying wholesale prices and sale pricing. Inventory service wraps both SanMar Standard `getInventoryQtyForStyleColorSize` (per-item) and PromoStandards `GetInventoryLevels` (batch).

Purpose: Pricing and inventory are essential for the product creation pipeline (pricing feeds WIX product prices) and the inventory monitoring system (Phase 8). Building both in one plan keeps the commercial data services together.
Output: `pricing.ts` service with price lookups and sale detection. `inventory.ts` service with per-warehouse stock queries and batch capability. `services/index.ts` barrel export.
</objective>

  <name>Task 1: Build pricing service</name>
  <files>scripts/sanmar/services/pricing.ts</files>
  <action>
Create the pricing service that queries SanMar for product pricing.

**scripts/sanmar/services/pricing.ts:**

1. Import: getPricingClient from `../client.js`, getSanMarAuth from `../auth.js`, types from `../types/index.js`, PRICING_CODES from `../constants.js`, withRetry from `../utils/retry.js`, classifyError from `../utils/error-handler.js`

2. Define `PricingQuery` interface:
   - style: string (required)
   - color?: string (optional — catalogColor)
   - size?: string (optional)

3. `getPricing(query: PricingQuery): Promise<PricingResponse>` function:
   - Get client via getPricingClient()
   - Get auth via getSanMarAuth()
   - Build SOAP args with query params + auth
   - Call `client.getPricingAsync(args)` wrapped in withRetry()
   - Parse and return typed response
   - Check errorOccured — classify and throw on error

4. `getStylePricing(style: string): Promise<PricingInfo>` convenience:
   - Calls getPricing({ style })
   - Returns pricing info for the style (piece, case, sale prices)
   - Throws if style not found

5. `getVariantPricing(style: string, catalogColor: string, size: string): Promise<PricingInfo>` function:
   - Calls getPricing({ style, color: catalogColor, size })
   - Returns pricing for specific variant

6. `isSaleActive(pricing: PricingInfo): boolean` function:
   - Check if saleStartDate and saleEndDate are set
   - Parse dates and compare to current date
   - Return true if current date is within sale window
   - NOTE: Sale pricing updates every Monday and Wednesday (from RESEARCH.md pitfall 6)

7. `getEffectivePrice(pricing: PricingInfo): number` function:
   - If isSaleActive(pricing) and pieceSalePrice > 0, return pieceSalePrice
   - Otherwise return piecePrice
   - This is the wholesale cost HotBox pays — HotBox then applies their markup (Phase 7)

8. `getSuggestedRetail(pricing: PricingInfo): number` function:
   - Look up priceCode in PRICING_CODES to get markup percentage
   - Calculate: piecePrice * (1 + markupPercentage / 100)
   - Return suggested retail price
   - NOTE: HotBox may use different markup logic (Phase 7), but SanMar's suggested retail is useful as reference

9. `formatPricingSummary(pricing: PricingInfo): string` function:
   - Returns human-readable pricing summary: "Piece: $X.XX, Case: $X.XX, Sale: $X.XX (until MM/DD), Code: X (Y% markup)"
   - Useful for CLI output and logging

Export all functions and PricingQuery interface.

IMPORTANT: "Dozens pricing" is deprecated (RESEARCH.md SOTA). The dozenPrice field now returns the piece price. Do NOT display or calculate with dozen pricing — just ignore the field.

<task type="auto">
  <name>Task 2: Build inventory service</name>
  <files>scripts/sanmar/services/inventory.ts, scripts/sanmar/services/index.ts</files>
  <action>
Create the inventory service with both per-item and batch query capabilities.

**scripts/sanmar/services/inventory.ts:**

1. Import: getInventoryClient, getPSInventoryClient from `../client.js`, getSanMarAuth, getPromoStandardsAuth from `../auth.js`, types from `../types/index.js`, WAREHOUSES, INVENTORY_CAP from `../constants.js`, withRetry from `../utils/retry.js`

2. Define `InventoryQuery` interface:
   - style: string (required)
   - color?: string (optional — catalogColor)
   - size?: string (optional)

3. `getInventory(query: InventoryQuery): Promise<InventoryResponse>` function:
   - Get client via getInventoryClient()
   - Get auth via getSanMarAuth()
   - Build SOAP args: arg0=customerNumber, arg1=username, arg2=password, arg3=style, arg4=color (or empty), arg5=size (or empty)
   - NOTE: Inventory service uses positional args (arg0-arg5), NOT named object args like product info. Verify with describeClient() at runtime.
   - Call `client.getInventoryQtyForStyleColorSizeAsync(args)` wrapped in withRetry()
   - Parse response into InventoryResponse type
   - Return typed response

4. `getStyleInventory(style: string): Promise<SkuInventory[]>` convenience:
   - Calls getInventory({ style })
   - Returns array of all SKU inventory (all colors and sizes with per-warehouse breakdown)
   - This is the primary query for checking a full style's stock

5. `getTotalQuantity(skuInventory: SkuInventory): number` utility:
   - Sums qty across all warehouses for a single SKU
   - Returns total available quantity

6. `isInStock(skuInventory: SkuInventory, minQty?: number): boolean` utility:
   - Returns true if getTotalQuantity >= minQty (default 1)
   - Use minQty > 1 for case pack requirements or minimum order thresholds

7. `isWellStocked(skuInventory: SkuInventory): boolean` utility:
   - Returns true if any warehouse shows INVENTORY_CAP (1500) — means "1500 or more"
   - Per RESEARCH.md pitfall 3: 1500 is the API cap, actual quantity is higher

8. `getInventoryBatch(partIds: string[]): Promise<PSPartInventory[]>` function:
   - Uses PromoStandards GetInventoryLevels with partIdArray for batch queries
   - Get client via getPSInventoryClient()
   - Get auth via getPromoStandardsAuth('2.0.0')
   - Build args with partIdArray (up to 200 partIds per call)
   - If partIds.length > 200, chunk into batches of 200 and call sequentially (do NOT parallelize — respect SanMar server load)
   - Parse PSPartInventory[] response
   - Return combined array

9. `formatInventorySummary(skus: SkuInventory[]): string` function:
   - Returns human-readable inventory summary table
   - Format: "Color | Size | Total | In Stock | Warehouses with stock"
   - Show per-warehouse breakdown for items with low stock
   - Flag items at INVENTORY_CAP as "1500+"
   - Useful for CLI output

- This provides a single import point: `import { getProductByStyle, getStylePricing, getStyleInventory, getProductImages } from '../services/index.js'`

Export all functions and InventoryQuery interface.
