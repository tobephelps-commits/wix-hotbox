  <name>Task 1: Build product data service</name>
  <files>scripts/sanmar/services/product.ts</files>
  <action>
Create the product data service that queries SanMar for product information by style number.

**scripts/sanmar/services/product.ts:**

1. Import: getProductInfoClient from `../client.js`, getSanMarAuth from `../auth.js`, types from `../types/index.js`, withRetry from `../utils/retry.js`, classifyError from `../utils/error-handler.js`

2. Define `ProductQuery` interface:
   - style: string (required — SanMar style number like "PC61", "K420")
   - color?: string (optional — catalogColor/mainframe color, NOT display color name)
   - size?: string (optional — size code like "S", "M", "L", "XL", "2XL")

3. `getProductInfo(query: ProductQuery): Promise<ProductInfoResponse>` function:
   - Get client via getProductInfoClient()
   - Get auth via getSanMarAuth()
   - Build SOAP args: arg0 = { style, color, size } from query (omit undefined fields), arg1 = auth object
   - Call `client.getProductInfoByStyleColorSizeAsync(args)` wrapped in withRetry()
   - Parse response: extract result.return (or result[0].return depending on node-soap response format)
   - Check errorOccured field — if true, classify and throw using classifyError()
   - Return typed ProductInfoResponse

   NOTE on node-soap response format: node-soap's `*Async` methods return `[result, rawResponse, soapHeader, rawRequest]`. The actual data is in `result` (first element). The exact object path depends on WSDL parsing — use describeClient() during development to verify. The arg structure may use `arg0`/`arg1` positional params or named params — this needs runtime validation.

4. `getProductByStyle(style: string): Promise<ProductInfo[]>` convenience function:
   - Calls getProductInfo({ style })
   - Returns just the listResponse array (all colors and sizes for that style)
   - Filters out discontinued products (productStatus not in ACTIVE_PRODUCT_STATUSES)

5. `getProductByStyleAndColor(style: string, catalogColor: string): Promise<ProductInfo[]>` function:
   - Calls getProductInfo({ style, color: catalogColor })
   - Returns listResponse filtered to active statuses
   - NOTE: Parameter is named `catalogColor` to prevent the #1 pitfall (using display color instead of mainframe color)

6. `getProductVariant(style: string, catalogColor: string, size: string): Promise<ProductInfo | null>` function:
   - Calls getProductInfo({ style, color: catalogColor, size })
   - Returns single matching product or null if not found
   - Checks errorOccured — "Invalid Style + Color + Size" returns null (not found), other errors throw

7. `extractUniqueColors(products: ProductInfo[]): Array<{ catalogColor: string, displayColor: string }>` utility:
   - Takes product list, extracts unique color pairs (catalogColor + color display name)
   - Returns deduplicated sorted array
   - Useful for variant curation (Phase 7)

8. `extractAvailableSizes(products: ProductInfo[]): string[]` utility:
   - Takes product list, extracts unique sizes in SanMar size order
   - Returns sorted array (XS, S, M, L, XL, 2XL, 3XL, 4XL, 5XL, 6XL)
   - Size ordering: use the `sizeIndex` field from ProductBasicInfo for sort order

Export all functions and the ProductQuery interface.

<task type="auto">
  <name>Task 2: Build media content service</name>
  <files>scripts/sanmar/services/media.ts</files>
  <action>
Create the media content service that retrieves product images from SanMar via PromoStandards GetMediaContent.

**scripts/sanmar/services/media.ts:**

1. Import: getPSMediaClient from `../client.js`, getPromoStandardsAuth from `../auth.js`, types from `../types/index.js`, MEDIA_CLASS_TYPES from `../types/media.js`, withRetry from `../utils/retry.js`

2. Define `MediaQuery` interface:
   - productId: string (required — SanMar style number)
   - partId?: string (optional — specific SKU/part ID for one variant's images)
   - classType?: number (optional — filter by image type using MEDIA_CLASS_TYPES values)
   - mediaType?: 'Image' | 'Document' (default: 'Image')

3. `getMediaContent(query: MediaQuery): Promise<MediaContent[]>` function:
   - Get client via getPSMediaClient()
   - Get auth via getPromoStandardsAuth('1.1.0') — Media Content uses PS version 1.1.0
   - Build SOAP args: GetMediaContentRequest = { ...auth, mediaType, productId, partId (if provided), classType (if provided) }
   - Call `client.GetMediaContentAsync(args)` wrapped in withRetry()
   - Parse response: extract MediaContentArray.MediaContent (may be array or single object)
   - Normalize to always return an array
   - Return typed MediaContent[]

4. `getProductImages(style: string): Promise<MediaContent[]>` convenience:
   - Calls getMediaContent({ productId: style, mediaType: 'Image' })
   - Returns all images for the style

5. `getFrontImages(style: string): Promise<MediaContent[]>` convenience:
   - Calls getMediaContent({ productId: style, classType: MEDIA_CLASS_TYPES.Front })
   - Returns only front-view images (classType 1007)
   - These are typically the primary product images

6. `getSwatchImages(style: string): Promise<MediaContent[]>` convenience:
   - Calls getMediaContent({ productId: style, classType: MEDIA_CLASS_TYPES.Swatch })
   - Returns color swatch images (classType 1004)

7. `getImagesByColor(style: string, color: string): Promise<MediaContent[]>` function:
   - Calls getProductImages(style)
   - Filters results where mediaContent.color matches the provided color
   - Returns all image types for that specific color

8. `groupImagesByColor(images: MediaContent[]): Map<string, MediaContent[]>` utility:
   - Groups a flat image array by color field
   - Returns Map where key is color name, value is array of images for that color
   - Useful for Phase 6 when assigning images to WIX product variants

Export all functions and MediaQuery interface.

NOTE: HotBox uses mockup images (not SanMar product photos) for their custom decorated products. The media service is still valuable for: (1) getting blank product reference images during product creation, (2) color swatches for variant selection, (3) spec sheets for product details. The mockup images are added separately in the WIX product creation flow (Phase 6).
