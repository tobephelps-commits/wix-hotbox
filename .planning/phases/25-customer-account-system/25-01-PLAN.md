<task type="auto">
  <name>Task 1: Create customer account types and JSON-backed store</name>
  <files>scripts/customers/types.ts, scripts/customers/store.ts</files>
  <action>
Create the customer account data model and persistence layer following the exact patterns from scripts/orders/types.ts and scripts/orders/order-store.ts.

**types.ts** — Define these types:

1. `CustomerAccount` interface:
   - `id: string` — UUID (crypto.randomUUID)
   - `name: string` — Brand/company name (e.g., "Board 30", "Big Barn")
   - `contactName: string` — Primary contact person
   - `email: string` — Contact email (optional, not a primary key)
   - `phone?: string` — Contact phone
   - `logoKeys: string[]` — Array of logo registry keys (references data/logos.json keys like "board-30-logo-black-6x6"). This links the logo system to customer accounts.
   - `markupPercent: number` — Single markup percentage applied to wholesale cost for this customer (e.g., 40 means cost * 1.40). This is the key pricing field.
   - `royaltyPercent: number` — Royalty rate percentage on retail sales for this customer (used in phase 26 for royalty reporting)
   - `notes?: string` — Free-text notes
   - `active: boolean` — Whether account is currently active (default true)
   - `createdAt: string` — ISO-8601 timestamp
   - `updatedAt: string` — ISO-8601 timestamp

2. `CustomerStore` interface:
   - `customers: CustomerAccount[]` — Array of all customer accounts
   - `lastUpdated: string` — ISO-8601 timestamp

**store.ts** — Implement CRUD following order-store.ts pattern:

- `CUSTOMERS_DIR = './data/customers'`
- `CUSTOMERS_FILE = path.join(CUSTOMERS_DIR, 'customers.json')`
- `loadCustomers(): Promise<CustomerStore>` — Load from JSON, create dir/file if missing, normalize missing fields
- `saveCustomers(store: CustomerStore): Promise<void>` — Atomic write (.tmp then rename)
- `addCustomer(data: Omit<CustomerAccount, 'id' | 'createdAt' | 'updatedAt'>): Promise<CustomerAccount>` — Generate UUID, set timestamps, append, save
- `getCustomer(id: string): Promise<CustomerAccount | undefined>` — Find by ID
- `updateCustomer(id: string, updates: Partial<Pick<CustomerAccount, 'name' | 'contactName' | 'email' | 'phone' | 'logoKeys' | 'markupPercent' | 'royaltyPercent' | 'notes' | 'active'>>): Promise<CustomerAccount>` — Merge updates, set updatedAt, save
- `deleteCustomer(id: string): Promise<boolean>` — Remove from array, save, return success
- `listCustomers(activeOnly?: boolean): Promise<CustomerAccount[]>` — Filter by active status if specified

Use ESM imports with .js extensions (NodeNext resolution). Use node:fs/promises, node:path, node:crypto — same as order-store.ts.

Do NOT add tiers, volume discounts, or any complexity beyond what's specified. Per the CONTEXT.md: "Single markup percentage per customer (not per-category or tiered)."

<task type="auto">
  <name>Task 2: Add customer REST API endpoints to preview server</name>
  <files>scripts/pipeline/preview-server.ts</files>
  <action>
Add customer account CRUD endpoints to the existing preview server, following the exact routing and response patterns already established (manual string matching in parseRoute, sendJson responses with {ok: true/false}).

**New endpoints:**

1. `GET /api/customers` — List all customers
   - Import and call `loadCustomers()` from '../customers/store.js'
   - Return `{ ok: true, customers: CustomerAccount[] }`
   - Support optional `?active=true` query param to filter active only

2. `POST /api/customers` — Create a new customer
   - Parse JSON body with readBody()
   - Validate required fields: name, contactName, markupPercent, royaltyPercent
   - Validate markupPercent >= 0 and royaltyPercent >= 0 (these are money calculations — reject negatives)
   - Validate logoKeys (if provided) are strings
   - Call `addCustomer(data)`
   - Return `{ ok: true, customer: CustomerAccount }`
   - On validation error: `{ ok: false, error: "descriptive message" }`

3. `GET /api/customers/:id` — Get single customer
   - Parse customer ID from URL path
   - Call `getCustomer(id)`
   - If not found: `{ ok: false, error: "Customer not found" }` with 404
   - Otherwise: `{ ok: true, customer: CustomerAccount }`

4. `PATCH /api/customers/:id` — Update customer
   - Parse JSON body with readBody()
   - Validate markupPercent/royaltyPercent >= 0 if present
   - Call `updateCustomer(id, updates)`
   - Return `{ ok: true, customer: CustomerAccount }`
   - On not found: `{ ok: false, error: "Customer not found" }` with 404

5. `DELETE /api/customers/:id` — Delete customer
   - Call `deleteCustomer(id)`
   - Return `{ ok: true }` or `{ ok: false, error: "Customer not found" }` with 404

**Integration points:**
- Add import for customer store functions at top of preview-server.ts (alongside existing order/logo imports)
- Add routes in the existing parseRoute() function / request handler, following the same URL matching patterns used by /api/orders, /api/logos, etc.
- Use the same sendJson() helper for all responses
- Add 'customers' to any route listing/documentation if present

**Validation is critical** — markupPercent and royaltyPercent are used for money calculations. Reject non-numeric values, NaN, Infinity, and negative numbers.
