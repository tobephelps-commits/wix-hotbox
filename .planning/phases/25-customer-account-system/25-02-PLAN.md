- Add a "Customers" tab button in the header navigation alongside existing tabs (Products, Orders, Inventory, etc.)
- Wire tab switching using the same show/hide pattern used by other tabs
- Add a `#customersTab` container div that shows/hides with tab selection

**Customer list grid:**
- Use CSS grid with `grid-template-columns: repeat(auto-fill, minmax(300px, 1fr))` — same as logo library grid pattern

  - Contact name (secondary text)
  - Markup: XX% (in a colored badge — use the same badge styling as order status badges)
  - Royalty: XX% (in a second badge)
  - Active/Inactive status indicator (green dot for active, gray for inactive)
  - Edit button and Delete button (small, icon-style, top-right corner of card)
- Cards should have the same border-radius, shadow, and hover effects as logo library cards

**Empty state:**
- When no customers exist, show a centered message: "No customer accounts yet" with a prominent "Add Customer" button
- Same empty-state styling pattern used elsewhere in the dashboard

**Load data on tab activation:**
- Fetch GET /api/customers when the Customers tab is activated
- Store customers in a local `customersList` array for rendering
- Add a `renderCustomerCards()` function that clears and rebuilds the grid

**Add Customer button:**
- Prominent button in the section header (right-aligned, same style as "Upload Logo" button in logo section)
- Opens the create/edit form (built in Task 2)

<task type="auto">
  <name>Task 2: Build customer create/edit forms and delete flow</name>
  <files>scripts/pipeline/preview.html</files>
  <action>
Add the create/edit form modal and delete confirmation for customer management. Follow existing form patterns in preview.html.

**Create/Edit form:**
- Modal overlay (or inline form section) that appears when "Add Customer" or card Edit button is clicked
- Fields:
  - Brand Name (text input, required) — prominent, large
  - Contact Name (text input, required)
  - Email (text input, optional)
  - Phone (text input, optional)
  - Markup % (number input, required, min=0, step=0.1) — with helper text: "Applied to wholesale cost for this customer's products"
  - Royalty % (number input, required, min=0, step=0.1) — with helper text: "Royalty rate on retail sales"
  - Logo Selection (multi-select from existing logo registry) — fetch GET /api/logos and show checkboxes or a tag-picker with logo thumbnails so owner can assign which logos belong to this customer
  - Notes (textarea, optional)
  - Active toggle (checkbox, default checked)
- Save button: POST /api/customers (create) or PATCH /api/customers/:id (edit)
- Cancel button: close form without saving
- On save success: refresh customer list, close form, show brief success indicator
- On validation error: display error message from API response near the relevant field

**Edit pre-population:**
- When editing an existing customer, pre-fill all fields from the customer data
- The form title should change: "Add Customer" vs "Edit Customer"

**Delete flow:**
- Delete button on card triggers confirmation: "Delete [Brand Name]? This cannot be undone."
- On confirm: DELETE /api/customers/:id
- On success: remove card from grid with brief animation or just re-render

**Logo assignment display:**
- In the form, show available logos as small thumbnail chips (similar to color selection chips in product creation)
- Selected logos get a highlighted border (same selected state pattern as color-card.selected)
- On save, send `logoKeys` array to the API

**Markup/Royalty validation:**
- Client-side: prevent non-numeric input, show error if < 0
- Server-side validation is already in place from Plan 01
