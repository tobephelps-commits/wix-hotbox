<task type="auto">
  <name>Task 1: Create pi/ directory structure and bootstrap script</name>
  <files>pi/bootstrap.sh, pi/README.md</files>
  <action>
Create the `pi/` directory as the deployment artifact root for all Pi-specific scripts and configs.

Create `pi/bootstrap.sh` — the master setup script that runs on a fresh Pi OS Lite (64-bit, Bookworm) install. This script:

1. **OS choice: Pi OS Lite 64-bit (Bookworm)**
   - No desktop environment — lighter, fewer attack surfaces, faster boot
   - We install only what we need (Chromium, X11 minimal)
   - ARM64 for Node.js 20+ compatibility

2. **System updates and base packages:**
   - `apt update && apt upgrade -y`
   - Install: `git`, `curl`, `unzip`, `build-essential` (for native node modules)
   - Install Node.js 20 LTS via NodeSource repository (not apt default which is old)
   - Install npm globally

3. **User setup:**
   - Create `hotbox` system user if not exists
   - Set up `/home/hotbox/app` as the application directory
   - Set ownership and permissions

4. **Locale and timezone:**
   - Set locale to `en_US.UTF-8`
   - Set timezone to `America/New_York` (configurable via HOTBOX_TIMEZONE env var)

5. **Script requirements:**
   - Must run as root (check at top, exit if not)
   - Idempotent — safe to run multiple times
   - Log all output to `/var/log/hotbox-bootstrap.log`
   - Exit on any error (`set -euo pipefail`)
   - Print clear progress messages

Create `pi/README.md` with:
- Hardware requirements (Pi 5, 4GB+ RAM, 32GB+ SD card, 15.6" touchscreen)
- Step-by-step: flash Pi OS Lite 64-bit to SD card using Raspberry Pi Imager
- Enable SSH in Imager advanced options
- First boot: SSH in, clone repo, run bootstrap.sh
- Subsequent setup scripts referenced (kiosk, services, resilience)
  </action>
  <verify>bash -n pi/bootstrap.sh (syntax check passes)</verify>
  <done>pi/bootstrap.sh exists, is executable, installs Node.js 20, creates hotbox user, sets locale/timezone. pi/README.md documents the full setup flow.</done>
</task>

<task type="auto">
  <name>Task 2: Create network and SSH configuration</name>
  <files>pi/config/hotbox.conf, pi/config/wpa_supplicant.conf.template, pi/config/ssh-setup.sh</files>
  <action>
Create `pi/config/hotbox.conf` — central configuration file sourced by all pi/ scripts:
```bash
# HotBox Pi Appliance Configuration
HOTBOX_HOSTNAME="hotbox"
HOTBOX_USER="hotbox"
HOTBOX_APP_DIR="/home/hotbox/app"
HOTBOX_PORT=3456
HOTBOX_TIMEZONE="America/New_York"
HOTBOX_WIFI_COUNTRY="US"
```

Create `pi/config/wpa_supplicant.conf.template` — WiFi template:
```
ctrl_interface=DIR=/var/run/wpa_supplicant GROUP=netdev
update_config=1
country=${HOTBOX_WIFI_COUNTRY}

network={
    ssid="${WIFI_SSID}"
    psk="${WIFI_PASSWORD}"
    key_mgmt=WPA-PSK
}
```

Create `pi/config/ssh-setup.sh` — SSH hardening script:
1. Enable SSH service
2. Disable password auth (key-only after initial setup)
3. Generate SSH host keys if missing
4. Create `.ssh/authorized_keys` for hotbox user from `HOTBOX_SSH_PUBKEY` env var (if set)
5. Restart sshd

Script must:
- Source `hotbox.conf` for configuration
- Be idempotent
- Run as root
- Use `set -euo pipefail`

Update `pi/bootstrap.sh` to source `pi/config/hotbox.conf` and call `pi/config/ssh-setup.sh` at the end.
  </action>
  <verify>bash -n pi/config/ssh-setup.sh (syntax check passes)</verify>
  <done>hotbox.conf provides central config. wpa_supplicant template ready for WiFi setup. ssh-setup.sh hardens SSH access. bootstrap.sh sources config and calls ssh-setup.</done>
</task>
