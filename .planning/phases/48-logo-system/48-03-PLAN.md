**LogoPlacementEditor.tsx** — Visual drag-and-drop logo positioning on product images.

Port the placement engine from scripts/pipeline/preview.html (lines 7550-7900 JavaScript) to React.

**Core features:**
- Container div with product image as background (object-fit: contain)
- Logo overlay div positioned absolutely within the container, draggable via pointer events
- Position stored as proportional coordinates (0.0-1.0) relative to the displayed product image area
- Logo resizable via scale slider (range 0.05-0.80)
- Alignment guides: horizontal and vertical center lines that appear when logo center is near 50% on either axis (snap threshold: 2%)
- Coordinate display pill showing current x, y, and scale%

**Drag implementation (touch-first):**
- Use pointerdown/pointermove/pointerup events (unified mouse+touch)
- setPointerCapture for reliable drag tracking
- Calculate position relative to displayed product image bounds (not container — image may be letterboxed)
- Use ResizeObserver to track image display dimensions for accurate coordinate mapping
- Clamp logo position to keep it within image bounds
- Show alignment guides when near center (x≈0.5 or y≈0.5)

**Position presets:**
- Row of preset buttons: center-chest, left-chest, full-front, center-back, left-sleeve
- Fetch presets from GET /api/logos (positionPresets field, already fetched)
- Clicking a preset animates logo to that position

**Scale control:**
- Range slider below the placement area
- Label shows current scale as percentage
- Updates logo size in real-time

**Per-angle tabs:**
- Three tabs: Front, Back, Side
- Each tab has its own placement container with independent position/scale
- Tab shows product image for that angle (from preview data — front/back/side URLs)
- Tabs disabled if no image available for that angle
- Each angle can be toggled on/off (checkbox) — disabled = no logo for that angle

**Logo selector:**
- Dropdown or thumbnail strip at top showing available logos (from GET /api/logos)
- Each logo shows thumbnail + display name
- Selecting a logo loads it into all active angle placement containers
- "Manage Logos" link opens LogoManager (from Plan 02)

**Props:**
```typescript
interface LogoPlacementEditorProps {
  previewData: PreviewData;  // Product preview with image URLs per color
  selectedColors: string[];  // Which colors are selected
  onComplete: (config: AngleOverlayConfig | null) => void;  // null = skip logo
  onBack: () => void;
  onManageLogos: () => void;
}
```

Uses first selected color's images for the placement preview (representative).

**LogoStep.tsx** — Wrapper that manages the logo step in the creation flow:
- "Skip Logo" button (sets config to null, proceeds to pricing)
- "Continue with Logo" button (passes AngleOverlayConfig to onComplete)
- Header: "Logo Placement" with step indicator
- Renders LogoPlacementEditor

**CSS additions to ProductsTab.css:**
- Logo placement container: relative positioning, dark background, min-height 400px
- Product image: object-fit contain, centered
- Logo draggable: absolute positioning, cursor grab/grabbing, touch-action none
- Alignment guides: 1px dashed lines, semi-transparent accent color
- Coordinate pill: fixed bottom-center of container, semi-transparent background
- Per-angle tabs: horizontal tab bar matching dark theme
- Preset buttons: horizontal scrollable row, pill-shaped buttons
- Scale slider: full-width below placement area

**Frontend — ProductsTab.tsx state machine update:**

Current flow: lookup → preview → configure → creating → done
New flow: lookup → preview → **logo** → configure → creating → done

- Add 'logo' step between 'preview' and 'configure'
- ProductPreview's "Continue" button now goes to 'logo' step (not 'configure')
- LogoStep renders at 'logo' step
- LogoStep's onComplete(config) stores AngleOverlayConfig in state, advances to 'configure'
- LogoStep's onBack returns to 'preview'
- LogoStep's "Skip Logo" sets logo config to null, advances to 'configure'
- LogoStep's onManageLogos sets step to 'manage-logos' with a return-to-logo flag
- Pass logoConfig to CreateFlow when creating product

**State additions:**
- `logoConfig: AngleOverlayConfig | null` — stored after logo step
- `returnToLogo: boolean` — for managing return from logo management

**CreateFlow update:**
- Include logoConfig in the POST /api/pipeline/create body
- Add logo overlay as a visible step in the creation progress display

**Backend — src/routes/pipeline.ts:**
- Update POST /create endpoint to accept optional `logoConfig: AngleOverlayConfig` in request body
- If logoConfig is provided and not null, pass it to createWixProduct

**Backend — src/pipeline/create-product.ts:**
- Import overlay functions from src/logo/overlay.ts
- After building media payload (image URLs), if logoConfig is provided:
  - For each selected color, get front/back/side image URLs
  - Call overlayProductImagesByAngle(angleImages, logoConfig) to generate overlay images
  - Add overlay image URLs to the WIX media payload (as additional product images)
  - Log overlay generation progress
- If no logoConfig, skip overlay (existing behavior unchanged)

**Key considerations:**
- Overlay images are saved to {dataDir}/overlays/ directory
- Overlay images need to be served statically or uploaded to WIX media
- For WIX upload: read overlay file buffer, upload via WIX media API (importFile endpoint), use returned URL in product media
- Sequential processing per color to avoid memory pressure on Pi hardware
