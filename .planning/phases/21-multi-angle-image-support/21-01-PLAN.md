<objective>
Extend product pipeline to pass back and side images through to WIX product media, and expose multi-angle image URLs in the ColorPreview for curation UI.

Purpose: Currently only front images are assigned to WIX products. Back and side images are already fetched by both vendor adapters and stored in UnifiedMedia, but buildMediaPayload() discards them. This plan wires the existing multi-angle data through to WIX and the preview UI data model.

Output: WIX products created through the pipeline will include back and side images per color. ColorPreview will expose backImageUrl and sideImageUrl for the curation UI.
</objective>

<task type="auto">
  <name>Task 2: Extend buildMediaPayload to include back and side images</name>
  <files>scripts/pipeline/mapper.ts</files>
  <action>
Rewrite buildMediaPayload() to include multi-angle images while respecting the WIX 15-image limit.

New priority strategy (per selected color):
1. Front image → assigned to Color choice (existing behavior, unchanged)
2. Back image (classTypeId 1008) → assigned to Color choice
3. Side image (classTypeId 2001) → assigned to Color choice

After per-color angle images, fill remaining slots with general images (Primary 1006, High 2001 without color assignment) — same as current Step 2 behavior but only for images not already added.

Implementation:
- Keep the existing loop structure but add two inner lookups after the front image lookup:
  - Find back image: `colorImages.find(img => img.classType.classTypeId === CLASS_TYPE_REAR)`
  - Find side image: `colorImages.find(img => img.classType.classTypeId === CLASS_TYPE_HIGH)`
- Each found image gets pushed with the same `choice: { option: 'Color', choice: color.displayColor }` assignment
- Track added URLs in the existing addedUrls Set to avoid duplicates
- The WIX_MEDIA_LIMIT (15) check stays on every push

Define CLASS_TYPE_REAR = 1008 constant at the top of the file alongside the existing CLASS_TYPE_FRONT, CLASS_TYPE_PRIMARY, CLASS_TYPE_HIGH constants.

Note: Do NOT change the unifiedToProductData() bridge in fetch-product.ts — it already maps backImage→1008 and sideImage→2001, so the MediaContent entries are already present in imagesByColor.
  </action>
  <verify>npx tsc --noEmit passes. Manually verify by running: npx tsx scripts/pipeline/fetch-product.ts PC61 and confirming the images array contains classTypeId 1008 entries</verify>
  <done>buildMediaPayload() includes up to 3 images per color (front, back, side) all assigned to Color choice, with general images filling remaining slots up to the 15-image WIX limit.</done>
