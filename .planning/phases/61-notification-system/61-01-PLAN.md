<task type="auto">
  <name>Task 1: Create notification migration and types</name>
  <files>src/db/migrations/007-notifications.sql, src/notifications/types.ts</files>
  <action>
Create migration 007-notifications.sql with two tables:

**notification_templates** - configurable stage triggers:
- id INTEGER PRIMARY KEY AUTOINCREMENT
- stage TEXT NOT NULL — order status that triggers notification (matches OrderStatus: 'ordered', 'received', 'in-production', 'packed', 'shipped', 'delivered', 'cancelled')
- channel TEXT NOT NULL — 'email' or 'sms'
- enabled INTEGER NOT NULL DEFAULT 1
- subject TEXT — email subject template (null for SMS)
- body_template TEXT NOT NULL — message template with placeholders: {{orderNumber}}, {{customerName}}, {{status}}, {{storeName}}
- created_at TEXT NOT NULL DEFAULT (datetime('now'))
- updated_at TEXT NOT NULL DEFAULT (datetime('now'))
- UNIQUE(stage, channel) — one template per stage+channel combo

**notification_log** - delivery history:
- id INTEGER PRIMARY KEY AUTOINCREMENT
- order_id INTEGER NOT NULL REFERENCES orders(id) ON DELETE CASCADE
- template_id INTEGER REFERENCES notification_templates(id) ON DELETE SET NULL
- channel TEXT NOT NULL — 'email' or 'sms'
- recipient TEXT NOT NULL — email address or phone number
- subject TEXT — email subject (null for SMS)
- body TEXT NOT NULL — rendered message body
- status TEXT NOT NULL DEFAULT 'pending' — 'pending', 'sent', 'failed'
- error_message TEXT — error details on failure
- sent_at TEXT — ISO timestamp when actually sent
- created_at TEXT NOT NULL DEFAULT (datetime('now'))
- CREATE INDEX idx_notification_log_order ON notification_log(order_id)
- CREATE INDEX idx_notification_log_status ON notification_log(status)

Seed default templates for customer-facing stages (these are the stages customers care about):
- 'ordered' / email: "Your order #{{orderNumber}} has been placed with our supplier"
- 'shipped' / email: "Your order #{{orderNumber}} has shipped!"
- 'delivered' / email: "Your order #{{orderNumber}} has been delivered"
- 'ordered' / sms: "HotBox: Order #{{orderNumber}} placed with supplier"
- 'shipped' / sms: "HotBox: Order #{{orderNumber}} shipped!"
- SMS templates default enabled=0 (disabled until Twilio configured)

Create src/notifications/types.ts with:
- NotificationChannel = 'email' | 'sms'
- NotificationStatus = 'pending' | 'sent' | 'failed'
- NotificationTemplate interface (matches DB columns, camelCase)
- NotificationLogEntry interface (matches DB columns, camelCase)
- CreateTemplateInput (stage, channel, subject?, bodyTemplate, enabled?)
- UpdateTemplateInput (subject?, bodyTemplate?, enabled?)
- NotificationContext (orderNumber, customerName, customerEmail?, customerPhone?, status, storeName)
- SendResult { success: boolean; error?: string; logId?: number }
  </action>

Create src/notifications/store.ts following the wix-contacts/store.ts pattern (Database as first parameter, snake_case↔camelCase row mapping):

**Template CRUD:**

- getNotificationLog(db, filter?: { orderId?, channel?, status?, limit?, offset? }): { entries: NotificationLogEntry[], totalCount: number }

**Template rendering:**
- renderTemplate(template: string, context: NotificationContext): string — replace {{placeholder}} with context values. Use simple string replacement (no template engine needed). Handle missing values by leaving placeholder as empty string.
