  <name>Task 1: Create notification trigger engine</name>
  <files>src/notifications/trigger.ts, src/notifications/index.ts</files>
  <action>
Create src/notifications/trigger.ts — the orchestrator that fires notifications when order status changes.

**Main function:**
- triggerOrderNotifications(db: Database, config: Config, notificationConfig: NotificationConfig, orderId: string, newStatus: OrderStatus): Promise<SendResult[]>

**Flow:**
1. Get all enabled templates for this status stage: getEnabledTemplatesForStage(db, newStatus)
2. If no templates, return [] (no notifications configured for this stage)
3. Look up the order: getOrder(db, orderId) — need order details for context
4. If order not found, return [{ success: false, error: 'Order not found' }]
5. Resolve customer contact info:
   - First check order's billing info (order.billingAddress has name, email, phone fields from WIX)
   - If order has a customer email in its data, use that
   - Also try to find WIX contact by email: search wix_contacts store for matching email
   - Build NotificationContext: { orderNumber, customerName (firstName + lastName from billing or contact), customerEmail, customerPhone, status: newStatus, storeName: 'HotBox Clothing' }
6. For each enabled template:
   - If channel === 'email': call sendOrderEmail(notificationConfig, db, orderId as number, template, context)
   - If channel === 'sms': call sendOrderSms(config, db, orderId as number, template, context)
7. Return array of SendResult

**Customer info resolution helper:**
- resolveCustomerContact(db: Database, order: Order): { name: string, email: string | null, phone: string | null }
- Priority for email: order.buyerEmail > order.billingAddress?.email (if exists) > WIX contact lookup
- Priority for phone: order.billingAddress?.phone > WIX contact lookup
- Priority for name: order.billingAddress?.firstName + lastName > WIX contact name > 'Customer'

Note: The trigger function is intentionally best-effort. It logs all attempts to notification_log but never throws. If one channel fails, it still tries the other.

Update src/notifications/index.ts barrel to export:
- export { triggerOrderNotifications, resolveCustomerContact } from './trigger.js'

**Create src/routes/notifications.ts** — Fastify plugin following established route pattern:

GET /api/notifications/templates — List all notification templates
  Response: { templates: NotificationTemplate[] }

GET /api/notifications/templates/:id — Get single template
  Response: NotificationTemplate or 404

POST /api/notifications/templates — Create new template
  Body: { stage: OrderStatus, channel: 'email'|'sms', subject?: string, bodyTemplate: string, enabled?: boolean }
  Response: 201 + NotificationTemplate
  Validate: stage must be valid OrderStatus, channel must be 'email' or 'sms'

PATCH /api/notifications/templates/:id — Update template
  Body: { subject?: string, bodyTemplate?: string, enabled?: boolean }
  Response: NotificationTemplate or 404

DELETE /api/notifications/templates/:id — Delete template
  Response: 204 or 404

GET /api/notifications/log — View notification history
  Query: orderId?, channel?, status?, limit? (default 50), offset? (default 0)
  Response: { entries: NotificationLogEntry[], totalCount: number }

GET /api/notifications/log/order/:orderId — All notifications for an order
  Response: { entries: NotificationLogEntry[] }

POST /api/notifications/test — Send a test notification
  Body: { templateId: number, channel: 'email'|'sms', recipient: string }
  Sends a test message using dummy context (orderNumber: 'TEST-001', customerName: 'Test Customer', status: template's stage)
  Response: SendResult
