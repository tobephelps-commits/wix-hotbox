  <action>
Add a GET /api/orders/catalog endpoint that searches the product_mappings table for products already pushed to WIX.

Query parameters:
- `search` (optional string): Filters by product_name or style (case-insensitive LIKE match)
- `vendor` (optional VendorId): Filter by vendor
- `limit` (optional number, default 20, max 50): Pagination limit

Implementation:
1. Import `listMappings` pattern from `src/sync/product-map.ts` — but write a new query function inline (don't modify product-map.ts) that does filtered search with LIKE
2. Query: `SELECT style, vendor, wix_product_id, product_name, linked_at FROM product_mappings WHERE (product_name LIKE ? OR style LIKE ?) [AND vendor = ?] ORDER BY product_name LIMIT ?`
3. Use parameterized queries (never interpolate search input into SQL)
4. Return `{ products: Array<{ style, vendor, productName, wixProductId }> }`

The endpoint is lightweight — it returns catalog entries only. The UI will call the existing `/api/pipeline/preview/:vendorId/:style` endpoint separately when the user selects a product to get full color/size/pricing details.

<task type="auto">
  <name>Task 2: Create ProductPicker component</name>
  <files>ui/src/components/orders/ProductPicker.tsx, ui/src/components/orders/ProductPicker.css</files>
  <action>
Create a modal-style ProductPicker component with two browse modes and a color/size selection step.

**Component interface:**
```typescript
interface PickedProduct {
  productName: string;
  vendorStyle: string;
  vendor: 'sanmar' | 'ss';
  color: string;
  size: string;
  unitPrice: number;
  imageUrl: string | null;
}

interface ProductPickerProps {
  onPick: (product: PickedProduct) => void;
  onClose: () => void;
}
```

**Two-step flow:**

Step 1 — Product Search (two tabs):

Tab "WIX Catalog":
- Text search input that calls `GET /api/orders/catalog?search={term}` on input (debounce 300ms)
- Display results as a list: product name, style number, vendor badge (SanMar/S&S)
- Click a result → fetch `GET /api/pipeline/preview/{vendor}/{style}` → advance to Step 2

Tab "Vendor Lookup":
- Reuse the StyleLookup pattern: vendor toggle (SanMar/S&S) + style number input
- Submit → fetch `GET /api/pipeline/preview/{vendor}/{style}` → advance to Step 2

Step 2 — Color/Size/Qty Selection:
- Show product title, brand name, and description at top
- Color selector: grid of color swatches/names from PreviewData.availableColors. Each color shows frontImageUrl thumbnail. Selected color highlighted.
- Size selector: row of size buttons from PreviewData.availableSizes. Selected size highlighted.
- Price display: Show wholesale price and suggested retail from PreviewData.pricing
- Quantity input (number, min 1, default 1)
- "Add to Order" button (disabled until color + size selected)
- "Back" button to return to Step 1

When "Add to Order" clicked:
- Call `onPick()` with populated PickedProduct
- Product name = `${brandName} ${productTitle}`
- vendorStyle = style from lookup
- vendor = selected vendor
- color = selected color displayColor
- size = selected size
- unitPrice = pricing.suggestedRetail (the retail price, not wholesale)
- imageUrl = selected color's frontImageUrl

**Styling (ProductPicker.css):**
- Modal overlay (same pattern as OrderCreateForm overlay)
- Follow existing BEM naming: `product-picker__*`
- Color swatches: 48x48px grid items with border highlight on selection
- Size buttons: pill-shaped, inline row
- Match existing dark theme from OrderCreateForm.css

**Important:**
- Use `PreviewData` type from StyleLookup.tsx (import it) for the preview response shape
- Debounce the catalog search input with a simple setTimeout/clearTimeout pattern (no new dependencies)
- Show loading spinner during API calls
- Show error messages on API failures
