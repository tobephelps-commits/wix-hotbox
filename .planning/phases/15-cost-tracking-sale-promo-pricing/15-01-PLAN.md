<objective>
Build cost tracking data model with decoration cost support, historical cost recording, and a CLI margin report across all products.

Purpose: The existing pipeline stores only SanMar wholesale cost per variant in WIX. There is no tracking of decoration cost (screen printing, embroidery, heat transfer), no historical record of cost changes, and no way to view profitability across products. This plan adds the foundation that all subsequent pricing features build on.

Output: cost-tracker.ts module for recording costs, data/cost-history.json for persistence, margin-report.ts CLI script for viewing product profitability.
</objective>

<task type="auto">
  <name>Task 1: Add cost tracking types and decoration cost to pricing model</name>
  <files>scripts/pipeline/types.ts, scripts/pipeline/pricing-rules.ts</files>
  <action>
  1. In types.ts, add new interfaces:

  - `ProductCostRecord`: Tracks all costs for a single product.
    Fields: style (string), productName (string), wixProductId (string), wholesaleCost (number — SanMar piece price), decorationCost (number — per-unit decoration cost, default 0), decorationType (string — "screen-print" | "embroidery" | "heat-transfer" | "dtg" | "none"), totalCost (number — wholesale + decoration), retailPrice (number — base retail, no size upcharge), margin (object with dollars and percent), pricingPreset (string — preset key used), createdAt (string — ISO timestamp), updatedAt (string — ISO timestamp).

  - `CostHistoryEntry`: A point-in-time cost snapshot.
    Fields: timestamp (string — ISO), wholesaleCost (number), decorationCost (number), totalCost (number), retailPrice (number), margin (object with dollars and percent), reason (string — "initial" | "cost-change" | "price-change" | "sale-start" | "sale-end").

  - `CostHistoryFile`: The data/cost-history.json schema.
    Fields: products (Record of style to object containing current ProductCostRecord and history array of CostHistoryEntry), lastUpdated (string — ISO timestamp).

  2. In pricing-rules.ts, add a new function `calculateTotalCost(wholesaleCost: number, decorationCost: number): number` that returns the sum. This is trivial but centralizes the concept. Also add `calculateFullMargin(retailPrice: number, wholesaleCost: number, decorationCost: number): { dollars: number; percent: number }` that calculates margin INCLUDING decoration cost (retail - wholesale - decoration). The existing calculateMargin function remains for backward compatibility.

  3. Extend CuratedProduct in types.ts to add an optional `decorationCost?: number` field and optional `decorationType?: string` field so the create-product CLI can pass decoration costs through to WIX.

  Do NOT modify existing function signatures or behavior — only add new exports.
  </action>
  <verify>npx tsc --noEmit passes with no errors</verify>
  <done>New cost tracking types exported from types.ts, new cost calculation functions exported from pricing-rules.ts, CuratedProduct extended with optional decoration fields</done>
</task>

<task type="auto">
  <name>Task 2: Build cost tracker module and margin report CLI</name>
  <files>scripts/pipeline/cost-tracker.ts, scripts/pipeline/margin-report.ts, data/cost-history.json, scripts/pipeline/create-product.ts, package.json</files>
  <action>
  1. Create scripts/pipeline/cost-tracker.ts:
    - `loadCostHistory()`: Read data/cost-history.json (create with empty products object and current timestamp if not exists). Return CostHistoryFile.
    - `saveCostHistory(data: CostHistoryFile)`: Write to data/cost-history.json with pretty-print.
    - `recordProductCost(params)`: Given style, productName, wixProductId, wholesaleCost, decorationCost, decorationType, retailPrice, pricingPreset — compute margin using calculateFullMargin, upsert into products map, append CostHistoryEntry with reason "initial" (or "cost-change"/"price-change" if existing entry has different values). Return the ProductCostRecord.
    - `getProductCost(style)`: Return ProductCostRecord or null.
    - `getAllProductCosts()`: Return all ProductCostRecord entries.
    - `getCostHistory(style)`: Return CostHistoryEntry array for a style.

  2. In create-product.ts:
    - Add `--decoration-cost N` and `--decoration-type TYPE` CLI flags (parsed like existing flags).
    - After successful product creation (after Step 4 verify), call recordProductCost() to persist cost data. Pass through the decoration cost (default 0) and type (default "none").
    - Add decoration cost/type to template save if --save-template is used (extend ProductTemplate with optional decorationCost and decorationType fields).
    - Print margin info in the Result output: "Margin: $X.XX (Y.Y%) [wholesale: $A + decoration: $B = total cost: $C]"
    - Template precedence for decoration: --decoration-cost > template.decorationCost > 0

  3. Create scripts/pipeline/margin-report.ts:
    - CLI script: `npx tsx scripts/pipeline/margin-report.ts [--style STYLE] [--sort margin|cost|retail] [--below N]`
    - No args: Print table of ALL tracked products with columns: Style, Name, Wholesale, Decoration, Total Cost, Retail, Margin $, Margin %, Preset.
    - --style STYLE: Show detailed cost history for a single product.
    - --sort: Sort by margin%, total cost, or retail price (default: margin%).
    - --below N: Only show products with margin% below N (profitability alert).
    - Format as aligned CLI table using string padding (no external table library).

  4. Add to package.json scripts: `"margin-report": "npx tsx scripts/pipeline/margin-report.ts"`

  5. Add data/cost-history.json to .gitignore (local data, like collections.json and templates.json).
