<objective>
Build sale/promo pricing engine that applies time-limited retail price changes to WIX products with automatic revert scheduling.

Purpose: The store owner needs to run flash sales, seasonal promotions, and clearance pricing on selected products. Currently, changing prices requires manually editing each product in WIX or re-running the creation pipeline. This plan adds a dedicated sale pricing system that can batch-update WIX product prices and automatically revert them when the sale ends.

Output: sale-pricing.ts module with sale CRUD, price application to WIX, and scheduled revert logic. CLI commands for creating, listing, and ending sales.
</objective>

<task type="auto">
  <name>Task 2: Build sale pricing module with CLI commands</name>
  <files>scripts/pipeline/sale-pricing.ts, data/active-sales.json, package.json</files>
  <action>
  1. Create scripts/pipeline/sale-pricing.ts with:

  **Data layer:**
  - `loadActiveSales()`: Read data/active-sales.json (create if not exists).
  - `saveActiveSales(data)`: Write with pretty-print.

  **Sale CRUD:**
  - `createSale(params)`: Create a SaleConfig with generated id (sale-{unixTimestamp}), status "scheduled" if startDate is future or "active" if startDate is now/past and endDate is future. Save to file. Return the sale.
  - `getSale(id)`: Return sale or null.
  - `listSales(filter?: "active" | "scheduled" | "ended")`: Return filtered sales.
  - `cancelSale(id)`: Set status to "cancelled". If sale was active, revert prices.

  **Price calculation:**
  - `calculateSalePrice(originalPrice: number, discountType: SaleConfig["discountType"], discountValue: number)`: Apply discount.
    - "percent": originalPrice * (1 - discountValue / 100)
    - "fixed": originalPrice - discountValue (min 0.01)
    - "override": discountValue (exact price)
    - Round to 2 decimal places.

  **WIX price application:**
  - `applySale(saleId: string)`: For each product style in the sale's productStyles:
    1. Load cost history to get wixProductId.
    2. Get current product from WIX (getProduct) to snapshot original prices.
    3. Store original prices in sale's originalPrices map.
    4. Calculate sale price for each variant.
    5. Call updateProductVariants with new prices.
    6. Call updateProduct to update base product price.
    7. Update cost history with reason "sale-start".
    8. Set sale status to "active". Save.

  - `revertSale(saleId: string)`: Restore original prices from the sale's originalPrices snapshot.
    1. For each style, call updateProductVariants with stored original variant prices.
    2. Call updateProduct to restore base price.
    3. Update cost history with reason "sale-end".
    4. Set sale status to "ended". Save.

  - `checkAndProcessSales()`: Check all sales — activate scheduled sales whose startDate has passed, end active sales whose endDate has passed. This is the "cron-like" function meant to be called periodically (or manually).

  **CLI interface** (when run directly):
  - `npx tsx scripts/pipeline/sale-pricing.ts create --name "Flash Sale" --discount 20% --styles PC61,K420 --start 2026-02-01 --end 2026-02-03`
  - `npx tsx scripts/pipeline/sale-pricing.ts create --name "Clearance" --discount $5 --styles PC61 --start now --end 2026-02-15`
  - `npx tsx scripts/pipeline/sale-pricing.ts create --name "Fixed Price" --discount @19.99 --styles PC61 --start now --end 2026-02-15`
  - `npx tsx scripts/pipeline/sale-pricing.ts list [--active|--scheduled|--ended]`
  - `npx tsx scripts/pipeline/sale-pricing.ts apply SALE_ID` (manually trigger)
  - `npx tsx scripts/pipeline/sale-pricing.ts revert SALE_ID` (manually revert)
  - `npx tsx scripts/pipeline/sale-pricing.ts cancel SALE_ID`
  - `npx tsx scripts/pipeline/sale-pricing.ts check` (process scheduled/expired sales)

  Discount format parsing: "20%" = percent 20, "$5" = fixed 5, "@19.99" = override 19.99.

  2. Add to package.json scripts: `"sale": "npx tsx scripts/pipeline/sale-pricing.ts"`

  3. Add data/active-sales.json to .gitignore.
