<task type="auto">
  <name>Task 1: Add --template and --save-template to create-product CLI</name>
  <files>scripts/pipeline/create-product.ts</files>
  <action>
Add two new flags to the CLI runner in `create-product.ts`:

**`--template <name>`** — Load a saved template and apply it to auto-curation:
1. Call `getTemplate(name)` from templates.ts
2. If not found, print error listing available templates and exit 1
3. Apply template fields to the CuratedProduct being built:
   - `pricingConfig`: If template has `pricingConfig`, use it. Else if template has `pricingPreset`, use `getPresetConfig(preset)`. CLI `--preset` and `--price` still override.
   - `selectedSizes`: If template has `selectedSizes`, filter `data.preview.availableSizes` to only include template sizes. Otherwise keep all sizes.
   - `colorFilter`: If template has `colorFilter` as string array, filter `data.preview.availableColors` to only include those catalog colors. If "all" or not specified, keep all colors.
   - `collections`: If template has `collections`, use them. CLI `--collection` flags ADD to template collections (don't replace).
4. Print which template was applied and what it set:
   ```
   Applied template "bigbarn-tee":
     Pricing: standard-tee (100% markup)
     Sizes: S, M, L, XL, 2XL (filtered from 8 available)
     Collections: Big Barn Crossfit
   ```

**`--save-template <name>`** — After successful product creation, save the current settings as a template:
1. Parse this flag before product creation (alongside other args)
2. After successful `createWixProduct()`, build a ProductTemplate from the CuratedProduct that was used
3. Call `saveTemplate(template)` to persist it
4. Print confirmation: `Template "${name}" saved. Use --template "${name}" for future products.`

**Precedence order (highest to lowest):**
1. `--price` (explicit price override)
2. `--preset` (named pricing preset)
3. `--template` pricing fields (from saved template)
4. Default: `standard-tee`

**Update --help** to document both flags with examples:
```
  --template "name"        Apply saved template (pricing, sizes, colors, collections)
  --save-template "name"   Save current settings as reusable template after creation
```

Import `getTemplate`, `saveTemplate`, `listTemplates` from `./templates.js`.
  </action>

  <done>--template applies saved template to product creation. --save-template saves current settings. Precedence: --price > --preset > --template > default. Both flags documented in --help.</done>
</task>

<task type="auto">
  <name>Task 2: Add template API endpoints to preview server</name>
  <files>scripts/pipeline/preview-server.ts</files>
  <action>
Add template management endpoints to the preview server's HTTP router. Follow the existing router pattern (URL path matching in the request handler).

**New endpoints:**

1. **`GET /api/templates`** — List all saved templates
   - Call `listTemplates()`
   - Return JSON: `{ templates: ProductTemplate[] }`

2. **`GET /api/templates/:name`** — Get a single template
   - Call `getTemplate(name)` (URL-decode the name parameter)
   - Return 200 with template JSON, or 404 with `{ error: "Template not found" }`

3. **`POST /api/templates`** — Save a new template
   - Read body as JSON, expect `ProductTemplate` shape
   - Validate: `name` field required, non-empty
   - Call `saveTemplate(template)`
   - Return 201 with saved template JSON

4. **`DELETE /api/templates/:name`** — Delete a template
   - Call `deleteTemplate(name)`
   - Return 200 with `{ deleted: true }` or 404 with `{ error: "Template not found" }`

5. **`GET /api/presets`** — List available pricing presets
   - Import `PRICING_PRESETS` from pricing-rules.ts
   - Return JSON: `{ presets: Record<string, PricingPreset> }`

Import `listTemplates`, `getTemplate`, `saveTemplate`, `deleteTemplate` from `./templates.js` and `PRICING_PRESETS` from `./pricing-rules.js`.

Follow existing server patterns:
- Use `readBody()` helper for POST body
- Return JSON with `res.writeHead(200, { 'Content-Type': 'application/json' })` + `res.end(JSON.stringify(data))`
- Handle errors with try/catch and 500 response

Do NOT modify the preview.html file in this task — the API is consumable by future UI updates or direct fetch calls. The UI integration can be done when the preview server UI is next updated.
