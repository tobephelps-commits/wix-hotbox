<task type="auto">
  <name>Task 1: Execute API-automatable fixes on the live WIX store</name>
  <files>scripts/apply-api-fixes.ts</files>
  <action>
Read WIX-EDITOR-FIXES.md (from Plan 11-01) and identify all fixes marked as "Automatable" or "WIX API".

Based on the v0.1 audit, the following categories MAY have API-automatable components:
- **Product description updates** — WIX REST API can update product descriptions (already used in v0.1 for size guides). Check if any product-level text fixes are pending.
- **Product visibility/status** — API can toggle product visibility. Check if any products need hiding (like the already-hidden LMNT products).
- **Collection assignments** — API can add/remove products from collections. Check if any collection reorganization is pending.
- **Product media** — API can add/update product images. Check if any product image fixes are pending (Big Barn Team Hat was already addressed).

Create `scripts/apply-api-fixes.ts` that:
1. Reads the WIX API key from .env
2. For each automatable fix, applies the change via the existing wix-api.ts client
3. Logs each change: `[APPLIED] Fix ID: Description — API call details`
4. Reports summary: `X fixes applied, Y skipped (already done), Z failed`

If Plan 11-01's triage reveals NO API-automatable fixes remain (because v0.1 already handled all API-accessible items like CK-1, CK-2, CR-2, CR-4, CL-4), then:
- Create the script as a no-op that documents WHY nothing is automatable
- Log: "All API-automatable fixes were completed in v0.1. Remaining fixes require WIX Editor/Dashboard."
- This is a valid outcome — documenting the boundary is the value

Do NOT fabricate fixes that don't exist. Only apply changes that are clearly identified in the master checklist as automatable.
  </action>
  <verify>Script runs without errors. If fixes were applied, verify via WIX API query that changes are reflected. If no fixes are automatable, script reports that clearly.</verify>
  <done>All API-automatable fixes applied (or documented as already complete). Script exists for future use.</done>
