<task type="auto">
  <name>Task 1: Create royalty calculation types and pure functions</name>
  <files>scripts/customers/royalty.ts, scripts/customers/types.ts</files>
  <action>
Create scripts/customers/royalty.ts with the royalty calculation engine. Follow the same pure-function pattern as scripts/customers/pricing.ts (no API deps, testable, composable, round2 at every step).

**Types to define in royalty.ts:**

1. `RoyaltyLineItem` — represents one order line item's royalty calculation:
   - `orderId: string` — reference to the order
   - `orderNumber: number` — display order number
   - `orderDate: string` — ISO-8601 date from order.createdAt
   - `productName: string` — from OrderLineItem.productName
   - `sku: string` — from OrderLineItem.sku (or empty string)
   - `color: string` — from OrderLineItem.color (or empty string)
   - `size: string` — from OrderLineItem.size (or empty string)
   - `quantity: number` — from OrderLineItem.quantity
   - `unitPrice: number` — actual unit price charged (from OrderLineItem.unitPrice)
   - `royaltyRate: number` — customer's royaltyPercent (copied for transparency)
   - `royaltyPerUnit: number` — calculated royalty per unit (may be $0 if discounted)
   - `royaltyTotal: number` — royaltyPerUnit * quantity
   - `discounted: boolean` — true if royalty was zeroed due to discount

2. `RoyaltyReport` — complete royalty report for a customer over a date range:
   - `customerId: string`
   - `customerName: string`
   - `royaltyRate: number` — customer's royaltyPercent
   - `periodStart: string` — ISO-8601 date range start
   - `periodEnd: string` — ISO-8601 date range end
   - `generatedAt: string` — ISO-8601 timestamp when report was generated
   - `lineItems: RoyaltyLineItem[]` — all line items sorted by orderDate ASC
   - `totalUnits: number` — sum of all line item quantities
   - `totalRevenue: number` — sum of all unitPrice * quantity
   - `totalRoyalty: number` — sum of all royaltyTotal
   - `discountedLineItems: number` — count of line items with discounted=true
   - `orderCount: number` — number of distinct orders in the report

**Functions to implement:**

1. `matchOrdersToCustomer(orders: Order[], customerName: string): Order[]`
   - Filter orders where order.collection matches customerName (case-insensitive trim comparison).
   - This is the linkage: WIX orders have `collection` set to the brand name (e.g., "Board 30") during sync, which corresponds to the customer account name.
   - Return matched orders sorted by createdAt ASC.

2. `filterOrdersByDateRange(orders: Order[], start: string, end: string): Order[]`
   - Filter orders where order.createdAt >= start AND order.createdAt <= end (ISO string comparison works for ISO-8601).
   - Only include non-cancelled orders (status !== 'cancelled').

3. `isDiscountedLineItem(lineItem: OrderLineItem, order: Order): boolean`
   - Determine if a line item was sold at a discount that eliminates markup.
   - Logic: if `order.discount > 0` AND the order's discount effectively removes the markup, the line items are discounted. Since we don't have per-line-item discount tracking, use a simple heuristic: if the order has ANY discount applied (`order.discount > 0`), mark ALL line items in that order as discounted. This is conservative — it avoids charging royalty on orders where discount codes were used. The owner manually creates orders and would know which orders used staff discount codes.
   - Return true if discounted (royalty should be $0).

4. `calculateRoyaltyForLineItem(lineItem: OrderLineItem, order: Order, royaltyPercent: number): RoyaltyLineItem`
   - If `isDiscountedLineItem(lineItem, order)` returns true: royaltyPerUnit = 0, discounted = true.
   - Otherwise: royaltyPerUnit = round2(lineItem.unitPrice * royaltyPercent / 100).
   - royaltyTotal = round2(royaltyPerUnit * lineItem.quantity).
   - Build and return the full RoyaltyLineItem with all fields populated from the order and line item.

5. `generateRoyaltyReport(params: { customer: CustomerAccount; orders: Order[]; periodStart: string; periodEnd: string }): RoyaltyReport`
   - The main entry point. Takes a customer and ALL orders (caller is responsible for loading orders from store).
   - Calls matchOrdersToCustomer to filter orders for this customer.
   - Calls filterOrdersByDateRange to apply date range.
   - For each matched order, iterates line items and calls calculateRoyaltyForLineItem.
   - Aggregates totals (totalUnits, totalRevenue, totalRoyalty, discountedLineItems, orderCount).
   - Returns complete RoyaltyReport.

**Also add to scripts/customers/types.ts:**
- Export `RoyaltyLineItem` and `RoyaltyReport` types (re-export from royalty.ts, or define in types.ts and import in royalty.ts — use whichever keeps the module structure clean; defining in royalty.ts and re-exporting from types.ts is fine).

**Critical implementation notes:**
- Use round2 (Math.round(value * 100) / 100) for ALL money calculations, same as pricing.ts.
- Import Order and OrderLineItem types from scripts/orders/types.ts.
- Import CustomerAccount from scripts/customers/types.ts.
- All functions are pure — no file I/O, no API calls, no side effects.
- Date comparison uses ISO-8601 string comparison (lexicographic) which works correctly for date ranges.

Add two new API endpoints to the preview server for royalty report generation. Follow the existing pattern (parseRoute, sendJson, readBody).

**Endpoint 1: GET /api/customers/:id/royalty?start=YYYY-MM-DD&end=YYYY-MM-DD**
- Loads the customer account using getCustomer(id) from scripts/customers/store.ts.
- Loads all orders using loadOrders() from scripts/orders/order-store.ts.
- Calls generateRoyaltyReport({ customer, orders: store.orders, periodStart, periodEnd }).
- Returns the full RoyaltyReport as JSON: `{ ok: true, data: royaltyReport }`.
- If customer not found: 404 `{ ok: false, error: "Customer not found" }`.
- If start or end query params missing: 400 `{ ok: false, error: "start and end query parameters required (YYYY-MM-DD)" }`.
- Convert YYYY-MM-DD params to ISO-8601 range: start = `${start}T00:00:00.000Z`, end = `${end}T23:59:59.999Z`.

**Endpoint 2: GET /api/customers/:id/royalty/pdf?start=YYYY-MM-DD&end=YYYY-MM-DD**
- Same parameter validation as Endpoint 1.
- Generates the royalty report (same as above).
- Calls generateRoyaltyStatement(royaltyReport, customer) from the statement generator (scripts/customers/royalty-statement.ts — will be created in Plan 02).
- Returns the PDF buffer with content-type application/pdf and disposition `inline; filename="ROYALTY-{customerName}-{start}-to-{end}.pdf"`.
