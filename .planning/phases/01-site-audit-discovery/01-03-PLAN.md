## WIX MCP API Tools
- **mcp__MCP_DOCKER__CallWixSiteAPI** — Query checkout config, shipping, payment methods, store policies
- **mcp__MCP_DOCKER__SearchWixRESTDocumentation** — Find checkout/cart/ecommerce API endpoints

- **mcp__MCP_DOCKER__ReadFullDocsMethodSchema** — Fallback schema access

## Playwright Browser Tools (CRITICAL for this plan)
- **mcp__MCP_DOCKER__browser_navigate** — Navigate through the entire site
- **mcp__MCP_DOCKER__browser_snapshot** — Accessibility tree capture (reveals: heading hierarchy, ARIA labels, form labels, link text, alt text, tab order)
- **mcp__MCP_DOCKER__browser_take_screenshot** — Visual evidence at every viewport size
- **mcp__MCP_DOCKER__browser_click** — Test buttons, links, navigation, add-to-cart
- **mcp__MCP_DOCKER__browser_hover** — Test hover states, dropdowns, tooltips
- **mcp__MCP_DOCKER__browser_resize** — CRITICAL: Test mobile (375x812), tablet (768x1024), desktop (1440x900) viewports
- **mcp__MCP_DOCKER__browser_evaluate** — Run JS: check viewport-dependent behavior, measure element sizes, count tap targets, inspect CSS
- **mcp__MCP_DOCKER__browser_run_code** — Run Playwright snippets for complex multi-step inspections
- **mcp__MCP_DOCKER__browser_console_messages** — Catch JavaScript errors across all pages
- **mcp__MCP_DOCKER__browser_network_requests** — Measure page load performance, check for slow/failed requests
- **mcp__MCP_DOCKER__browser_fill_form** — Test search functionality if available
- **mcp__MCP_DOCKER__browser_type** — Type into search bars, forms
- **mcp__MCP_DOCKER__browser_press_key** — Test keyboard navigation
- **mcp__MCP_DOCKER__browser_wait_for** — Wait for dynamic content to load

## Fetch Tool
- **mcp__MCP_DOCKER__fetch** — Fetch pages for raw HTML analysis

<task type="auto">
  <name>Task 1: Mobile viewport testing and responsive audit</name>
  <files>.planning/phases/01-site-audit-discovery/UX-ISSUES.md</files>
  <action>
    **Mobile experience audit (50% of traffic per PROJECT.md):**

    1. **Mobile viewport (375x812 — iPhone):**
       - Use browser_resize to set viewport to 375x812
       - Use browser_navigate to homepage
       - Use browser_snapshot to capture mobile DOM structure
       - Use browser_take_screenshot for visual evidence
       - Check: Does navigation collapse to hamburger? Is it accessible? Can you open/close it?
       - Use browser_click to open mobile menu, then browser_snapshot to see mobile nav options
       - Use browser_evaluate to measure: tap target sizes (should be ≥44x44px), text readability, content width (any horizontal scroll?)

    2. **Mobile navigation flow:**
       - From mobile homepage, navigate to shop page via mobile menu
       - browser_snapshot the product listing on mobile — how many products visible? Is there filtering?
       - Navigate to a product detail page on mobile
       - browser_snapshot: Is the add-to-cart button visible without scrolling? Can you select variants on mobile?
       - Take screenshots at each step

    3. **Mobile client landing pages:**
       - Visit each client landing page at mobile viewport
       - browser_snapshot and screenshot each
       - Assess: Are they usable on mobile? Do products display properly? Is navigation clear?

    4. **Tablet viewport (768x1024 — iPad):**
       - Use browser_resize to 768x1024
       - Navigate to homepage, shop page, and one product page
       - browser_snapshot and screenshot each — check for awkward layouts, wasted space, broken grids

    5. **Desktop viewport (1440x900):**
       - Use browser_resize to 1440x900
       - Quick verification that desktop experience is baseline functional
       - browser_snapshot and screenshot homepage

    6. **Cross-viewport comparison:**
       - Document what breaks or degrades at each viewport size
       - Identify elements that are invisible/inaccessible on mobile but present on desktop
       - Note any layout shifts, overflow issues, or touch target problems

    Begin writing UX-ISSUES.md with:
    - **Mobile Concerns** section with specific findings at each viewport, screenshots as evidence
  </action>
  <verify>
    - All three viewport sizes tested (375, 768, 1440)
    - Mobile navigation tested (open, use, close)
    - Mobile product browsing tested
    - Client landing pages tested on mobile
    - Screenshots captured at each viewport size
    - Specific issues documented with viewport and evidence
  </verify>
  <done>Mobile/responsive audit complete with specific issues documented at each viewport size.</done>

<task type="auto">
  <name>Task 2: Navigation flow testing, checkout audit, and UX synthesis</name>
  <files>.planning/phases/01-site-audit-discovery/UX-ISSUES.md, .planning/phases/01-site-audit-discovery/AUDIT-SUMMARY.md</files>
  <action>
    **Part A: Navigation and discovery UX testing**

    1. **User journey testing (reset to desktop 1440x900):**
       - Use browser_resize to 1440x900
       - Starting from homepage, attempt to find a specific product type (e.g., t-shirts) — count clicks required
       - Test the search functionality: use browser_snapshot to find search input, browser_type to search, assess results
       - Test category navigation: click through each category, assess product counts, filtering options
       - Document: How many clicks from homepage to product? Is search functional? Are filters useful?

    2. **Accessibility snapshot analysis:**
       - Use browser_snapshot on homepage, shop page, and a product page
       - Analyze the accessibility tree for: heading hierarchy (h1/h2/h3 order), link text quality, image alt text, form labels, ARIA roles
       - Use browser_press_key (Tab) to test keyboard navigation on key pages
       - Document accessibility issues

    3. **Console and network audit:**
       - Navigate to 5+ key pages, use browser_console_messages (onlyErrors: true) on each
       - Use browser_network_requests on homepage and shop page — check for: failed requests, slow-loading resources, excessive image sizes
       - Document any JavaScript errors and performance concerns

    **Part B: Checkout and conversion audit**

    4. **WIX API checkout data:**
       - Use mcp__MCP_DOCKER__SearchWixRESTDocumentation to find APIs for: checkout settings, shipping rules, payment methods, cart configuration, store policies
       - Use mcp__MCP_DOCKER__ReadFullDocsArticle for schemas, then mcp__MCP_DOCKER__CallWixSiteAPI to query:
         a. Checkout flow configuration (guest checkout available?)
         b. Shipping options and rules
         c. Payment methods enabled
         d. Discount/coupon settings
         e. Store policies (return, shipping, privacy)

    5. **Live checkout flow inspection:**
       - Navigate to a product page, use browser_click to add a product to cart
       - Follow the cart → checkout flow as far as possible without completing a purchase
       - browser_snapshot and screenshot each step of the checkout flow
       - Count steps from add-to-cart to order placement
       - Check: Is guest checkout available? What payment options show? Are shipping costs visible early? Trust signals present?
       - browser_evaluate to check for security indicators, SSL, policy links

    **Part C: Synthesize ALL findings**

    6. **Complete UX-ISSUES.md** with ALL sections:
       - **Critical Issues** (likely conversion killers from all testing — fix first)
       - **Navigation Issues** (feeds Phase 2 — from flow testing, accessibility, search)
       - **Mobile Concerns** (feeds Phase 3 — from Task 1 mobile testing)
       - **Checkout & Conversion Issues** (feeds Phase 4 — from checkout flow + API data)
       - **Client Experience Issues** (multi-client landing page problems from all plans)
       - **Performance & Technical Issues** (console errors, slow loads, failed requests)
       - **Accessibility Issues** (heading hierarchy, alt text, keyboard nav, ARIA)
       - **Quick Wins** (easy fixes with high impact)

       Each issue must have: description, severity (critical/high/medium/low), target phase, and specific evidence (screenshot reference, API data, browser finding).

    7. **Write AUDIT-SUMMARY.md** — the executive summary:
       - **Store Snapshot** (key numbers: pages, products, categories, client pages, installed apps)
       - **Top 5 Conversion Killers** (the most impactful issues, ranked, with evidence)
       - **Phase 2 Priorities** (navigation/discovery issues to address first)
       - **Phase 3 Priorities** (mobile issues from actual viewport testing)
       - **Phase 4 Priorities** (checkout issues from actual flow testing)
       - **Architectural Observations** (multi-client setup, catalog org, store health, technical state)
       - **Recommendations** (any changes to roadmap suggested by findings — should phase order change? Are new phases needed?)

       Be brutally honest per CONTEXT.md. Readable in 2 minutes. No sugarcoating.
