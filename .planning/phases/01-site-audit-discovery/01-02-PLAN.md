<task type="auto">
  <name>Task 1: Query complete product catalog via WIX API</name>
  <files>.planning/phases/01-site-audit-discovery/PRODUCT-CATALOG.md</files>
  <action>
    **WIX API product data extraction:**
    1. Get site ID from 01-01-SUMMARY.md or SITE-STRUCTURE.md
    2. Use mcp__MCP_DOCKER__SearchWixRESTDocumentation to find APIs for:
       - Querying/listing all products (Stores Catalog V3 API)
       - Querying product categories/collections
       - Getting product variants and options
    3. Use mcp__MCP_DOCKER__ReadFullDocsArticle to get exact API schemas
    4. Use mcp__MCP_DOCKER__CallWixSiteAPI to:
       - List ALL products (paginate if needed — expect 25-100 per PROJECT.md)
       - List ALL product categories/collections
       - For each product: get full details including variants, options, images, descriptions, pricing, stock status, visibility
    5. For each product, assess from API data:
       - Image count and types (mockup vs blank — per PROJECT.md, store uses mockup images)
       - Description presence and length
       - Variant structure (colors, sizes) and consistency across products
       - Pricing (set? range? consistent?)
       - Visibility status (published/draft/hidden)
       - Category/collection assignments
    6. For categories: map hierarchy, count products per category, identify empty or near-empty categories

    Begin writing PRODUCT-CATALOG.md with:
    - **Catalog Overview** (total products, categories, price range, variant patterns)
    - **Category Structure** (hierarchy, product counts, empty categories)
    - **Product Inventory** (table: name, category, variants count, images count, has description, price range, visibility)
  </action>
  <verify>
    - All products queried from API
    - All categories/collections mapped
    - Product inventory table is complete
  </verify>
  <done>Complete API-based product data extracted and cataloged.</done>
</task>

<task type="auto">
  <name>Task 2: Browse live product pages and assess customer-facing experience</name>
  <files>.planning/phases/01-site-audit-discovery/PRODUCT-CATALOG.md</files>
  <action>
    **Live browser inspection of product experience:**

    1. **Shop/catalog page inspection:**
       - Use browser_navigate to go to the main shop/product listing page
       - Use browser_snapshot to capture the product grid/list structure
       - Use browser_take_screenshot for visual evidence of the catalog layout
       - Use browser_evaluate to count visible products, check filtering/sorting options, assess layout
       - Check: Are there filters? Sort options? Pagination? How many products show per page?

    2. **Category pages:**
       - Navigate to each product category page found in Task 1
       - Use browser_snapshot to assess: product count displayed, filtering available, layout consistency
       - Take screenshots of key category pages
       - Note any empty categories, broken category pages, or inconsistent layouts

    3. **Product detail pages (sample 5-8 representative products):**
       - Navigate to a mix of products: some with many variants, some simple, some from different categories
       - For each, use browser_snapshot to capture:
         - Image gallery (how many images, can they zoom, are they high quality?)
         - Product description rendering (how it displays, formatting, completeness)
         - Variant selector (color/size dropdowns, swatches, clear labeling?)
         - Price display (visible, clear, includes any sale pricing?)
         - Add-to-cart button (prominent? above the fold?)
         - Related/recommended products section (present?)
       - Use browser_take_screenshot on each product page
       - Use browser_click to test variant selection (does price update? do images change?)
       - Use browser_console_messages to check for errors on product pages

    4. **Cross-reference with client landing pages:**
       - Using SITE-STRUCTURE.md client page data, visit client landing pages
       - Check which products appear on each client page
       - Use browser_evaluate to extract product names/links from each client page
       - Document the client-product mapping

    Complete PRODUCT-CATALOG.md by adding:
    - **Product Quality Assessment** (with visual evidence — products with missing/low-quality images, empty descriptions, broken variants, pricing issues)
    - **Product Page UX** (image galleries, variant selectors, pricing display, add-to-cart prominence, related products)
    - **Client-Product Mapping** (which products curated for which client pages, from live browser data)
    - **Catalog Issues** (brutally honest: orphan products, inconsistent data, missing info, poor presentation, broken elements)
    - **Screenshots Index** (list of product/category screenshots taken)
  </action>
  <verify>
    - Main shop page has been browsed and screenshotted
    - Category pages have been inspected
    - 5-8 product detail pages have been individually browsed, snapshotted, and assessed
    - Variant selection has been tested on at least 2 products
    - Client-product mapping is documented from live browsing
    - PRODUCT-CATALOG.md contains all sections: Catalog Overview, Category Structure, Product Inventory, Product Quality Assessment, Product Page UX, Client-Product Mapping, Catalog Issues, Screenshots Index
  </verify>
  <done>Complete product catalog audit combining API data with live browser inspection. Every product inventoried, category structure mapped, product page UX assessed from real browsing, quality issues documented with visual evidence.</done>
</task>
