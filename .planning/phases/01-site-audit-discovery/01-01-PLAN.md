<task type="auto">
  <name>Task 2: Browse live site with Playwright and map navigation and client pages</name>
  <files>.planning/phases/01-site-audit-discovery/SITE-STRUCTURE.md</files>
  <action>
    **Live site browser inspection using Playwright:**

    1. **Homepage inspection:**
       - Use browser_navigate to go to https://hotboxclothing.shop
       - Use browser_snapshot to capture the full accessibility tree (reveals all nav elements, links, headings, structure)
       - Use browser_take_screenshot with fullPage: true to capture full homepage visual
       - Use browser_console_messages to check for any JS errors on load
       - Use browser_evaluate to run JS that extracts: all links on the page, all navigation menus, header/footer structure

    2. **Navigation mapping:**
       - From the snapshot, identify all menu items and navigation elements
       - Use browser_hover on each top-level menu to reveal dropdown/submenu behavior
       - Use browser_click to follow each navigation link, then browser_snapshot each destination page
       - Map the complete navigation tree: what's in the header, footer, sidebar, mobile menu
       - Record which links work, which are dead, which lead to unexpected pages

    3. **Client landing pages deep dive:**
       - From the page inventory (Task 1) and navigation, identify ALL client-specific landing pages
       - Use browser_navigate to visit each client landing page
       - Use browser_snapshot on each to capture: page layout, product listings, navigation back to main site
       - Use browser_take_screenshot on each for visual evidence
       - For each client page: record the client name, URL, product count visible, navigation options, overall state

    4. **Site-wide link audit:**
       - Use browser_evaluate to run JS that collects all internal links on each key page visited
       - Cross-reference with the API page inventory — identify orphan pages (exist in API but no navigation path) and dead links (navigation points to nonexistent pages)

    Complete SITE-STRUCTURE.md by adding:
    - **Navigation Hierarchy** (tree view of all menus, submenus, and their targets — from live browser inspection)
    - **Client Landing Pages** (dedicated section: each client page with purpose, products, screenshot reference, and current state assessment)
    - **Structural Observations** (orphan pages, dead links, navigation gaps, console errors — brutally honest per CONTEXT.md)
    - **Screenshots Index** (list of screenshots taken with descriptions)
  </action>
  <verify>
    - Navigation hierarchy is mapped from live browser inspection (not just API data)
    - Every client landing page has been visited and documented
    - Screenshots have been captured for homepage, navigation states, and each client page
    - Console errors (if any) are documented
    - Dead links and orphan pages are identified
    - SITE-STRUCTURE.md contains all sections: Site Overview, Page Inventory, Navigation Hierarchy, Client Landing Pages, Structural Observations, Screenshots Index
  </verify>
  <done>Complete site structure document combining WIX API data with live browser inspection. Every page inventoried, navigation mapped from actual browsing, client pages individually assessed with screenshots, structural issues identified with evidence.</done>
</task>
