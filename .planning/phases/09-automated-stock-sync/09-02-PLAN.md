**Step 1: Install nodemailer**

Run `npm install nodemailer` and `npm install -D @types/nodemailer`.

Nodemailer is the standard Node.js email library -- zero dependencies, works with any SMTP provider (Gmail, Outlook, SendGrid, custom SMTP). No external service account needed beyond an email account with SMTP access.

**Step 2: Add notification types to scripts/sync/types.ts**

```typescript
/** Email notification configuration */
interface NotificationConfig {
  /** Whether email notifications are enabled */
  enabled: boolean;
  /** SMTP connection settings */
  smtp: {
    host: string;       // e.g., "smtp.gmail.com"
    port: number;       // e.g., 587
    secure: boolean;    // true for 465, false for 587/25
    user: string;       // SMTP username (email address)
    pass: string;       // SMTP password or app password
  };
  /** Recipient email address (store owner) */
  to: string;
  /** Sender email address (can be same as smtp.user) */
  from: string;
}
```

Add `notification` field to `SyncConfig`:
```typescript
interface SyncConfig {
  dataDir: string;
  notification: NotificationConfig;
}
```

Update `getDefaultSyncConfig()` to include notification defaults with `enabled: false`.

**Step 3: Create scripts/sync/notifications.ts**

Functions:

`buildSyncEmailBody(results: SyncResult[], alerts: StockAlert[]): string`

Build a plain-text email body summarizing what happened. Structure:

```
HotBox Stock Sync Report
========================
Date: {ISO timestamp}

STOCK CHANGES DETECTED
---------------------
{for each alert, grouped by product}:
  PC61 Port & Company Essential Tee:
    ⚠ OUT OF STOCK: Black 2XL (was 5, now 0)
    🟢 BACK IN STOCK: White M (was 0, now 45)

WIX STORE UPDATES
-----------------
{for each sync result with changes}:
  PC61 Port & Company Essential Tee:
    - 2 variants hidden (out of stock at SanMar)
    - 1 variant restored (back in stock)
    - 57 variants unchanged

{for unmapped products}:
  K500: Not linked to a WIX product (skipped)

SUMMARY
-------
Products checked: 3
WIX updates made: 2 products, 3 variant changes
No action needed: 1 product (no changes)

---
Automated by HotBox Stock Sync
```

If no changes at all (no alerts, no sync updates), don't send email -- return null.

`sendSyncNotification(subject: string, body: string, config: NotificationConfig): Promise<void>`

Use nodemailer to send the email:
1. Create transport with `nodemailer.createTransport({ host, port, secure, auth: { user, pass } })`
2. Send with `transport.sendMail({ from, to, subject, text: body })`
3. Log success/failure. Do NOT throw on email failure -- log error and continue (email is best-effort, not critical).

`notifySyncResults(results: SyncResult[], alerts: StockAlert[], config: SyncConfig): Promise<void>`

Orchestrator function:
1. Check if notifications are enabled (`config.notification.enabled`). If not, return silently.
2. Build email body. If null (no changes), return.
3. Build subject line: `"[HotBox] Stock Sync: {N} changes detected"` or `"[HotBox] Stock Sync: No changes"`.
4. Send email via `sendSyncNotification`.

Export all from index.ts.

**Step 1: Create scripts/sync/sync-poller.ts**

The sync poller wraps the monitor poller and adds WIX sync + notifications.

`syncOnce(monitorConfig: MonitorConfig, syncConfig: SyncConfig): Promise<void>`

1. Call `pollOnce(monitorConfig)` to get current snapshots and trigger alert detection.
2. Read the latest alert log to get alerts from this poll cycle (use `getRecentAlerts` from monitor, filter by timestamp matching this poll cycle -- or simpler: use the `onAlerts` callback from `pollOnce` to capture alerts directly).
3. Call `syncAllProducts(snapshots, monitorConfig, syncConfig)` to update WIX variants.
4. Call `notifySyncResults(results, alerts, syncConfig)` to email the owner.
5. Log a summary to console using `buildSyncSummary`.

Actually, better approach: use the `onAlerts` callback in `pollOnce`:
```typescript
let pollAlerts: StockAlert[] = [];
const snapshots = await pollOnce(monitorConfig, (alerts) => {
  pollAlerts = alerts;
});
```

`startSyncLoop(monitorConfig: MonitorConfig, syncConfig: SyncConfig): Promise<void>`

Like `startPolling` from monitor/poller.ts but runs `syncOnce` instead of `pollOnce`:
1. Run `syncOnce` immediately.
2. Set up interval at `monitorConfig.pollIntervalMinutes`.
3. Handle SIGINT for graceful shutdown.

**Step 2: Create scripts/sync/manage.ts**

CLI for managing stock sync. Uses `import.meta.url` guard pattern from monitor/manage.ts.

Subcommands:

- `link <style> <wixProductId> [name]` -- Add product mapping. If name not provided, use style as name. Example: `sync link PC61 abc123 "Port & Company Essential Tee"`
- `unlink <style>` -- Remove product mapping.
- `list` -- Show all product mappings (style → WIX product ID).
- `scan` -- Auto-discover mappings: call `listAllProducts()` from wix-api, match WIX product SKUs against tracked styles. For each match found, offer to create mapping. This is the easy-setup path.
- `sync` -- Run one sync cycle (poll + sync + notify).
- `start` -- Start continuous sync loop.
- `notify-test` -- Send a test email to verify SMTP config works.
- `config` -- Show current sync config (notification settings, data dir).
- `help` -- Show usage.

For `scan` subcommand logic:
1. Call `listAllProducts()` to get all WIX products with variants.
2. Call `loadTrackedProducts(monitorConfig)` to get monitored SanMar styles.
3. For each WIX product, check if any variant SKU starts with a tracked style number (SKU format is `{style}-{catalogColor}-{size}`).
4. For matches, auto-create ProductMapping entries.
5. Report: "Found N WIX products matching tracked styles: PC61 → abc123, K420 → def456"

**Step 4: Load notification config from environment**

In `manage.ts`, load SMTP config from environment variables to avoid hardcoding credentials:
- `SMTP_HOST` (default: "smtp.gmail.com")
- `SMTP_PORT` (default: 587)
- `SMTP_USER` (required if notifications enabled)
- `SMTP_PASS` (required if notifications enabled)
- `NOTIFY_TO` (recipient email, defaults to SMTP_USER)
- `NOTIFY_FROM` (sender email, defaults to SMTP_USER)
- `NOTIFY_ENABLED` (default: "false")

Build SyncConfig from env vars + defaults. If SMTP_USER is not set and notifications are requested, log a warning and disable notifications.
