**Step 1: Add queryProducts to wix-api.ts**

Add a `queryProducts` function to `scripts/pipeline/wix-api.ts` that calls `POST /stores/v1/products/query`. This is the WIX V1 query endpoint.

Request body format:
```json
{
  "query": {
    "filter": "{\"name\": {\"$contains\": \"searchTerm\"}}",
    "paging": { "limit": 100, "offset": 0 }
  },
  "includeVariants": true
}
```

The `filter` field is a JSON **string** (WIX V1 quirk -- the filter object is stringified, not nested).

Function signature:
```typescript
export async function queryProducts(filter?: Record<string, unknown>, limit?: number): Promise<WixProduct[]>
```

If no filter provided, return all products (useful for building initial map). Support pagination by making multiple requests if `totalResults > limit`.

Also add a `listAllProducts` convenience function that paginates through all products:
```typescript
export async function listAllProducts(): Promise<WixProduct[]>
```

Export both from `scripts/pipeline/index.ts`.

**Function: syncProductStock**

```typescript
async function syncProductStock(
  style: string,
  snapshot: InventorySnapshot,
  config: MonitorConfig,
  syncConfig: SyncConfig,
): Promise<SyncResult | null>
```

Logic:
1. Look up WIX product ID from product map using `findMapping(style, syncConfig)`. If no mapping exists, return null (product not linked to WIX).
2. Call `getProduct(wixProductId)` to get current WIX variant state.
3. For each WIX variant:
   a. Parse the SKU to extract catalogColor and size: SKU format is `{style}-{catalogColor}-{size}`. Split on `-` but note that catalogColor may contain `-` (unlikely for SanMar but be safe -- split style prefix, then last segment is size, middle is catalogColor).
   b. Actually, more reliable: match by variant `choices` -- Color is displayColor and Size is size. Find matching SKU in snapshot by iterating snapshot.skus and comparing color+size. The snapshot uses catalogColor, but the WIX variant uses displayColor. **Key insight:** The SKU field in WIX contains catalogColor. Use the SKU format `{style}-{catalogColor}-{size}` to extract catalogColor+size and match against `snapshot.skus` by color+size.
   c. Parse SKU: remove the style prefix + first dash, then the last segment after the final dash is size, everything in between is catalogColor. Example: `PC61-Ath. Maroon-2XL` → catalogColor="Ath. Maroon", size="2XL".
   d. Find the matching SkuSnapshot by color === catalogColor and size === size.
   e. Classify stock level using `classifyStockLevel(totalQty, config)`.
   f. Determine desired visibility: `out-of-stock` → visible: false; everything else → visible: true.
   g. Compare desired visibility against current `variant.variant.visible`.
   h. If different, add to updates list.
4. If updates list is not empty, call `updateProductVariants(wixProductId, updates)` with the variant updates.
5. Build and return SyncResult.

**Important:** Build variant updates as `WixVariantUpdate` objects matching WIX V1 format. Each update needs `choices` (the Color/Size dict from the existing variant), plus `price`, `cost`, `weight`, `sku` (carry over from existing variant data), and the new `visible` value. This ensures we only change visibility, not pricing or other fields.
