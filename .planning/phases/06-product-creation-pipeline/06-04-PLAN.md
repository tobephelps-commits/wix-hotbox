<objective>
Build a local web preview server that displays SanMar product data as visual cards for color/size curation before creating WIX drafts.

Purpose: The CONTEXT.md vision describes "a local web preview page with product cards -- swatch, image, name, checkbox -- browse, pick, create." This is the core UX that makes the pipeline useful: seeing 40+ colors visually and picking the ones to sell, instead of guessing from a text list. The preview page is a local tool, not a deployed app.

Output: A local HTTP server that serves a self-contained HTML page with product cards, color swatches, size grid, pricing info, and a "Create Draft" button that posts the curated selection back to the server.
</objective>

<task type="auto">
  <name>Task 1: Build local preview HTTP server</name>
  <files>scripts/pipeline/preview-server.ts</files>
  <action>
Create a lightweight HTTP server using Node.js built-in `http` module (NO external dependencies -- keep the dependency footprint minimal).

**Server endpoints:**

1. `GET /` → Serve the preview.html file
2. `GET /api/product/:style` → Fetch SanMar data and return ProductPreview JSON
3. `POST /api/create` → Accept CuratedProduct JSON, create WIX draft, return CreationResult

**Server flow:**

1. Parse command line: `npx tsx scripts/pipeline/preview-server.ts [STYLE]`
   - If STYLE provided: pre-fetch data and open preview with that style loaded
   - If no STYLE: show search input on the preview page

2. Start server on `localhost:3456` (or next available port)
3. Log: `Preview server running at http://localhost:3456`
4. Optionally auto-open browser (try `open` / `start` / `xdg-open` based on platform, but don't fail if it doesn't work)

**GET /api/product/:style handler:**
- Call `fetchProductData(style)` from fetch-product.ts
- Return JSON: `{ ok: true, data: productData.preview }` on success
- Return JSON: `{ ok: false, error: "message" }` on failure
- Include CORS headers for local development

**POST /api/create handler:**
- Accept JSON body: CuratedProduct
- Call `createWixProduct(curated, productData)` from create-product.ts
- Need to re-fetch productData here (or cache from the GET call -- cache by style for the session)
- Return JSON: `{ ok: true, result: creationResult }` on success
- Return JSON: `{ ok: false, error: "message" }` on failure

**Cache:** Keep a simple in-memory Map<string, ProductData> so the fetch from GET /api/product is reused when POST /api/create fires for the same style. Clear on new style fetch.

**Add npm script to package.json:**
```json
"preview": "npx tsx scripts/pipeline/preview-server.ts"
```

Import from `./fetch-product.js` and `./create-product.js`.
Use `node:http`, `node:fs`, `node:path`, `node:url` -- all built-in.
  </action>
  <verify>npx tsc --noEmit passes. Running `npm run preview` starts server on localhost:3456.</verify>
  <done>Preview server starts, serves HTML, handles /api/product/:style and /api/create endpoints</done>

```
│  COLORS (12 of 42 in stock)  [Select All] [Clear]  │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐            │
│  │ [img]    │ │ [img]    │ │ [img]    │  ...       │
│  │ ■ Black  │ │ ■ Navy   │ │ ■ White  │            │

```

**Color cards:**
- Each card shows: product front image (or swatch if no front image), color swatch square, display color name, stock status indicator
- Checkbox for selection (checked by default for in-stock colors)
- Cards arranged in a responsive CSS grid (auto-fill, min 150px per card)
- Out-of-stock colors shown with reduced opacity, unchecked by default
- Clicking the image or name also toggles the checkbox

**Size grid:**
- Horizontal row of size checkboxes in SanMar order (XS → 6XL)
- All sizes checked by default
- Show size labels clearly

**Pricing section:**
- Display wholesale price (what HotBox pays) and suggested retail (SanMar's recommendation)
- Editable retail price input (defaults to suggested retail)
- Clear label: "This is the price customers will see"

**Create button:**
- Posts CuratedProduct JSON to /api/create
- Disables during creation, shows spinner/progress
- On success: shows product URL as clickable link + "Created! Review your draft in WIX."
- On failure: shows error message in red

**Status bar:**
- Shows current state: "Enter a style number", "Fetching...", "Ready to curate", "Creating...", "Done!"
- Error messages appear here in red

**Styling:**
- Clean, minimal CSS inline in the HTML file (no external stylesheets)
- Dark header bar, white content area
- Professional but simple -- this is an internal tool, not a customer-facing page
- Responsive enough to be usable but not pixel-perfect

**JavaScript (inline, vanilla):**
- Fetch handler: GET /api/product/{style} on form submit
- Populate cards and sizes from response
- Select All / Clear All buttons for colors and sizes
- Variant count calculation (selected colors × selected sizes)
- Create handler: POST /api/create with CuratedProduct body
- All state managed in simple variables (no framework needed)

**No external dependencies.** No React, no Tailwind CDN, no Google Fonts. Pure HTML/CSS/JS in a single file. This is a local developer tool.
