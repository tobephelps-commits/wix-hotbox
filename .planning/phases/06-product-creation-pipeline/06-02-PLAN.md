  <files>scripts/pipeline/wix-api.ts</files>
  <action>
Create a WIX API service module that wraps fetch calls to the WIX Catalog V1 REST API. The site is Catalog V1 -- use V1 endpoints exclusively.

**Site ID:** `c744cbdb-46f8-4c66-ac76-eb31bd0d52c1` (from Phase 1 audit). Store as a constant `WIX_SITE_ID`.

**Environment:** The pipeline scripts run locally via `npx tsx`. WIX API calls need an API key. Add `WIX_API_KEY` to the .env.example file. The API key is passed as Bearer token in the Authorization header.

**Functions to create:**

1. `createProduct(payload: WixCreateProductRequest): Promise<WixProduct>`
   - POST to `https://www.wixapis.com/stores/v1/products`
   - Headers: `Content-Type: application/json`, `Authorization: Bearer ${WIX_API_KEY}`
   - Body: the product payload
   - Returns: the created product object (includes `id` needed for subsequent calls)
   - Throw descriptive error on non-200 response (include response body in error)

2. `addProductMedia(productId: string, media: WixMediaItem[]): Promise<void>`
   - POST to `https://www.wixapis.com/stores/v1/products/${productId}/media`
   - Body: `{ media: media }` -- array of media items with url and optional choice assignment
   - V1 accepts external URLs directly -- no need to upload to WIX Media Manager first
   - Log count of media items added

3. `updateProductVariants(productId: string, variants: WixVariantUpdate[]): Promise<WixVariant[]>`
   - PATCH to `https://www.wixapis.com/stores/v1/products/${productId}/variants`
   - Body: `{ variants: variants }` -- array of variant updates with choices, price, cost, weight, sku, visible
   - Returns: updated variants array (includes variant IDs)
   - Note: V1 accepts choices as `Record<string, string>` (e.g., `{ "Color": "Black", "Size": "M" }`)

4. `getProduct(productId: string): Promise<WixProduct>`
   - GET to `https://www.wixapis.com/stores/v1/products/${productId}?includeVariants=true`
   - For verification after creation
   - Returns full product with variants

5. `addProductToCollection(productId: string, collectionId: string): Promise<void>`
   - POST to `https://www.wixapis.com/stores/v1/collections/${collectionId}/productIds`
   - Body: `{ productIds: [productId] }`
   - For optional collection assignment after creation

**WIX API response types** (define in this file since they're WIX-specific):
```
WixProduct {
  id: string
  name: string
  visible: boolean
  productPageUrl: { base: string; path: string }
  variants: WixVariant[]
  // ... other fields from V1 response
}

WixVariant {
  id: string
  choices: Record<string, string>
  variant: {
    priceData: { price: number; currency: string }
    sku: string
    weight: number
    visible: boolean
  }
  stock: {
    trackQuantity: boolean
    quantity: number
    inStock: boolean
  }
}
```

**Error handling:**
- Check response.ok on every call
- On failure, read response body and throw with: HTTP status, endpoint URL, and WIX error message
- Common V1 errors to handle:
  - 401: Invalid or missing API key → suggest checking WIX_API_KEY in .env
  - 404: Product not found → include productId in error
  - 400: Invalid request → include full WIX error details

**Module pattern:** Export individual functions (not a class). Load WIX_API_KEY from process.env at module level using dotenv. Validate WIX_API_KEY exists on first call (throw with actionable message if missing).

Import types from `./types.js` for WixCreateProductRequest, WixMediaItem, WixVariantUpdate.
