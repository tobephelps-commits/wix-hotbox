  <action>
Wire together any remaining integration issues between the preview UI and pipeline backend. This task addresses the seams between Plans 03 and 04.

**Integration checklist:**

1. **Server↔HTML data contract:** Ensure the preview.html JavaScript expects the exact JSON shape that /api/product/:style returns. The server returns `ProductPreview` -- verify the HTML parses `availableColors[].swatchUrl`, `availableColors[].frontImageUrl`, `availableColors[].catalogColor`, `availableColors[].displayColor`, `availableColors[].inStock`, `availableSizes[]`, `pricing.wholesalePrice`, `pricing.suggestedRetail`, `pricing.saleActive`.

2. **Create request contract:** Ensure the HTML builds a CuratedProduct JSON body that matches the TypeScript interface exactly. Fields: `style`, `brandName`, `productTitle`, `description`, `selectedColors[]` (each with `catalogColor` and `displayColor`), `selectedSizes[]`, `basePrice`, `wholesaleCost`.

3. **Server product data caching:** Verify the server caches ProductData from the GET /api/product/:style call and reuses it in the POST /api/create handler (the create flow needs the full ProductData, not just the preview).

4. **Error propagation:** Ensure SanMar API errors and WIX API errors surface in the preview UI status bar with actionable messages. Test: invalid style number → "Style 'XXXXX' not found", missing WIX_API_KEY → "WIX_API_KEY not set in .env".

5. **Success feedback:** After successful creation, the preview should show the WIX product URL as a clickable link and a clear "Draft created!" message.

6. **Edge cases to handle:**
   - Style with 0 in-stock colors → show warning "No colors currently in stock"
   - Style with only 1 color → still show card grid, pre-select it
   - User selects 0 colors and clicks Create → show validation error
   - User selects 0 sizes and clicks Create → show validation error
   - Network error during create → show retry guidance

Fix any type mismatches, missing fields, or broken data flow discovered during integration.
