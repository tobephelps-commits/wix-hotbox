<task type="auto">
  <name>Task 1: Set up SQLite database with better-sqlite3 and migration system</name>
  <files>src/db/index.ts, src/db/schema.ts, src/db/migrations/001-initial.sql, package.json</files>
  <action>
  1. Install dependencies:
     - `better-sqlite3` (synchronous SQLite driver, fast on ARM64)
     - `@types/better-sqlite3` (dev dependency)

  2. Create src/db/schema.ts:
     - Export SQL string constants for table creation (used by migration 001)
     - Initial tables for the migration tracking system only:
       - `migrations` table: id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE, applied_at TEXT NOT NULL DEFAULT (datetime('now'))
     - Domain tables (products, orders, etc.) will be added in their respective phases
     - Export column type helpers if useful (e.g., timestamp defaults)

  3. Create src/db/migrations/001-initial.sql:
     - CREATE TABLE IF NOT EXISTS migrations (id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL UNIQUE, applied_at TEXT NOT NULL DEFAULT (datetime('now')))
     - This is the bootstrap migration — future phases add their own numbered migrations (002-products.sql, 003-orders.sql, etc.)

  4. Create src/db/index.ts:
     - Import better-sqlite3 and Config type
     - Export `createDatabase(config: Config)` function:
       - Opens SQLite database at `${config.dataDir}/hotbox.db`
       - Enables WAL mode (PRAGMA journal_mode=WAL) for better concurrent read performance
       - Enables foreign keys (PRAGMA foreign_keys=ON)
       - Sets busy timeout to 5000ms
       - Returns the Database instance
     - Export `runMigrations(db: Database)` function:
       - Reads all .sql files from src/db/migrations/ (or dist/db/migrations/ in production)
       - Sorts by filename (001-, 002-, etc.)
       - For each migration not yet in the migrations table:
         - Execute the SQL
         - Insert record into migrations table
       - Wrap in a transaction for atomicity
       - Log which migrations were applied
     - Export `closeDatabase(db: Database)` function for graceful shutdown

  5. Handle migration file resolution:
     - In development (tsx): resolve relative to src/db/migrations/
     - In production (node dist/): resolve relative to the compiled location
     - Use a simple approach: check if src/db/migrations/ exists, fall back to looking relative to __dirname
     - Alternative: copy .sql files to dist/ in build step — add a `postbuild` script in package.json: `"postbuild": "cp -r src/db/migrations dist/db/"` (use platform-appropriate copy)
     - On Windows dev, use `xcopy` or a small node script. Simplest: use a `copyfiles` approach or inline node -e script.
  </action>
  <verify>
  Run `npx tsc --noEmit` to verify TypeScript compiles.
  Write a quick test: `npx tsx -e "import { createDatabase, runMigrations } from './src/db/index.js'; const db = createDatabase({ dataDir: './data', port: 3456, host: '0.0.0.0', nodeEnv: 'development', logDir: './logs' }); runMigrations(db); console.log(db.prepare('SELECT * FROM migrations').all()); db.close();"` — should show the 001-initial migration applied.
  </verify>
  <done>
  - better-sqlite3 installed
  - Database opens at data/hotbox.db with WAL mode and foreign keys
  - Migration system tracks applied migrations
  - 001-initial.sql creates the migrations table
  - Migration files copied to dist/ during build
  </done>
</task>

<task type="auto">
  <name>Task 2: Integrate database into server lifecycle and add system info endpoint</name>
  <files>src/app.ts, src/server.ts, src/routes/index.ts</files>
  <action>
  1. Update src/server.ts:
     - Import createDatabase, runMigrations, closeDatabase from ./db/index.js
     - After loading config, create database and run migrations
     - Pass database instance to buildApp (add db parameter)
     - In shutdown handler, close database before closing app

  2. Update src/app.ts:
     - Accept Database instance as second parameter to buildApp()
     - Decorate Fastify instance with `db` using fastify.decorate('db', db)
     - Add TypeScript type augmentation for Fastify so `fastify.db` is typed:
       ```typescript
       declare module 'fastify' {
         interface FastifyInstance {
           db: import('better-sqlite3').Database;
         }
       }
       ```
     - Pass through to route plugins via Fastify's decoration (available as fastify.db in all routes)

  3. Update src/routes/index.ts:
     - Add GET /api/system endpoint returning:
       - version (from package.json)
       - uptime (process.uptime())
       - nodeVersion (process.version)
       - platform (process.platform)
       - arch (process.arch)
       - memoryUsage (process.memoryUsage().rss in MB, rounded)
       - database: { path, size in MB (from fs.statSync), migrations applied count }
     - This endpoint is useful for the Pi appliance dashboard to show system status
     - Keep the existing /api/health endpoint (lightweight for monitoring)

  4. Ensure clean startup/shutdown:
     - Server starts: load config → open db → run migrations → build app → listen
     - Server stops (SIGTERM/SIGINT): close app → close db → exit
     - Log each lifecycle step
  </action>

  </verify>
