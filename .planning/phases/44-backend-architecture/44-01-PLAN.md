<task type="auto">
  <name>Task 1: Create src/ directory structure and update TypeScript config</name>
  <files>src/server.ts, src/app.ts, src/config.ts, tsconfig.json, package.json</files>
  <action>
  1. Update tsconfig.json:
     - Change `"include"` from `["scripts/**/*.ts"]` to `["src/**/*.ts"]`
     - Keep all other settings (target ES2022, module NodeNext, outDir dist, strict true)
     - The v1.x scripts/ code stays but won't be compiled by default (it's reference for porting)

  2. Update package.json:
     - Add dependencies: `fastify` (latest v5.x), `@fastify/cors`, `@fastify/static`, `dotenv`
     - Add devDependencies: `@types/node` (if not present)
     - Add/update scripts:
       - `"build": "tsc"`
       - `"dev": "npx tsx watch src/server.ts"`
       - `"start": "node dist/server.js"`
     - Keep existing v1.x scripts (preview, monitor, sync, etc.) — they still work via tsx

  3. Create src/config.ts:
     - Export a typed `Config` interface with: port (number), host (string), nodeEnv (string), dataDir (string), logDir (string)
     - Export `loadConfig()` function that reads from process.env with defaults:
       - PORT: 3456 (matches hotbox.conf and systemd service)
       - HOST: '0.0.0.0' (LAN accessible for Phase 55)
       - NODE_ENV: 'development'
       - DATA_DIR: './data' (matches systemd ReadWritePaths)
       - LOG_DIR: './logs' (matches systemd ReadWritePaths)
     - Validate required values, throw on invalid config
     - Use dotenv/config import at top for .env file loading

  4. Create src/app.ts:
     - Export `buildApp(config: Config)` function that creates and configures a Fastify instance
     - Register @fastify/cors with origin: true (LAN access from any device)
     - Add a global error handler that logs errors and returns structured JSON responses
     - Register GET /api/health endpoint returning: { status: 'ok', version: string (from package.json), uptime: process.uptime(), timestamp: new Date().toISOString() }
     - Return the Fastify instance (don't call listen — that happens in server.ts)
     - Use Fastify's built-in logger (logger: true in production, logger: { level: 'info' } in dev)

  5. Create src/server.ts (the entry point — compiles to dist/server.js):
     - Import dotenv/config first
     - Import loadConfig from ./config.js
     - Import buildApp from ./app.js
     - Load config, build app, call app.listen({ port: config.port, host: config.host })
     - Log startup message with port and host
     - Handle SIGTERM and SIGINT for graceful shutdown (call app.close())
     - Use .js extensions in imports (NodeNext resolution)
  </action>
  <verify>
  Run `npx tsc --noEmit` to verify TypeScript compiles without errors.
  Run `npx tsx src/server.ts &` then `curl http://localhost:3456/api/health` returns JSON with status: 'ok'.
  Kill the server process after verification.
  </verify>
  <done>
  - tsconfig.json updated to compile src/
  - package.json has Fastify dependencies and new scripts
  - src/config.ts exports typed config loader
  - src/app.ts exports buildApp() with health endpoint
  - src/server.ts is the entry point with graceful shutdown
  - `npm run build` produces dist/server.js
  - Health endpoint responds at /api/health
  </done>
</task>
