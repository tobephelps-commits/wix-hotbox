  <action>
Port `scripts/orders/wix-orders-api.ts` and `scripts/orders/wix-order-sync.ts` into a single v2.0 module. The pipeline's wix-api.ts already has WIX API helpers — reuse the auth pattern (WIX_API_KEY, WIX_SITE_ID from config).

**WIX API Functions:**

`searchWixOrders(config, filter?, limit?)`:
- POST to `https://www.wixapis.com/ecom/v1/orders/search`
- Cursor-based pagination (loop until no more cursors)
- Headers: Authorization Bearer WIX_API_KEY, wix-site-id
- Return raw WIX order objects array

`getWixOrder(config, orderId)`:
- GET `https://www.wixapis.com/ecom/v1/orders/{orderId}`
- Return single raw WIX order object

`getRecentWixOrders(config, days?)`:
- Smart fetch: all unfulfilled orders + last N days (default 60)
- Deduplicate by order ID
- Sort by createdDate DESC
- This is the primary sync function — ensures no unfulfilled order is missed

**Mapping Functions:**

`mapWixStatusToOrderStatus(wixOrder)`:
- FULFILLED → 'shipped'
- PARTIALLY_FULFILLED → 'packed'
- NOT_FULFILLED + PAID → 'new'
- CANCELED → 'cancelled'
- Default → 'new'

`mapWixOrderToCreateInput(wixOrder, collectionMap?)`:
- Map WIX order fields to CreateOrderInput shape
- Customer: from billingInfo.contactDetails (firstName, lastName, email, phone)
- Addresses: handle WIX V1's addressLine (single field) — split or use as addressLine1
- Line items: extract color/size from descriptionLines array, map to OrderLineItem shape
- Monetary: parse WIX string amounts to numbers
- Collection: lookup from collectionMap if provided, default to undefined
- Set source = 'wix', set wixOrderId = wixOrder.id
- Return CreateOrderInput & { wixOrderId: string }

**Collection Resolution:**

`buildCollectionMap(config)`:
- Fetch WIX Products and Collections via REST API (same APIs used in pipeline)
- Build map: productId → collectionName
- Return Map<string, string>
- Gracefully handle API failures (return empty map — orders still sync without collection tags)

**Sync Orchestration:**

`syncWixOrders(config, db, options?)`:
- options: { days?: number, signal?: AbortSignal }
- Fetch recent WIX orders via getRecentWixOrders
- Build collection map via buildCollectionMap
- Map each WIX order via mapWixOrderToCreateInput
- Import order-service functions and call upsertWixOrder for each
- Track results: newOrders, updatedOrders, unchanged, errors[]
- Continue on individual order errors (non-blocking)
- Return SyncResult: { newOrders, updatedOrders, totalWixOrders, errors, syncedAt }

`syncWithRetry(config, db, options?)`:
- options: { maxRetries?: number, baseDelayMs?: number, ...syncOptions }
- Wrap syncWixOrders with exponential backoff (2^n * baseDelay, default 2000ms)
- Return SyncResult with retriesUsed count

Use native fetch (Node 18+). Do NOT use axios or node-fetch — the v2.0 codebase uses native fetch throughout.

Accept config parameter (from fastify.config) for WIX_API_KEY and WIX_SITE_ID rather than reading env directly — matches v2.0 patterns.
