<task type="auto">
  <name>Task 1: Create order service with CRUD + state machine</name>
  <files>src/orders/order-service.ts</files>
  <action>
Create order service that operates on the SQLite database. Accept `Database` from better-sqlite3 as constructor/parameter (same pattern as other modules using fastify.db).

Use a functional module pattern: export functions that accept `db: Database` as first parameter (matching how pipeline and logo modules work — they receive db/config at init time).

**CRUD Operations:**

`getNextOrderNumber(db)`: Query MAX(order_number) from orders table, return max + 1 or 1001 if empty.

`createOrder(db, input: CreateOrderInput)`:
- Generate UUID for id (use crypto.randomUUID())
- Get next order number
- INSERT into orders table
- INSERT each line item into order_items
- INSERT initial status into order_status_history (status: input source's initial status, typically 'new')
- Return the created OrderWithDetails
- Wrap in transaction for atomicity

`getOrder(db, id)`:
- SELECT from orders WHERE id = ?
- SELECT items from order_items WHERE order_id = ?
- SELECT history from order_status_history WHERE order_id = ? ORDER BY created_at ASC
- SELECT errors from order_errors WHERE order_id = ?
- Parse JSON addresses (billingAddress, shippingAddress)
- Return OrderWithDetails or null

`getOrderByNumber(db, orderNumber)`:
- SELECT from orders WHERE order_number = ?
- Delegate to getOrder with found id

`getOrderByWixId(db, wixOrderId)`:
- SELECT from orders WHERE wix_order_id = ?
- Delegate to getOrder with found id

`listOrders(db, filter?: OrderFilter)`:
- Build dynamic WHERE clause from filter (status, source, search)
- Search filter: LIKE match on customer_first_name, customer_last_name, customer_email, or CAST(order_number AS TEXT)
- ORDER BY updated_at DESC
- Apply LIMIT/OFFSET for pagination
- Return Order[] (without details for list performance)
- Also return totalCount for pagination

`updateOrderStatus(db, id, newStatus, note?)`:
- Load current order status
- Validate transition using isValidTransition() from types
- If invalid, throw error with message showing current → requested
- UPDATE orders SET status = newStatus, updated_at = datetime('now')
- INSERT into order_status_history
- Return updated Order

`updateOrderStatusBulk(db, ids[], newStatus, note?)`:
- Process each order individually (some may fail validation)
- Return { succeeded: string[], failed: { id: string, error: string }[] }
- NOT wrapped in single transaction — partial success is acceptable (v1.x pattern from Phase 41)

`upsertWixOrder(db, orderData: CreateOrderInput & { wixOrderId: string })`:
- Check if order with wix_order_id exists
- If exists: UPDATE order fields, REPLACE line items (delete + reinsert), but PRESERVE local status if it's more advanced than the WIX-mapped status (v1.x critical behavior — if local status is 'in-production' and WIX says 'new', keep 'in-production')
- If new: createOrder with wixOrderId set
- Return { order: OrderWithDetails, action: 'created' | 'updated' | 'unchanged' }

`deleteOrder(db, id)`:
- DELETE FROM orders WHERE id = ? (CASCADE handles items, history, errors)
- Return boolean success

`clearWixOrders(db)`:
- DELETE FROM orders WHERE source = 'wix'
- Return count of deleted orders

**Error Tracking:**

`addOrderError(db, orderId, error: { operation, message })`:
- Check for existing unresolved error with same operation
- If exists, increment retry_count
- If not, INSERT new error
- Return the error record

`resolveOrderError(db, orderId, operation)`:
- UPDATE order_errors SET resolved = 1 WHERE order_id = ? AND operation = ? AND resolved = 0

`getOrdersWithErrors(db)`:
- SELECT DISTINCT orders.* FROM orders JOIN order_errors ON ... WHERE resolved = 0
- Return Order[]

**Summary/Metrics:**

`getOrderSummary(db)`:
- SELECT status, COUNT(*) FROM orders GROUP BY status
- Count unresolved errors
- Get MAX(updated_at) for WIX orders as lastSync
- Return OrderSummary

`getOrderSummaryExtended(db)`:
- Everything from getOrderSummary plus:
- Aging orders: SELECT orders where hours-in-current-status exceeds AGING_THRESHOLDS (use julianday arithmetic)
- Attention counts: cartFillPending (status=new), stuckInProduction (in-production > 72h), awaitingShipment (packed > 24h), unresolvedErrors
- Stage metrics per active status: count, total items (SUM from order_items), total value (SUM of order totals), oldest order hours
- Return ExtendedOrderSummary (define inline or add to types)

Use prepared statements for frequently called queries (better-sqlite3 supports this natively via db.prepare()).
