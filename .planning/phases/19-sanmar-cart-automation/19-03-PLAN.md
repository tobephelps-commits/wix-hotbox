<task type="auto">
  <name>Task 1: Build cart fill CLI command</name>
  <files>scripts/orders/cart-cli.ts</files>
  <action>
Create cart-cli.ts as a standalone CLI script (following the pattern of manage.ts) with these commands:

1. **`preview` command** (default, no args):
   - Calls `getOrdersForCartFill()` to show eligible orders
   - Calls `consolidateOrders()` to show what would be added to cart
   - Displays a summary table:
     ```
     SanMar Cart Preview
     ═══════════════════
     Orders: #1001, #1003, #1005 (3 orders, 8 line items)

     Consolidated Cart (5 unique items):
       PC61  | Black    | M   | qty 3  | from orders #1001, #1003
       PC61  | Black    | L   | qty 2  | from orders #1001, #1005
       K420  | Navy     | XL  | qty 1  | from order #1005
       ...

     Skipped: 2 items (no vendor style / S&S vendor)

     Run with --fill to execute cart automation
     ```
   - Does NOT launch browser or modify anything — preview only

2. **`fill` command** (`--fill` flag):
   - Calls `fillCartForPendingOrders()` with default options
   - Displays progress as items are added
   - Shows final result summary (success/partial/failed, per-item status)
   - Reports which orders were marked as 'ordered'

3. **`--status` flag**: Filter orders by status (default: 'new'). Accept comma-separated values: `--status new,ordered`
4. **`--no-headless` flag**: Run browser in visible mode from the start (useful for debugging)
5. **`help` command**: Show usage

Add npm script to package.json: `"cart": "npx tsx scripts/orders/cart-cli.ts"` and `"cart:preview": "npx tsx scripts/orders/cart-cli.ts preview"` and `"cart:fill": "npx tsx scripts/orders/cart-cli.ts --fill"`

Parse args using the same manual process.argv parsing pattern used in manage.ts (no external arg parser library).
  </action>
  <verify>npx tsc --noEmit passes. Verify CLI arg parsing handles preview (default), --fill, --status, --no-headless, and help commands.</verify>
  <done>Cart CLI displays preview by default, executes fill with --fill flag, supports status filtering and headless toggle.</done>
</task>

<task type="auto">
  <name>Task 2: Add cart fill API endpoint to preview server</name>
  <files>scripts/orders/index.ts, scripts/pipeline/preview-server.ts</files>
  <action>
1. **Update barrel export** (scripts/orders/index.ts):
   - Add exports from cart-types.ts: `CartItem, CartFillRequest, CartFillResult, CartItemResult`
   - Add exports from cart-consolidator.ts: `consolidateOrders, getOrdersForCartFill`
   - Add exports from sanmar-cart-filler.ts: `fillSanMarCart, fillCartForPendingOrders, saveCartFillResult`

2. **Add preview server endpoints** (scripts/pipeline/preview-server.ts):

   **GET /api/cart/preview** — Preview consolidated cart without executing:
   - Call `getOrdersForCartFill()` with optional `?status=new` query param
   - Call `consolidateOrders()` on the orders
   - Return `{ items: CartItem[], orderNumbers: number[], orderCount: number, itemCount: number, skippedCount: number }`
   - 200 OK always (empty cart is valid)

   **POST /api/cart/fill** — Execute cart fill automation:
   - Accept optional body: `{ statuses?: string[], headless?: boolean }`
   - Call `fillCartForPendingOrders()` with provided options
   - Return `{ result: CartFillResult }`
   - 200 OK on success/partial, 500 on complete failure or thrown error
   - This is a long-running request (browser automation takes time) — set appropriate timeout

   **GET /api/cart/history** — List past cart fill results:
   - Read `data/cart-fills/` directory
   - Parse each JSON file
   - Return `{ fills: CartFillResult[] }` sorted by completedAt DESC
   - Return empty array if directory doesn't exist

Add CORS support for these new endpoints (follow existing CORS pattern in preview-server.ts).
  </action>
  <verify>npx tsc --noEmit passes. Verify endpoints are registered with correct HTTP methods and response shapes.</verify>
  <done>Cart preview, fill, and history endpoints operational on preview server.</done>
</task>
