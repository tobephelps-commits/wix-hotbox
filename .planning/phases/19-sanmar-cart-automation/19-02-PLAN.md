  <name>Task 1: Build SanMar.com browser automation engine</name>
  <files>scripts/orders/sanmar-cart-filler.ts</files>
  <action>
Create sanmar-cart-filler.ts with a `fillSanMarCart` function that uses Playwright to automate SanMar.com cart filling.

**Environment variables required:**
- `SANMAR_USERNAME` — SanMar.com web login (already used by SOAP API auth)
- `SANMAR_PASSWORD` — SanMar.com web password (already used by SOAP API auth)

**Core function signature:**
```typescript
async function fillSanMarCart(request: CartFillRequest, options?: {
  headless?: boolean;       // default: true (headless until checkout handoff)
  slowMo?: number;          // default: 0 (ms delay between actions, useful for debugging)
  timeout?: number;         // default: 60000 (per-item timeout in ms)
}): Promise<CartFillResult>
```

**Implementation approach:**

1. **Launch browser** — Use `chromium.launch({ headless: true })` initially. Create a persistent browser context with `browser.newContext()` so cookies persist across pages.

2. **Login to SanMar.com:**
   - Navigate to `https://www.sanmar.com/signin`
   - Fill email/username field and password field
   - Submit login form
   - Wait for redirect to authenticated page (look for account menu or dashboard element)
   - If login fails (wrong credentials, CAPTCHA, etc.), throw a descriptive error and close browser
   - Store authentication state in the browser context (cookies persist automatically)

3. **For each CartItem in request.items:**
   - Navigate to SanMar product page. SanMar URLs follow the pattern `https://www.sanmar.com/p/{vendorStyle}` (e.g., `https://www.sanmar.com/p/PC61`)
   - Wait for product page to load (look for color/size selectors)
   - Select the correct color from the color picker (match by color name text)
   - Select the correct size from the size selector (match by size text)
   - Set the quantity in the quantity input field
   - Click "Add to Cart" button
   - Wait for cart confirmation (modal, toast, or cart count update)
   - Record success/failure in CartItemResult
   - If an item fails, log the error but continue with remaining items (don't abort the whole batch)

4. **Important resilience patterns:**
   - Wrap each item addition in try/catch — one item failing shouldn't stop others
   - Use `page.waitForSelector()` with reasonable timeouts (not page.waitForLoadState which can hang)
   - After each add-to-cart, verify the cart count incremented or the confirmation appeared
   - If SanMar shows an "item out of stock" or "unavailable" message, capture it in the error field

5. **Browser handoff at checkout:**
   - After all items are processed, navigate to `https://www.sanmar.com/cart` (or the SanMar cart page)
   - Close the headless browser
   - Relaunch browser in HEADED mode (`chromium.launch({ headless: false })`) with the same storage state (use `context.storageState()` to save and restore cookies/localStorage)
   - Navigate to the cart page in the visible browser
   - Log "Browser opened at SanMar cart — complete checkout manually"
   - DO NOT close this visible browser — leave it open for the owner

6. **Return CartFillResult** with:
   - Per-item success/failure results
   - Overall status: 'success' if all items added, 'partial' if some failed, 'failed' if all failed
   - checkoutUrl: the cart page URL
   - completedAt timestamp

**Important notes on SanMar.com automation:**
- SanMar.com may have dynamic elements (React/Angular) — use `page.waitForSelector()` liberally
- Color selectors may be swatches (clickable color chips) or dropdowns — handle both patterns
- The site may show login prompts or session timeouts — detect and re-login if needed
- Do NOT attempt to complete checkout — the owner does this manually
- Use descriptive selector strategies: prefer `text=`, `role=`, or data attributes over fragile CSS selectors
- Add reasonable delays between rapid actions to avoid triggering rate limits or bot detection

**Selector strategy notes:**
- Since SanMar.com's exact DOM structure may change, use flexible selectors
- Prefer: `page.getByText()`, `page.getByRole()`, `page.getByLabel()`, `page.locator('[data-*]')`
- Fallback: CSS selectors with semantic class names
- The exact selectors WILL need adjustment based on SanMar.com's actual DOM — the initial implementation should use the most robust selectors possible and include clear comments marking where selectors target specific SanMar.com elements so they're easy to update

3. **High-level orchestrator** — `fillCartForPendingOrders(options?: { statuses?: OrderStatus[]; headless?: boolean }): Promise<CartFillResult>` function that:
   - Calls `getOrdersForCartFill()` to get eligible orders

   - Calls `consolidateOrders()` to build the CartFillRequest
   - If no SanMar items found after consolidation, log message and return early
   - Calls `fillSanMarCart()` to execute the automation
   - Calls `saveCartFillResult()` to persist the result
   - Calls `markOrdersAsOrdered()` to update order statuses
   - Returns the CartFillResult

Export all public functions: fillSanMarCart, fillCartForPendingOrders, saveCartFillResult, markOrdersAsOrdered.
