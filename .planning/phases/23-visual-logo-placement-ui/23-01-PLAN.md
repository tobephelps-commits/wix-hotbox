<task type="auto">
  <name>Task 1: Build drag-and-drop logo placement engine</name>
  <files>scripts/pipeline/preview.html</files>
  <action>
Add a self-contained visual logo placement system to preview.html. This is a pure DOM/CSS approach using Pointer Events API — no external dependencies.

**CSS additions (~80 lines):**
- `.logo-placement-container` — `position: relative; overflow: hidden; cursor: crosshair` container that holds the product image and the draggable logo overlay. Size should match the angle preview area (max-width 100%, max-height 320px, centered). Background: subtle checkerboard or dark border to distinguish the interactive area.
- `.logo-placement-img` — The product image fills the container naturally (`width: 100%; height: auto; display: block; pointer-events: none; user-select: none`).
- `.logo-draggable` — `position: absolute; cursor: grab; user-select: none` for the logo image overlay. When dragging: `cursor: grabbing`. Has a 1px dashed border (#6c63ff) to show bounds. The logo img inside uses `width: 100%; height: 100%; object-fit: contain; pointer-events: none`.
- `.logo-handle` — 10x10px white squares with 1px solid #6c63ff border, `position: absolute; z-index: 10`. Four corners with appropriate resize cursors (`nwse-resize` for top-left/bottom-right, `nesw-resize` for top-right/bottom-left). On hover: background #6c63ff.
- `.logo-placement-coords` — Small text overlay at bottom of container showing live "x: 0.50 y: 0.33 scale: 0.25" as user drags.

**JavaScript: LogoPlacementEngine object (~150 lines):**

Create a `LogoPlacementEngine` object (not a class — keep consistent with existing vanilla JS patterns) with these methods:

`init(containerEl, angle)` — Sets up a placement container for one angle. Stores reference in `anglePlacement[angle]`.

`loadProductImage(angle, imageUrl)` — Sets the product image as background in the container. After the image loads, records `naturalWidth`/`naturalHeight` and the displayed size for coordinate mapping.

`loadLogo(angle, logoUrl)` — Creates the draggable logo `<div>` with the logo `<img>` inside, plus 4 corner handle `<div>` elements. Positions the logo at the current `angleOverlayState[angle].customX/customY` coordinates. Sets initial size based on `angleOverlayState[angle].scale`. If a logo is already loaded, removes and replaces it.

`_setupDrag(angle)` — Attaches `pointerdown` on the logo div. On pointerdown: `setPointerCapture`, record start offset between pointer and logo top-left. On `pointermove`: update `style.left`/`style.top`, clamp to container bounds, update handle positions, update live coordinate display, update `angleOverlayState[angle]`. On `pointerup`: `releasePointerCapture`, finalize coordinates.

`_setupResize(angle)` — Attaches `pointerdown` on each handle div. On pointerdown: record which corner, capture pointer. On pointermove: calculate new width from drag delta, maintain aspect ratio (`newHeight = newWidth / aspectRatio`), enforce min size (container width * 0.05) and max size (container width * 0.60), update logo div dimensions and position (for top-left/top-right handles that move the origin), update all 4 handle positions, update live coordinate display, update `angleOverlayState[angle].scale`. On pointerup: release.

`_updateHandles(angle)` — Repositions the 4 corner handles to match current logo div bounds. Handles sit centered on each corner (offset by -5px from corner).

`_extractCoords(angle)` — Reads logo div position and size, computes normalized coordinates:
  - `x = (logoDiv.offsetLeft + logoDiv.offsetWidth / 2) / containerWidth` (center of logo, normalized)
  - `y = (logoDiv.offsetTop + logoDiv.offsetHeight / 2) / containerHeight`
  - `scale = logoDiv.offsetWidth / containerWidth`
  Updates `angleOverlayState[angle].customX`, `.customY`, `.scale` and the `.position` to `'custom'`.

`setFromCoords(angle, x, y, scale)` — Positions the logo programmatically from normalized coordinates (used when loading existing config or when user changes the scale slider).

`remove(angle)` — Removes the logo overlay and handles from the container.

**Coordinate mapping is critical for accuracy:**
The product image displayed in the container may not be at its natural resolution. The container CSS constrains it. The normalized coordinates (0-1) must be relative to the *displayed* image dimensions, not the container dimensions. Use a `ResizeObserver` on the container to track display size changes and adjust logo position proportionally.

**Important implementation details:**
- Use `touch-action: none` on the logo div and handles to prevent browser scroll interference during drag on mobile.
- All pointer events should use `setPointerCapture(e.pointerId)` to ensure drag continues even if pointer leaves the element.
- The coordinate display should update on every pointermove, not just on pointerup.
- When the logo is first loaded onto an angle, position it at the current angleOverlayState values (which default to center-chest: 0.5, 0.33).
- The logo image should be loaded with `crossOrigin: 'anonymous'` if it's a URL (logos are local files served by the preview server, so this shouldn't be an issue, but be defensive).

<task type="auto">
  <name>Task 2: Integrate placement engine into angle cards</name>
  <files>scripts/pipeline/preview.html</files>
  <action>
Wire the LogoPlacementEngine into the existing per-angle overlay card UI, replacing the position preset dropdown and custom X/Y inputs with the visual placement area.

**HTML changes per angle card:**
In each `.angle-overlay-card` (front, back, side), replace the existing controls section layout:
- KEEP the enable/disable checkbox toggle at the top of each card.
- KEEP the scale slider (range 0.10-0.60) but move it below the placement area.
- REMOVE the position preset dropdown (`<select>` with center-chest, left-chest, etc.).
- REMOVE the custom X/Y number inputs.
- ADD a `.logo-placement-container` div inside each card's content area, between the toggle and the scale slider. This is where the product image + draggable logo will render.

The angle card HTML structure should become:
```
.angle-overlay-card
  .angle-card-header (checkbox toggle + angle label)
  .angle-card-content (shown when enabled)
    .logo-placement-container (product image + draggable logo)
    .placement-scale-row (scale slider with label)
    .placement-actions-row (Preview with Sharp button)
```

**JavaScript integration changes:**

1. **On product load (when color data arrives):** For each angle that has an available image URL, call `LogoPlacementEngine.init(containerEl, angle)` and `LogoPlacementEngine.loadProductImage(angle, imageUrl)`. The image URL comes from the same source the current angle cards use — the selected color's front/back/side image URLs stored in the product preview data.

2. **On logo selection (logo dropdown change):** For each enabled angle, call `LogoPlacementEngine.loadLogo(angle, logoUrl)`. The logo URL is constructed the same way the current preview system does it — from the logo registry served by `/api/logos`. Position the logo at the current `angleOverlayState[angle]` coordinates.

3. **On angle toggle (checkbox change):** When an angle is enabled and both product image and logo are available, initialize the placement and load both images. When disabled, call `LogoPlacementEngine.remove(angle)`.

4. **Scale slider sync:** When the user drags the scale slider, call `LogoPlacementEngine.setFromCoords(angle, currentX, currentY, newScale)` to resize the logo in the placement area. Conversely, when the user resizes via drag handles, update the scale slider value to match. Use a flag to prevent circular update loops.

5. **Preview with Sharp button:** Keep the existing `generateAnglePreview()` function but rename the button to "Render Final" or similar. This calls `/api/overlay` with the coordinates from `angleOverlayState` (which the placement engine updates live) and shows the Sharp-composited result below the placement area. This serves as the "what you see is what you get" confirmation — the drag preview shows the logo at the right position, and the Sharp render confirms the actual output.

6. **buildLogoAnglesConfig() stays unchanged** — it already reads from `angleOverlayState` which the placement engine updates. The creation flow continues to work as-is.

7. **Position preset dropdown replacement:** Since we're removing the dropdown, add a small "Quick position" row of clickable preset buttons (center-chest, left-chest, center-back) below the placement container. When clicked, call `LogoPlacementEngine.setFromCoords(angle, presetX, presetY, currentScale)`. Style as small pill buttons. This preserves quick access to common positions while the drag area allows precise custom placement.

**State sync details:**
- `angleOverlayState[angle].position` should be set to `'custom'` whenever the user drags the logo (the engine does this in `_extractCoords`).
- `angleOverlayState[angle].customX` and `.customY` are updated live during drag.
- `angleOverlayState[angle].scale` is synced bidirectionally between the slider and the drag handles.

**angleDom registry updates:**
Update the `angleDom` object to include references to the new placement container elements instead of the old dropdown/input elements. Remove references to the position select and custom X/Y inputs. Add references to: `placementContainer`, `scaleSlider`, `scaleLabel`, `renderBtn`.

**Important: preserve the disabled state logic.** Angles without product images should still show as disabled. The placement container should display a "No image available" message when the angle has no image, matching the current behavior.
