<task type="auto">
  <name>Task 1: Port stock sync engine and smart daemon</name>
  <files>src/sync/stock-sync.ts, src/sync/sync-poller.ts, src/sync/index.ts</files>
  <action>
  Port `src/sync/stock-sync.ts` from `scripts/sync/stock-sync.ts`:

  - `parseSku(sku)`: Extract { style, color, size } from WIX variant SKU format "{style}-{color}-{size}". Return null on parse failure.

  - `syncProductStock(db, mapping, wixConfig)`: Sync a single product:
    1. Get latest snapshot from monitor store (getSnapshot)
    2. Check snapshot staleness (isSnapshotStale)
    3. Fetch WIX product variants via WIX API (use self-contained WIX calls like orders/wix-sync.ts pattern -- ecom/v1 or stores/v1 endpoints)
    4. Parse each variant SKU, match color (case-insensitive) and size (exact) against snapshot
    5. Update WIX inventory: quantity + inStock flag per variant
    6. Return SyncResult with counts of outOfStock/restocked/unchanged/parseErrors
  - WIX API calls: GET product variants, POST update inventory. Use wixConfig { apiKey, siteId } parameter (same pattern as orders/wix-sync.ts).
  - 200ms delay between WIX API calls to respect rate limits.

  Port `src/sync/sync-poller.ts` from `scripts/sync/sync-poller.ts`:

  - Module-level state: syncHealth (SyncHealth), abortController (AbortController | null), running flag
  - `syncOnce(db, config, wixConfig, credentials)`: Single sync cycle -- pollOnce() for inventory, then syncProductStock() for each mapped product, then sendSyncNotification(), then return results.
  - `startDaemon(db, config, wixConfig, credentials)`: Start smart sync loop. 60-second tick interval. Each tick calls pollDue() to check which products need polling, then syncs. Updates SyncHealth on each tick. Respects AbortSignal for graceful shutdown. Error escalation after 5 consecutive failures.
  - `stopDaemon()`: Signal abort, wait for current tick, clear state.
  - `getSyncHealth()`: Return current SyncHealth snapshot.
  - `isDaemonRunning()`: Return running flag.
  - Health tracking: cumulative moving average for tick duration, max tick duration, products polled count, notification success/failure counts.

  Update `src/sync/index.ts` barrel: add stock-sync and sync-poller exports.
  </action>
  <verify>npx tsc --noEmit --pretty 2>&1 | head -20 (stock-sync and sync-poller compile)</verify>
  <done>Stock sync updates WIX inventory from snapshots, daemon runs priority-aware polling loop, health tracked</done>
</task>

<task type="auto">
  <name>Task 2: Create sync API routes and register</name>
  <files>src/routes/sync.ts, src/routes/index.ts</files>
  <action>
  Create `src/routes/sync.ts` as Fastify plugin with endpoints:

  Product Mappings:
  - GET /api/sync/mappings -- List all product mappings
  - POST /api/sync/mappings -- Create mapping { style, wixProductId, productName, vendor? }
  - DELETE /api/sync/mappings/:style -- Remove mapping (query param vendor=)

  Sync Operations:
  - POST /api/sync/run -- Run single sync cycle on-demand. Extract credentials from fastify.config, wixConfig from { apiKey: config.wixApiKey, siteId: config.wixSiteId }. Return { productsPolled, productsSynced, alerts, errors }.

  Daemon Control:
  - GET /api/sync/health -- Return daemon health (getSyncHealth()) plus running status
  - POST /api/sync/start -- Start smart sync daemon. Return 200 if started, 409 if already running. Extract config/credentials from fastify.config.
  - POST /api/sync/stop -- Stop daemon. Return 200 if stopped, 404 if not running.

  Audit:
  - POST /api/sync/audit -- Audit all product mappings against WIX API. Check each mapping's wixProductId still exists. Return MappingAuditResult { total, healthy, orphaned, errors }. Use 200ms rate limit between WIX API calls.

  Register in `src/routes/index.ts`:
  - Import syncRoutes from './sync.js'
  - Register with prefix '/sync'
  </action>
