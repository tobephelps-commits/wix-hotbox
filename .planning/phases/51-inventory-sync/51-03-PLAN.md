  <name>Task 1: Port polling engine</name>
  <files>src/monitor/poller.ts, src/monitor/index.ts</files>
  <action>
  Port `src/monitor/poller.ts` from `scripts/monitor/poller.ts`:

  - `pollProduct(db, product, config, credentials)`: Fetch inventory for a single tracked product via the vendor adapter registry. Convert unified inventory data to SkuSnapshot[] format. Save snapshot, detect alerts vs previous snapshot, log alerts, update lastPolledAt. Return { snapshot, alerts }.

  - `pollDue(db, config)`: Check which tracked products are due for polling based on priority tier intervals (hot=hotIntervalMinutes, normal=pollIntervalMinutes, slow=slowIntervalMinutes). Compare lastPolledAt against current time. Return TrackedProduct[] that need polling.

  - `pollOnce(db, config, credentials)`: Single poll cycle -- get due products, poll each sequentially, collect all alerts. Return { productsPolled, alerts, errors }.

  - `unifiedInventoryToSnapshots(inventory)`: Convert UnifiedInventory[] (from vendor adapter) to SkuSnapshot[] format. Map vendor warehouse data to WarehouseQuantity[]. Determine wellStocked flag (any warehouse at 1500 cap).

  Key adaptations from v1.x:
  - Use `getAdapter(vendor)` from `src/vendors/registry.ts` instead of scripts/vendor/registry
  - Credentials come from Config (fastify.config) -- extract sanmarCustomerNumber/username/password and ssAccountNumber/apiKey
  - Database parameter instead of file-based store
  - Vendor credential validation: call adapter.validateCredentials() once per process (module-level Set tracking validated vendors)

  Add poller exports to src/monitor/index.ts barrel.
  </action>

<task type="auto">
  <name>Task 2: Create monitoring API routes</name>
  <files>src/routes/monitor.ts, src/routes/index.ts</files>
  <action>
  Create `src/routes/monitor.ts` as Fastify plugin with endpoints:

  Config:
  - GET /api/monitor/config -- Return current monitor config (DEFAULT_CONFIG merged with any saved overrides)

  Tracked Products CRUD:
  - GET /api/monitor/products -- List all tracked products with their latest snapshot timestamps
  - POST /api/monitor/products -- Add tracked product { style, name, vendor?, colors?, sizes?, priority? }
  - DELETE /api/monitor/products/:style -- Remove tracked product (query param vendor= for vendor specificity)
  - PATCH /api/monitor/products/:style -- Update product fields (priority, thresholds, colors, sizes)

  Snapshots:
  - GET /api/monitor/products/:style/snapshot -- Get latest inventory snapshot for a style (query param vendor=)

  Alerts:
  - GET /api/monitor/alerts -- List alerts with filtering: query params type, style, vendor, since (ISO date), limit (default 50), offset (default 0)
  - POST /api/monitor/alerts/:id/acknowledge -- Mark alert as acknowledged

  Polling:
  - POST /api/monitor/poll -- Run a single poll cycle on-demand. Return { productsPolled, alertsGenerated, errors }. Extract credentials from fastify.config.

  Register in `src/routes/index.ts`:
  - Import monitorRoutes from './monitor.js'
  - Register with prefix '/monitor'
  </action>
