<task type="auto">
  <name>Task 1: Create health check, backup, and update scripts</name>
  <files>pi/health/health-check.sh, pi/health/hotbox-health.service, pi/health/hotbox-health.timer, pi/maintenance/backup-db.sh, pi/maintenance/update-app.sh, pi/maintenance/hotbox-backup.service, pi/maintenance/hotbox-backup.timer, pi/setup.sh</files>
  <action>
  **Health Check (pi/health/):**

  Create `pi/health/health-check.sh`:
  - Source hotbox.conf for PORT (default 3456)
  - curl -sf http://localhost:${PORT}/api/health with 10s timeout
  - If fails, log warning and retry once after 5s
  - If second attempt fails, restart hotbox-server.service via systemctl
  - Log all actions to journald via logger -t hotbox-health
  - Root guard, set -euo pipefail

  Create `pi/health/hotbox-health.service` (oneshot):
  - Type=oneshot
  - ExecStart=/home/hotbox/app/pi/health/health-check.sh
  - User=root (needs systemctl restart permission)

  Create `pi/health/hotbox-health.timer`:
  - OnBootSec=60 (wait for server to start)
  - OnUnitActiveSec=120 (check every 2 minutes)
  - AccuracySec=30s

  **Database Backup (pi/maintenance/):**

  Create `pi/maintenance/backup-db.sh`:
  - Source hotbox.conf for DATA_DIR (default /home/hotbox/app/data)
  - Create backup dir: ${DATA_DIR}/backups/
  - Use SQLite .backup command via `sqlite3 ${DATA_DIR}/hotbox.db ".backup ${BACKUP_PATH}"`
  - Backup filename: hotbox-YYYY-MM-DD-HHMMSS.db
  - Rotate: keep only last 7 backups (ls -t, tail +8, xargs rm -f)
  - Log via logger -t hotbox-backup
  - Root guard not needed (runs as hotbox user)

  Create `pi/maintenance/hotbox-backup.service` (oneshot):
  - Type=oneshot
  - ExecStart=/home/hotbox/app/pi/maintenance/backup-db.sh
  - User=hotbox, Group=hotbox

  Create `pi/maintenance/hotbox-backup.timer`:
  - OnCalendar=daily (midnight)
  - Persistent=true (run on boot if missed)
  - RandomizedDelaySec=300

  **App Update (pi/maintenance/):**

  Create `pi/maintenance/update-app.sh`:
  - Source hotbox.conf for APP_DIR (default /home/hotbox/app)
  - cd to APP_DIR
  - git fetch origin main
  - Compare local HEAD with origin/main. If same, log "Already up to date" and exit.
  - git pull origin main
  - npm install --production
  - npm run build
  - systemctl restart hotbox-server.service
  - Log all steps via logger -t hotbox-update
  - Root guard (needs systemctl restart)

  **Update setup.sh:**

  Read existing pi/setup.sh first. Add a new phase at the end (before the final success message):
  - Phase: Install health check and backup timers
  - Copy health-check.sh to app dir, chmod +x
  - Copy and enable hotbox-health.timer and hotbox-health.service
  - Copy backup-db.sh, chmod +x
  - Copy and enable hotbox-backup.timer and hotbox-backup.service
  - Copy update-app.sh, chmod +x
  </action>
  <verify>bash -n pi/health/health-check.sh && bash -n pi/maintenance/backup-db.sh && bash -n pi/maintenance/update-app.sh && echo "All scripts valid"</verify>
  <done>Health check timer (2min interval), daily DB backup with 7-day rotation, update script, setup.sh updated</done>
</task>

<task type="auto">
  <name>Task 2: Extend /api/system with hardware metrics</name>
  <files>src/routes/index.ts</files>
  <action>
  Update the existing GET /api/system endpoint in `src/routes/index.ts` to include hardware metrics useful for dashboard monitoring.

  Read src/routes/index.ts first.

  Add to the system endpoint response:

  - `cpu`: { loadAvg: os.loadavg() (1/5/15 min array), cores: os.cpus().length }
  - `memory`: { totalMB: Math.round(os.totalmem() / 1024 / 1024), freeMB: Math.round(os.freemem() / 1024 / 1024), usedPercent: Math.round((1 - os.freemem() / os.totalmem()) * 100) }
  - `temperature`: Read /sys/class/thermal/thermal_zone0/temp if it exists (Pi CPU temp). Parse as number, divide by 1000 for Celsius. Return null if file doesn't exist (non-Pi platform). Use try/catch with fs.readFileSync.
  - `disk`: Try to read disk usage via statfs or df. On Pi (linux), use child_process.execSync('df -B1 /home/hotbox/app/data 2>/dev/null') to get total/used/available. On other platforms, return null. Parse df output: split lines, parse second line columns.
  - `network`: Import getNetworkInfo from '../lan/index.js', call getNetworkInfo(fastify.config.port) and include in response.

  Import `os` from 'node:os' and `readFileSync` from 'node:fs' (both likely already imported or available). Import `execSync` from 'node:child_process'.

  Keep the existing response fields (version, uptime, nodeVersion, platform, arch, memoryUsage, database). Add the new fields alongside.
