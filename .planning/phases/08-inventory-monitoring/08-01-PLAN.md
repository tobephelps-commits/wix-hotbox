<task type="auto">
  <name>Task 1: Create monitor types, config, and tracked products store</name>
  <files>scripts/monitor/types.ts, scripts/monitor/store.ts</files>
  <action>
Create `scripts/monitor/` directory.

**types.ts** — Define TypeScript interfaces for the monitoring system:

- `MonitorConfig`: Configuration object with:
  - `pollIntervalMinutes: number` (default: 60) — how often to check inventory
  - `dataDir: string` (default: "./data/monitor") — where to persist JSON state files
  - `lowStockThreshold: number` (default: 10) — total qty below this = low stock alert
  - `criticalStockThreshold: number` (default: 3) — total qty below this = critical alert
  - `outOfStockThreshold: number` (default: 0) — total qty at or below this = out of stock alert

- `TrackedProduct`: A product being monitored:
  - `style: string` — SanMar style number (e.g., "PC61")
  - `name: string` — Human-friendly name for alerts (e.g., "Port & Company Essential Tee")
  - `addedAt: string` — ISO timestamp when product was added to monitoring
  - `colors?: string[]` — Optional: only monitor specific catalog colors (monitor all if omitted)
  - `sizes?: string[]` — Optional: only monitor specific sizes (monitor all if omitted)

- `InventorySnapshot`: A point-in-time inventory reading:
  - `style: string`
  - `timestamp: string` — ISO timestamp of this snapshot
  - `skus: SkuSnapshot[]`

- `SkuSnapshot`: Per-SKU inventory at snapshot time:
  - `color: string`
  - `size: string`
  - `totalQty: number` — sum across all warehouses
  - `wellStocked: boolean` — any warehouse at 1500 cap

- `StockAlert`: An alert triggered by threshold crossing (defined here, used in Plan 02):
  - `type: "out-of-stock" | "critical" | "low-stock" | "back-in-stock"`
  - `style: string`
  - `productName: string`
  - `color: string`
  - `size: string`
  - `previousQty: number`
  - `currentQty: number`
  - `timestamp: string`

**store.ts** — JSON file persistence for tracked products and inventory snapshots:

- `getDefaultConfig(): MonitorConfig` — returns default config values
- `loadConfig(dataDir?: string): Promise<MonitorConfig>` — load config from `{dataDir}/config.json`, return defaults if file doesn't exist
- `saveConfig(config: MonitorConfig): Promise<void>` — write config to `{config.dataDir}/config.json`
- `loadTrackedProducts(config: MonitorConfig): Promise<TrackedProduct[]>` — load from `{dataDir}/tracked-products.json`, return `[]` if file doesn't exist
- `saveTrackedProducts(products: TrackedProduct[], config: MonitorConfig): Promise<void>` — write to `{dataDir}/tracked-products.json`
- `addTrackedProduct(product: TrackedProduct, config: MonitorConfig): Promise<void>` — load existing, add if not duplicate (by style), save
- `removeTrackedProduct(style: string, config: MonitorConfig): Promise<boolean>` — load, filter out by style, save, return true if found
- `loadLatestSnapshot(style: string, config: MonitorConfig): Promise<InventorySnapshot | null>` — load from `{dataDir}/snapshots/{style}.json`, return null if doesn't exist
- `saveSnapshot(snapshot: InventorySnapshot, config: MonitorConfig): Promise<void>` — write to `{dataDir}/snapshots/{style}.json` (overwrite — only latest snapshot needed for change detection)

Use `node:fs/promises` for all file I/O. Create directories recursively with `{ recursive: true }` on mkdir. Use JSON.stringify with 2-space indent for human-readable files.

Follow established patterns:
- ESM module with `.js` extensions in imports
- Function exports (not class)
- Import types with `import type` where possible

  <name>Task 2: Build polling engine and tracked-product CLI</name>

  <action>
**poller.ts** — Core polling engine:

- `async function pollOnce(config: MonitorConfig): Promise<InventorySnapshot[]>` — For each tracked product: call `getStyleInventory(style)` from sanmar/index.js, convert SkuInventory[] to InventorySnapshot (summing warehouse qtys via getTotalQuantity, checking isWellStocked), filter to tracked colors/sizes if specified, save snapshot via store.saveSnapshot. Return all new snapshots. Log progress to console: `[Monitor] Polling {N} tracked products...`, `[Monitor] {style}: {X} SKUs fetched`.

- `async function startPolling(config?: MonitorConfig): Promise<void>` — Load config (or use provided), load tracked products, run pollOnce immediately, then set up `setInterval` for config.pollIntervalMinutes. Log: `[Monitor] Started. Polling every {N} minutes for {M} products.` Handle SIGINT for graceful shutdown (clear interval, log `[Monitor] Stopped.`).

- Export `pollOnce` and `startPolling`.

IMPORTANT: The poller does NOT evaluate alerts — that's Plan 02's job. The poller only fetches and stores snapshots. Plan 02 will hook into `pollOnce` results to compare against previous snapshots.

**manage.ts** — CLI for managing tracked products:

- Parse `process.argv` for subcommands:
  - `add <style> [name]` — Add a style to tracking. If name not provided, use style as name. Call addTrackedProduct.
  - `remove <style>` — Remove a style from tracking. Call removeTrackedProduct.
  - `list` — List all tracked products (style, name, addedAt).
  - `poll` — Run a single poll cycle (pollOnce) and print results summary.
  - `start` — Start continuous polling (startPolling).
  - No args or `help` — Print usage.

- Add CLI guard using `import.meta.url` pattern (match create-product.ts pattern with fileURLToPath + path.resolve to handle spaces in Windows paths).

**package.json** — Add npm scripts:
- `"monitor"`: `"npx tsx scripts/monitor/manage.ts"`
- `"monitor:add"`: `"npx tsx scripts/monitor/manage.ts add"`
- `"monitor:list"`: `"npx tsx scripts/monitor/manage.ts list"`
- `"monitor:poll"`: `"npx tsx scripts/monitor/manage.ts poll"`
- `"monitor:start"`: `"npx tsx scripts/monitor/manage.ts start"`

Test by running: `npx tsx scripts/monitor/manage.ts help` (should print usage without errors).
