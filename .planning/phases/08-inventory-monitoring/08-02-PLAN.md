**alerts.ts** — Stock change detection and alert generation:

- `function classifyStockLevel(totalQty: number, config: MonitorConfig): "out-of-stock" | "critical" | "low-stock" | "normal"` — Classify a SKU's stock level based on config thresholds. Check in order: `<= outOfStockThreshold` → out-of-stock, `<= criticalStockThreshold` → critical, `<= lowStockThreshold` → low-stock, else → normal.

- `function detectAlerts(current: InventorySnapshot, previous: InventorySnapshot | null, config: MonitorConfig, productName: string): StockAlert[]` — Compare current snapshot against previous:
  1. For each SKU in current snapshot, find matching SKU in previous (by color+size).
  2. Classify both current and previous stock levels.
  3. Generate alert if level CHANGED (not just if below threshold — only alert on transitions):
     - normal/low/critical → out-of-stock: alert type "out-of-stock"
     - normal/low → critical: alert type "critical"
     - normal → low-stock: alert type "low-stock"
     - out-of-stock → anything above: alert type "back-in-stock"
  4. If no previous snapshot (first poll), only generate alerts for SKUs already at critical or out-of-stock (skip low-stock on first run to avoid alert flood).
  5. Return array of StockAlert objects.

- `function formatAlert(alert: StockAlert): string` — Format a single alert for console output:
  - out-of-stock: `⚠ OUT OF STOCK: {productName} - {color} {size} (was {previousQty}, now {currentQty})`
  - critical: `🔴 CRITICAL: {productName} - {color} {size} ({currentQty} remaining)`
  - low-stock: `🟡 LOW STOCK: {productName} - {color} {size} ({currentQty} remaining)`
  - back-in-stock: `🟢 BACK IN STOCK: {productName} - {color} {size} ({currentQty} available)`

- `function formatAlertSummary(alerts: StockAlert[]): string` — Format summary: count by type, list each alert. If no alerts: `No stock level changes detected.`

**alert-log.ts** — Persistent alert log:

- `async function loadAlertLog(config: MonitorConfig): Promise<StockAlert[]>` — Load from `{dataDir}/alerts.json`, return `[]` if doesn't exist.
- `async function appendAlerts(alerts: StockAlert[], config: MonitorConfig): Promise<void>` — Load existing log, append new alerts, save. Cap log at 1000 entries (keep most recent, trim oldest).
- `async function getRecentAlerts(config: MonitorConfig, count?: number): Promise<StockAlert[]>` — Load and return last N alerts (default 50).
- `async function clearAlertLog(config: MonitorConfig): Promise<void>` — Delete alerts.json.

Use same JSON file patterns as store.ts (node:fs/promises, 2-space indent, recursive mkdir).

**poller.ts** — Add alert detection to polling cycle:

- Modify `pollOnce` to accept an optional `onAlerts?: (alerts: StockAlert[]) => void` callback.
- After fetching each product's inventory snapshot, load the PREVIOUS snapshot (via store.loadLatestSnapshot) BEFORE saving the new one.
- Call `detectAlerts(currentSnapshot, previousSnapshot, config, product.name)` to get alerts.
- Save new snapshot (overwriting previous).
- Append any alerts to alert log via `appendAlerts`.
- Print any alerts to console via `formatAlertSummary`.
- Call `onAlerts` callback if provided and alerts exist.
- After all products polled, print overall summary: `[Monitor] Poll complete. {N} products checked, {M} alerts generated.`

- Update `startPolling` to log alert count after each cycle.

**manage.ts** — Add alert-related CLI subcommands:

- `alerts` — Show recent alerts (last 50) formatted for console. Call getRecentAlerts + format each.
- `alerts clear` — Clear the alert log. Call clearAlertLog.
- `config` — Print current monitor config as formatted JSON.
- `config set <key> <value>` — Update a single config value. Validate key is a valid MonitorConfig field and value is a number. Save via saveConfig.

Update help text to include new subcommands.
