Replace the existing logo overlay section in preview.html (the `#logoOverlaySection` div and all its JS logic) with a per-angle design. The core compositing endpoint (`POST /api/overlay`) is unchanged — it already accepts any imageUrl + logoName + position + scale, so per-angle preview just sends the specific angle's image URL.

**HTML structure — replace the existing logo overlay section (~lines 1764-1803):**

Replace with a new layout that has:

1. **Logo select** (unchanged — pick logo from registry, or "None")
2. **Angle cards** — 3 cards (Front, Back, Side) displayed in a row. Each card has:
   - **Toggle checkbox** — enable/disable logo on this angle. Default: all unchecked until user enables.
   - **Angle label** ("Front", "Back", "Side")
   - **Position select** — same preset dropdown as before (center-chest, left-chest, etc.) plus Custom option. Independent per angle. Default: "center-chest" for front, "center-back" for back, "center-chest" for side.
   - **Scale slider** — 0.10 to 0.60, step 0.05. Independent per angle.
   - **Custom X/Y inputs** — shown only when position is "Custom"
   - **Preview button** — "Preview" per-angle, generates overlay for THIS angle's image
   - **Preview image area** — shows composited result for this angle
   - Controls are disabled/grayed when angle toggle is off
   - If no image URL available for this angle (e.g., product has no back image), show "No image available" and disable the toggle

**CSS additions (in the existing `<style>` block):**

Add styles for:
- `.angle-overlay-cards` — flex row container for the 3 angle cards, gap 16px, flex-wrap for mobile
- `.angle-overlay-card` — flex column, border, border-radius, padding, min-width ~200px, flex: 1
- `.angle-overlay-card.disabled` — opacity 0.5, pointer-events none on inner controls
- `.angle-overlay-card .angle-header` — flex row with checkbox + label
- `.angle-overlay-card .angle-controls` — the position/scale/custom fields
- `.angle-overlay-card .angle-preview` — preview image area per card
- Mobile: stack cards vertically

**JavaScript changes — replace the logo overlay JS section (~lines 3017-3203):**

Replace with:

1. **State:** Track per-angle config in a JS object:
```javascript
var angleOverlayState = {
  front: { enabled: false, position: 'center-chest', scale: 0.25, customX: 0.5, customY: 0.33 },
  back:  { enabled: false, position: 'center-back',  scale: 0.25, customX: 0.5, customY: 0.30 },
  side:  { enabled: false, position: 'center-chest', scale: 0.25, customX: 0.5, customY: 0.33 },
};
```

2. **fetchLogos()** — same as before (load registry, populate logo dropdown + position presets). After loading, populate all 3 angle cards' position dropdowns with the presets.

3. **showLogoSection()** — same visibility logic. Additionally, for each angle, check if the current product has that angle's image available (`productData.availableColors` → check if any selected color has `frontImageUrl`/`backImageUrl`/`sideImageUrl`). If no image for an angle, disable that angle card with "No image" message.

4. **Angle toggle handlers** — when checkbox changes, enable/disable controls in that card. When enabled, position/scale/preview become interactive. When disabled, preview area clears.

5. **Per-angle preview** — Each angle's "Preview" button calls `generateAnglePreview(angle)`:
   - Find the image URL for that angle from selected colors (same logic as current `generateOverlayPreview()` but using `backImageUrl` for back, `sideImageUrl` for side)
   - Call `POST /api/overlay` with that angle's image URL + position + scale
   - Display result in that angle card's preview area
   - Each angle card has its own preview img element and blob URL tracking

6. **Integration with product creation** — when the "Create WIX Product" button is clicked, collect the per-angle config from `angleOverlayState` and include in the creation request. The existing creation flow passes `--logo` args; the UI should build the equivalent per-angle config. Add the angle config to the fetch body sent to `/api/create`.

   Actually — check how the existing UI triggers creation. The preview server's creation endpoint reads args from the POST body. Update the creation request to include `logoAngles` data when per-angle config is active.

7. **Backward compat** — if user selects a logo but doesn't enable any angle toggles, show a hint: "Enable at least one angle to apply the logo."

**Key UX per CONTEXT.md:**
- "Dead simple toggle on/off" → checkbox per angle, not a complex form
- "No default assumptions" → all angles start unchecked; user explicitly enables
- "Preview before commit" → preview button per angle shows the composited result
- "Each angle is its own independent canvas" → separate position/scale controls
