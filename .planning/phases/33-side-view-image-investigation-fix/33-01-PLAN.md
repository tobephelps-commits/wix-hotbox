<objective>
Fix incorrect side image assignment in mapper.ts that causes sleeve logo placement on wrong angle images.

Purpose: SanMar's CLASS_TYPE_HIGH (2001) is a high-resolution front/lifestyle image, NOT a side view. The mapper incorrectly assigns it as sideImage, which causes sleeve logos to be placed on front-angle images instead of actual side-profile images (which SanMar doesn't provide).

Output: Corrected mapper.ts with sideImage set to null for SanMar products, preventing incorrect sleeve logo placement.
</objective>

In buildMediaPayload() (lines 341-348), the code adds CLASS_TYPE_HIGH images as "side images" assigned to Color choices. This is incorrect because:
1. These are high-resolution front/lifestyle shots, not true side views
2. When used for WIX variant image switching, customers see what appears to be a duplicate front image

Two options:
A) Remove the side image block entirely (simplest, matches adapter behavior)
B) Keep adding HIGH images but WITHOUT the "side" semantic (add as general product images)

Choose option A - remove the side image block entirely from Step 1. The HIGH images will still be added in Step 2 (lines 351-370) as general product images without choice assignment.

Current code (lines 341-348):
```typescript
// Side image (classTypeId 2001)
const sideImage = colorImages.find(

if (sideImage && !addedUrls.has(sideImage.url) && mediaItems.length < WIX_MEDIA_LIMIT) {
  mediaItems.push({ url: sideImage.url, choice: choiceAssignment });
  addedUrls.add(sideImage.url);
}
```

Replace with:
```typescript
// Note: SanMar does NOT provide true side-view images. CLASS_TYPE_HIGH (2001)
```
