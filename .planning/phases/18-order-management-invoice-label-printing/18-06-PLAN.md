Add order detail view that replaces the list when an order is selected.

**Detail view layout:**

Header:
- "← Back to Orders" link
- "Order #10043" title with status badge
- Source badge (WIX/Manual)
- Created date

**Two-column layout:**

Left column (order info):
- **Customer section:** Name, email, phone
- **Shipping address** (if present, else "Local Pickup")
- **Billing address** (if different from shipping)
- **Notes** (if present)

Right column (actions):
- **Status management:**
  - Current status prominently displayed
  - "Next Status" button showing the valid next status (from OrderStatusTransition)
  - Optional note field for status update
  - Status history timeline (vertical timeline with timestamps and notes)

- **Print actions:**
  - "Print Invoice" button — calls POST /api/orders/:id/print-invoice
  - "Download Invoice" button — opens GET /api/orders/:id/invoice in new tab (PDF viewer)
  - "Print Shipping Label" button (only visible if order has shipping address) — calls POST /api/orders/:id/print-label
  - "Download Label" button — opens GET /api/orders/:id/label in new tab
  - Print buttons show loading spinner during print, then success/error toast

**Line items table:**
- Full width below the two columns
- Columns: Product | Color/Size | Qty | Unit Price | Total
- Product name with thumbnail image if imageUrl present
- Vendor style number shown in small text below product name (if present)

**Totals section (right-aligned below line items):**
- Subtotal
- Shipping (if > 0)
- Tax (if > 0)
- Discount (if > 0)
- **Total** (bold, larger)

**Manual order form (modal/overlay):**
When "New Manual Order" is clicked, show a form overlay:
- Customer: First Name, Last Name, Email (opt), Phone (opt)
- Shipping address fields (optional section with checkbox "Has shipping address")
- Line items: dynamic rows with Product Name, Qty, Unit Price, and + button to add more rows
- Shipping cost, Tax fields
- Notes textarea
- "Create Order" submit button
- Posts to POST /api/orders, closes modal on success, refreshes list

**Status transition UX:**
When user clicks "Next Status":
1. Show the next valid status as button text (e.g., "Mark as Ordered")
2. If multiple valid transitions exist (e.g., 'new' can go to 'ordered' or 'cancelled'), show a dropdown
3. Optional note input appears
4. Confirm click calls PATCH /api/orders/:id/status
5. UI updates immediately on success

Follow existing CSS and interaction patterns. All API calls use fetch() with proper error handling and toast notifications for success/failure.
