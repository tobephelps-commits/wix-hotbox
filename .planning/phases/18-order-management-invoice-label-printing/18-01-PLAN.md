<task type="auto">
  <name>Task 1: Define order management types</name>
  <files>scripts/orders/types.ts</files>
  <action>
Create scripts/orders/types.ts with the following types:

**OrderStatus enum/union:** The full lifecycle from 18-CONTEXT.md:
- 'new' — just received, no action taken
- 'ordered' — items ordered from vendor (SanMar/S&S)
- 'received' — vendor shipment received at HotBox
- 'in-production' — items being decorated/customized
- 'packed' — ready to ship/pickup
- 'shipped' — in transit to customer
- 'delivered' — confirmed delivered
- 'cancelled' — order cancelled

**OrderSource union:** 'wix' | 'manual'

**OrderLineItem interface:**
- productName: string
- sku: string (optional)
- quantity: number
- unitPrice: number (retail price charged to customer)
- totalPrice: number
- vendorStyle: string (optional — SanMar/S&S style number for vendor ordering)
- vendor: string (optional — 'sanmar' | 'ss')
- color: string (optional)
- size: string (optional)
- imageUrl: string (optional)

**OrderAddress interface:**
- firstName: string
- lastName: string
- company: string (optional)
- addressLine1: string
- addressLine2: string (optional)
- city: string
- state: string
- postalCode: string
- country: string (default 'US')
- phone: string (optional)

**OrderCustomer interface:**
- firstName: string
- lastName: string
- email: string (optional)
- phone: string (optional)

**Order interface:**
- id: string (UUID v4 for local, WIX order ID for WIX orders)
- orderNumber: number (display number, e.g., 10043)
- source: OrderSource
- wixOrderId: string (optional — only for WIX-sourced orders)
- status: OrderStatus
- customer: OrderCustomer
- billingAddress: OrderAddress (optional)
- shippingAddress: OrderAddress (optional)
- lineItems: OrderLineItem[]
- subtotal: number
- shippingCost: number
- tax: number
- discount: number
- total: number
- notes: string (optional — buyer notes or internal notes)
- createdAt: string (ISO-8601)
- updatedAt: string (ISO-8601)
- statusHistory: Array<{ status: OrderStatus; timestamp: string; note?: string }>

**OrderStatusTransition:** Record mapping each OrderStatus to valid next statuses. 'new' can go to 'ordered' or 'cancelled'. 'ordered' can go to 'received' or 'cancelled'. Etc. 'delivered' and 'cancelled' are terminal states.

Export all types. Use TypeScript string literal unions (not enums) to match project conventions.

<task type="auto">
  <name>Task 2: Build WIX eCommerce Orders API client</name>
  <files>scripts/orders/wix-orders-api.ts</files>
  <action>
Create scripts/orders/wix-orders-api.ts that wraps the WIX eCommerce V1 Orders API.

Use the same auth pattern as scripts/pipeline/wix-api.ts (getApiKey(), getHeaders() with Bearer token and wix-site-id). Do NOT import private functions from wix-api.ts — duplicate the auth helpers locally (same pattern as Phase 15 coupon module, see STATE.md decision 15-03).

**API Base:** 'https://www.wixapis.com/ecom/v1'

**Functions to implement:**

1. `searchOrders(filter?: Record<string, unknown>, limit?: number): Promise<WixEcomOrder[]>`
   - POST /ecom/v1/orders/search
   - Body: { search: { filter, cursorPaging: { limit } } }
   - Handle cursor-based pagination (WIX returns nextCursor in pagingMetadata)
   - Default limit 50
   - Log count found

2. `getOrder(orderId: string): Promise<WixEcomOrder>`
   - GET /ecom/v1/orders/{orderId}
   - Return single order object

3. `getRecentOrders(days?: number): Promise<WixEcomOrder[]>`
   - Convenience: searchOrders with createdDate >= (now - days), default 30 days
   - Sort by createdDate DESC

4. `mapWixOrderToOrder(wixOrder: WixEcomOrder): Order`
   - Transform WIX ecom order shape to our Order interface
   - Map WIX paymentStatus/fulfillmentStatus to our OrderStatus:
     - PAID + NOT_FULFILLED → 'new'
     - PAID + FULFILLED → 'shipped'
     - PAID + PARTIALLY_FULFILLED → 'packed' (approximation)
     - NOT_PAID → 'new'
     - CANCELED → 'cancelled'
   - Extract buyer info, addresses, line items, price summary
   - Set source: 'wix', wixOrderId: wixOrder.id
   - Generate statusHistory with single entry from current status

**WixEcomOrder interface:** Define locally in this file (not exported broadly) matching the WIX eCommerce V1 response shape. Include: id, number, status, paymentStatus, fulfillmentStatus, buyerInfo, billingInfo, shippingInfo, lineItems, priceSummary, createdDate, updatedDate, buyerNote.

Use handleErrorResponse pattern from wix-api.ts (duplicate locally). Include specific error messages for 401 mentioning the required WIX permission: "Manage Orders" or "Read Orders".

Add CLI runner at bottom (same pattern as wix-api.ts): if run directly with `--recent`, call getRecentOrders(30) and print summary table.
  </action>

  <done>WIX Orders API client fetches, paginates, and maps orders to unified Order type. CLI --recent flag works.</done>
</task>
