<task type="auto">
  <name>Task 1: Add inventory API endpoints to preview server</name>
  <files>scripts/pipeline/preview-server.ts</files>
  <action>
  Add the following API endpoints to preview-server.ts, following the existing endpoint patterns (try/catch, JSON responses, proper HTTP status codes):

  1. `GET /api/inventory/products` — List all tracked products with latest snapshot summary.
     - Import loadTrackedProducts, loadLatestSnapshot, loadConfig from monitor module
     - For each tracked product, load its latest snapshot
     - Return array of: { style, name, priority, lastPolledAt, totalSkus, outOfStockSkus, lowStockSkus, hasWarehouseData }

  2. `GET /api/inventory/product/:style` — Full warehouse breakdown for a specific style.
     - Load latest snapshot for the style
     - Return full snapshot including per-SKU warehouse breakdown
     - Group and aggregate: per-warehouse totals across all SKUs for summary view
     - Return: { style, timestamp, warehouseSummary: [{id, name, totalQty, skuCount}], skus: [...full snapshot data] }

  3. `GET /api/inventory/alerts` — Recent stock alerts.
     - Import getRecentAlerts from monitor module
     - Accept optional ?count=N query param (default 50)
     - Return alerts array with warehouseDetail when available

  4. `GET /api/inventory/health` — Daemon health status.
     - Import getSyncHealth from sync module
     - Return health object or { running: false } if not available

  5. `GET /api/inventory/config` — Current monitor/sync configuration.
     - Return merged config: poll intervals (hot/normal/slow), stock thresholds, notification settings
  </action>
  <verify>Start preview server with `npx tsx scripts/pipeline/preview-server.ts` and test: `curl http://localhost:3456/api/inventory/products` returns JSON array. `curl http://localhost:3456/api/inventory/alerts` returns alerts array.</verify>
  <done>5 inventory API endpoints operational on preview server. All return proper JSON with error handling.</done>
</task>

<task type="auto">
  <name>Task 2: Build inventory dashboard UI tab</name>
  <files>scripts/pipeline/preview.html</files>
  <action>
  Add a new "Inventory" tab to the preview UI following the existing tab pattern (Products, Margin, Sales tabs already exist).

  The Inventory tab has three sections:

  **Section 1: Tracked Products Overview**
  - Table with columns: Style, Name, Priority, Last Polled, Total SKUs, OOS SKUs, Status
  - Status column: green dot for all-stocked, yellow for some-low, red for any-OOS
  - Priority shown as colored badge: hot=red, normal=blue, slow=gray
  - Last Polled shows relative time ("5 min ago", "1 hour ago")
  - Clicking a row expands to show warehouse breakdown (same expandable row pattern used in Margin tab)

  **Section 2: Warehouse Breakdown (expanded row)**
  - When a product row is expanded, show warehouse table:
    - Columns: Warehouse, Location, Total Qty, Status
    - Color-coded rows: green for well-stocked (>=1500), yellow for normal, red for zero
    - Sort by qty descending

  **Section 3: Recent Alerts Feed**
  - Below the products table, show last 20 alerts in a scrollable feed
  - Each alert shows: timestamp, style, color/size, alert type (with emoji), previous/current level
  - If alert has warehouseDetail, show a compact "Stock: Seattle(450), Dallas(200)..." line
  - Auto-refresh every 60 seconds (fetch from /api/inventory/alerts)

  **Daemon Status Badge (top-right of Inventory tab)**
  - Small status indicator: green dot + "Running" or red dot + "Stopped"
  - On hover/click, show health details (last tick, cycles, errors)
  - Fetches from /api/inventory/health

  Use the same styling patterns as existing tabs (Tailwind-like inline styles, consistent color scheme). Use fetch() for API calls, same pattern as margin and sales sections.

  Add auto-refresh: products table refreshes every 60 seconds, alerts every 30 seconds. Use setInterval with tab visibility check (only refresh when Inventory tab is active).
  </action>
