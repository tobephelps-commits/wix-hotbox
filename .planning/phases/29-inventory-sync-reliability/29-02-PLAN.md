Improve sync daemon observability with cycle duration tracking, notification delivery tracking, mapping freshness auditing, and time-based alert log retention.

Purpose: The current sync health tracks uptime and error counts but not per-cycle timing, email delivery failures are silently swallowed, stale product mappings (WIX products deleted) go undetected until sync time, and the alert log only caps at 1000 entries with no time-based cleanup. These gaps reduce operational confidence and can mask issues.

Output: Enhanced SyncHealth with cycle timing, notification delivery tracking in health state, a mapping audit function, and time-based alert log pruning.
</objective>

  <name>Task 1: Add cycle duration tracking and notification delivery state to SyncHealth</name>
  <files>scripts/sync/sync-poller.ts, scripts/sync/notifications.ts, scripts/sync/types.ts</files>
  <action>
1. In sync-poller.ts, extend the SyncHealth interface with:
   ```
   /** Duration of last tick in milliseconds */
   lastTickDurationMs: number;
   /** Average tick duration in milliseconds (rolling) */
   avgTickDurationMs: number;
   /** Longest tick duration seen in milliseconds */
   maxTickDurationMs: number;
   /** Notification delivery tracking */
   notifications: {
     /** Total emails sent successfully */
     sent: number;
     /** Total email send failures */
     failed: number;
     /** ISO timestamp of last successful email */
     lastSentAt: string | null;
     /** ISO timestamp of last failed email attempt */
     lastFailedAt: string | null;
     /** Last failure message (for dashboard display) */
     lastFailureReason: string | null;
   };
   ```

2. In executeTick, wrap the entire tick body with timing:
   ```
   const tickStart = Date.now();
   // ... existing tick logic ...
   const tickDurationMs = Date.now() - tickStart;
   ```
   After the tick completes (success or failure), update:
   - `_syncHealth.lastTickDurationMs = tickDurationMs`
   - `_syncHealth.maxTickDurationMs = Math.max(_syncHealth.maxTickDurationMs, tickDurationMs)`
   - `_syncHealth.avgTickDurationMs` using a cumulative moving average: `((prev * (totalCycles - 1)) + tickDurationMs) / totalCycles`

   Add a latency warning: if tickDurationMs > avgTickDurationMs * 3 AND totalCycles > 5, log: `[Sync] SLOW TICK: ${tickDurationMs}ms (avg: ${avgTickDurationMs}ms)`.

3. In notifications.ts, change `sendSyncNotification` to return a result instead of swallowing errors:
   - Create a new type `NotificationResult = { success: boolean; error?: string }` in types.ts.
   - Change sendSyncNotification return type to `Promise<NotificationResult>`.
   - On success: return `{ success: true }`.
   - On failure: log the error (keep existing behavior), return `{ success: false, error: message }`.
   - Update `notifySyncResults` to return NotificationResult (or null if skipped).

4. In sync-poller.ts `executeTick`, after `notifySyncResults` call, update `_syncHealth.notifications`:
   - If notification was sent (result is not null):
     - If success: increment `sent`, update `lastSentAt`
     - If failure: increment `failed`, update `lastFailedAt` and `lastFailureReason`

5. Initialize the new SyncHealth fields in `startSmartSyncLoop`:
   ```
   lastTickDurationMs: 0,
   avgTickDurationMs: 0,
   maxTickDurationMs: 0,
   notifications: { sent: 0, failed: 0, lastSentAt: null, lastFailedAt: null, lastFailureReason: null },
   ```
  </action>
  <verify>Run `npx tsc --noEmit` — no TypeScript errors. Verify SyncHealth includes all new timing and notification fields.</verify>
  <done>SyncHealth tracks per-tick duration (last, avg, max), slow tick detection logs warnings, and notification delivery success/failure is tracked with counts and timestamps. All accessible via getSyncHealth().</done>


   Create `MappingAuditResult` interface in types.ts:
   ```typescript
   export interface MappingAuditResult {
     total: number;
     healthy: number;
     orphaned: ProductMapping[];  // WIX product not found (404)
     errors: { mapping: ProductMapping; error: string }[];  // Other fetch errors
   }
   ```

   Implementation:
   - Load all product mappings via loadProductMap
   - For each mapping, call `getProduct(mapping.wixProductId)` wrapped in try/catch
   - If 404/not found: add to `orphaned` array
   - If other error: add to `errors` array
   - If success: increment `healthy`
   - Add rate limiting: delay 200ms between WIX API calls to avoid rate limits (`await new Promise(r => setTimeout(r, 200))`)

   - At completion, log summary: `[Audit] ${healthy} healthy, ${orphaned.length} orphaned, ${errors.length} errors`

   Also add `removeOrphanedMappings` that takes an audit result and removes orphaned mappings:
   ```typescript
   export async function removeOrphanedMappings(audit: MappingAuditResult, config: SyncConfig): Promise<number>
   ```

   - Return count removed
   - Log: `[Audit] Removed ${count} orphaned mapping(s)`

     ```
     combined = combined.filter(a => new Date(a.timestamp).getTime() > cutoff);
     // Then apply entry cap
     if (combined.length > MAX_ALERT_LOG_SIZE) { ... }
     ```
