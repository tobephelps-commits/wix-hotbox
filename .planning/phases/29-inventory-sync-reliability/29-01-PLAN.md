<objective>
Harden inventory monitoring accuracy with per-product thresholds, case-insensitive SKU matching, and snapshot staleness detection.

Purpose: The current system uses global thresholds for all products and exact-case SKU matching, which leads to missed alerts for products with different stock profiles and silent failures when vendor color names have case mismatches. Snapshot staleness goes undetected, causing stale data to drive WIX visibility decisions.

Output: Per-product threshold overrides, robust SKU parsing, and snapshot age tracking integrated into the monitor and sync systems.
</objective>

  <name>Task 1: Add per-product threshold overrides and snapshot staleness tracking</name>
  <files>scripts/monitor/types.ts, scripts/monitor/alerts.ts, scripts/monitor/store.ts, scripts/monitor/manage.ts</files>
  <action>
1. In types.ts, add an optional `thresholds` field to TrackedProduct:
   ```
   thresholds?: {
     lowStockThreshold?: number;
     criticalStockThreshold?: number;
     outOfStockThreshold?: number;
   };
   ```
   This allows per-product overrides while falling back to global config when absent.

2. In alerts.ts, update `classifyStockLevel` to accept an optional thresholds override parameter. Create a new helper `getEffectiveThresholds(product: TrackedProduct, config: MonitorConfig)` that merges per-product overrides with global defaults. Update `detectAlerts` signature to accept optional TrackedProduct so it can use per-product thresholds. The existing function without product param should continue to work (backward compatible — uses global config only).

3. In store.ts, add a `snapshotMaxAgeMinutes` field to MonitorConfig defaults (default: 180 — 3 hours). Add a function `isSnapshotStale(snapshot: InventorySnapshot, maxAgeMinutes: number): boolean` that checks if the snapshot timestamp is older than the configured max age. Update `getDefaultConfig()` to include this new field.

4. In manage.ts, add a `monitor threshold <style> <key> <value>` CLI command that updates a tracked product's per-product thresholds. Keys: lowStockThreshold, criticalStockThreshold, outOfStockThreshold. Example: `monitor threshold PC61 lowStockThreshold 20`. Also add `monitor threshold <style> reset` to clear per-product overrides. Show per-product thresholds in the `monitor list` output when they exist.
  </action>
  <verify>Run `npx tsc --noEmit` — no TypeScript errors. Verify that existing MonitorConfig and TrackedProduct interfaces are backward compatible (no required fields added).</verify>
  <done>TrackedProduct supports optional per-product thresholds. classifyStockLevel uses effective thresholds. Snapshot staleness is detectable. CLI supports threshold management. All changes backward compatible with existing data files.</done>

<task type="auto">
  <name>Task 2: Harden SKU parsing with case-insensitive color matching and snapshot staleness in sync</name>
  <files>scripts/sync/stock-sync.ts, scripts/monitor/poller.ts</files>
  <action>
1. In stock-sync.ts `syncProductStock`:
   - Change the snapshotMap key to use lowercased color: `snapshotMap.set(\`${sku.color.toLowerCase()}|${sku.size}\`, sku)`.
   - When looking up parsed SKU, lowercase the catalogColor: `snapshotMap.get(\`${parsed.catalogColor.toLowerCase()}|${parsed.size}\`)`.
   - This makes color matching case-insensitive while preserving exact size matching (sizes like "S", "M", "L" are always uppercase).
   - Add a parse error counter: track how many variants had unparseable SKUs and include count in SyncResult. Add a `parseErrors` field (number) to SyncResult in types.ts. Increment it when parseSku returns null instead of silently skipping.
   - Before syncing, check snapshot staleness using `isSnapshotStale`. If stale (older than config max age), log a warning `[Sync] ${style}: Snapshot is ${ageMinutes}min old (max: ${maxAge}min) — skipping sync to avoid stale data`. Skip the sync for that product and add an error to SyncResult: "Snapshot too old — poll may have failed".

2. In poller.ts `pollOnce`:
   - Pass the TrackedProduct to `detectAlerts` so per-product thresholds are used. Update the detectAlerts call to include the product. This requires alerts.ts detectAlerts to accept the optional TrackedProduct (done in Task 1).
   - After successful poll, log the snapshot age: `[Monitor] ${style}: Fresh snapshot (${skuCount} SKUs, ${warehouseCount} warehouses)`.

3. In stock-sync.ts `parseSku`, add a trim() call on the extracted catalogColor and size to handle any whitespace in SKU strings: `catalogColor.trim()` and `size.trim()`.
  </action>
  <verify>Run `npx tsc --noEmit` — no TypeScript errors. Check that SyncResult now includes parseErrors field.</verify>
  <done>SKU color matching is case-insensitive. Parse errors are tracked and counted. Stale snapshots are detected and skipped with warning. Trim handles edge-case whitespace in SKUs. Per-product thresholds flow through to alert detection.</done>
</task>
