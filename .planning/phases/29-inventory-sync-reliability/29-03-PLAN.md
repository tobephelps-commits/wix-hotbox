<task type="auto">
  <name>Task 1: Add API endpoints for mapping audit, alert filtering, and threshold display</name>
  <files>scripts/pipeline/preview-server.ts</files>
  <action>
1. Add `POST /api/inventory/audit` endpoint:
   - Import auditProductMappings and removeOrphanedMappings from product-map.ts
   - On POST, run auditProductMappings(syncConfig) and return the MappingAuditResult as JSON
   - This is intentionally POST (triggers side-effect: WIX API calls) not GET
   - Route: add `'inventory-audit'` to the route matcher

2. Add `POST /api/inventory/audit/cleanup` endpoint:
   - Accepts JSON body `{ styles: string[] }` for selective removal, or empty body for all orphaned
   - Run audit first, then removeOrphanedMappings for specified or all orphaned
   - Return `{ removed: number, remaining: number }`

3. Enhance `GET /api/inventory/alerts` endpoint:
   - Add query params: `?type=out-of-stock,critical` (comma-separated alert types) and `?style=PC61` (filter by style)
   - Load alerts, filter by type and/or style if params present, then apply count limit
   - Backward compatible: no params = current behavior (last 50)

4. Enhance `GET /api/inventory/products` response:
   - For each tracked product, include `thresholds` field (per-product overrides if set, or null)
   - Include the effective thresholds (merged global + per-product) as `effectiveThresholds`
   - Include snapshot age in minutes: `snapshotAgeMinutes` (null if no snapshot)
   - Include `isStale` boolean based on snapshotMaxAgeMinutes config

5. Enhance `GET /api/inventory/health` response:
   - Include the new timing fields: lastTickDurationMs, avgTickDurationMs, maxTickDurationMs
   - Include notification delivery stats: notifications object from SyncHealth
   - All these are already in SyncHealth — just ensure the spread includes them (it should, since getSyncHealth returns a copy)
  </action>

<task type="auto">
  <name>Task 2: Add inventory reliability UI to dashboard</name>
  <files>scripts/pipeline/preview.html</files>
  <action>
Add the following UI enhancements to the inventory section of preview.html, following existing patterns (inline styles, vanilla JS, fetch API):

1. **Sync Health Cards Enhancement:**
   - Add "Avg Tick" and "Max Tick" metric cards alongside existing health display
   - Format as `${ms}ms` for sub-second, `${(ms/1000).toFixed(1)}s` for multi-second
   - Color coding: green if avgTick < 5000ms, yellow if < 15000ms, red if >= 15000ms
   - Add "Notification Status" card showing: `✓ ${sent} sent` in green or `✗ ${failed} failed` in red
   - If lastFailureReason exists, show it as a small tooltip or subtitle text

2. **Alert Filtering Controls:**
   - Add a filter bar above the alerts list with:
     - Type filter pills: "All", "Out of Stock", "Critical", "Low Stock", "Back in Stock" (toggle on/off)
     - Product filter: dropdown populated from tracked products list
   - Fetch alerts with query params based on selected filters
   - "All" is default (no filter params)
   - Style: match existing pill/filter patterns used in order management section

3. **Per-Product Threshold Badges:**
   - In the inventory products list, show a small badge/tag next to products that have custom thresholds
   - Badge text: "Custom" in a muted style (e.g., small pill with border)
   - On hover or click, show tooltip/popover with the per-product threshold values vs global defaults
   - Example: "Low: 20 (global: 10) | Critical: 5 (global: 3)"

4. **Stale Snapshot Warning:**
   - For each product in the inventory list, if `isStale` is true, show a warning icon and message
   - Style: orange/amber warning indicator with text "Stale data ({ageMinutes}min old)"
   - This warns the operator that the product's inventory data hasn't been refreshed recently

5. **Mapping Audit Section:**
   - Add a "Audit Mappings" button in the inventory products area
   - On click, POST to `/api/inventory/audit`
   - While running, show a spinner/loading state
   - On result, display: "${healthy} healthy, ${orphaned.length} orphaned, ${errors.length} errors"
   - If orphaned > 0, show the orphaned product list with a "Remove Orphaned" button
   - "Remove Orphaned" POSTs to `/api/inventory/audit/cleanup` and refreshes the list
  </action>
